# 《AI 写代码之后》v2.3 减重修订设计

**状态：** 已由作者批准，执行口令为“按照这个开始做”。

**基线：** v2.2.0 EPUB 是 Canonical Source 的恢复来源；同版本 TXT 用于内容校对，PDF 仅用于页数、书签和版面核验。

## 目标

- 保留 10 卷、104 章、原章节编号和高级知识体系。
- 主 PDF 控制在 450–500 页，软目标约 470 页。
- 正文控制在约 38 万–42 万非空白字符。
- 不通过小于 10.5pt 的正文字号、小于 1.5 的行距或缩小图片实现减重。
- 允许系统性压缩、去重和外置操作细节，但不推翻知识体系、不删除章节、不改变编号。

## 内容模型

大多数章节压缩到 2–5 页；第一卷少数基础章节允许 5–7 页。每章优先保留：问题成因、核心心智模型、适用时机、最小示例或证据、证据边界、进一步实操入口。

主书保留概念关系、选型边界、AI Coding 常见错误、最小可运行或可观察示例、高风险操作的预检查/备份/验证/回滚、时效性事实状态框以及“现在可以跳过”的层级提示。

按钮级教程、长命令清单、完整配置、平台逐屏流程、大型对比表、完整视频卡、扩展案例和完整术语索引移到约 8 个主题参考页。

## 去重规则

- 一个概念只在一个主章节完整解释，其他章节只给提醒和链接。
- 日志、秘密、备份、回滚、Diff、人工确认各自设置唯一主章节。
- “成功状态不能证明全部结果”统一为短“证据边界”框。
- 同章最多保留一个完整故事。
- 删除超过 80 字的完全重复段落；语义重复人工复核。
- 产品枚举改成决策表。

## Canonical Source

```text
book/
  frontmatter/
  chapters/001-*.md ... 104-*.md
  manifest.json
references/
scripts/
tests/
VERIFICATION.md
AUDIT-v2.3.md
```

`manifest.json` 每章记录 `id`、`volume`、`part`、`title`、`source`、`level`、`volatile_facts`、`reference_links`。

## 实施批次

1. 审计冻结：记录章节字符数、资源、交叉引用、风险命令、易变事实和发布状态。
2. 恢复 Canonical Source：从 EPUB XHTML 确定性转换 104 章，并以 TXT 校对。
3. 六章压缩试点：第 1、19、40、54、70、91 章，目标减重 40%–45%。
4. 三批编辑：第一至五卷、六至九卷、第十卷。
5. 定位修订：README、书名页、前言、START-HERE、60 分钟路线、第八卷和第十卷结构、NotebookLM 用法。
6. 事实与风险核验：稳定原理、版本敏感和政策敏感内容分开管理。
7. 构建发布：同源生成各格式，修复 PDF 书签与空白页，生成完整 Release 和 SHA256SUMS。

## 验收

- 章节 ID 唯一且连续为 1–104，标题与目录一致，所有“第 X 章”引用存在。
- 不存在超过 80 字的完全重复段落。
- 易变事实进入核验表；高风险命令附近有影响、备份、验证和回滚说明。
- 内部链接、图片、脚注和引用可解析。
- 60 分钟路线不超过约 2.2 万字，15 章核心路线约 5.5 万–6.5 万字。
- PDF 450–500 页、无末尾空白页、104 个书签跳到真实章首页、可搜索且中文字体正常。
- EPUB TOC 和内部链接正确。
- v2.3.0 使用小写标签和 `ai-coding-after-v2.3.0.*` 文件名；FORMATS、Release 与 SHA256SUMS 一一对应。

## 当前子项目边界

第一子项目只做“源恢复与审计冻结”。它必须无损建立 104 章可审查 Markdown、manifest、结构验证和基线审计；不在同一批中压缩正文。六章试点以该子项目通过验证后的输出为输入。
