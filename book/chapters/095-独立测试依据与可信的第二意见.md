# 独立测试依据与可信的第二意见

第一位 AI 设计接口、编写实现和测试，再总结全部通过。第二位 AI 读完这些材料，很快回复方案合理。两份回答可能共享同一个错误前提，因此第二次回答不自动构成独立复核。

测试需要判断对错的依据，测试理论中常称 Oracle。需求、标准、旧版本行为、参考实现、人工计算、真实用户结果和安全规则都可以成为依据。若依据来自被测实现，测试会把实现错误复制成预期。

## 先确定什么算正确

税费函数返回 12.37，测试若复制同一公式计算预期值，两边会一起犯错。更可靠的依据可能来自法规、人工核对样本、验证过的参考实现，或金额守恒等不变量。

数据库迁移可以依据前后行数、约束和业务状态。上传功能可以依据文件哈希、内容类型规则和对象存储结果。不同依据发生冲突时，测试不能静默挑一个。需求文档允许进度回退，旧代码禁止回退，界面又提供重新学习按钮，此时需要产品负责人明确规则。生产行为也未必正确，把一次错误扣费录成 Golden File 只会固定缺陷。

## 独立性可以分开建立

复核者先看原始用户目标、公开规范和验收条件，自己列出风险、边界与反例，再查看实现者的结论。这建立了需求来源和测试设计上的独立。把原作者的测试交给另一位 AI 重跑，只增加了执行者。

实现层可以用旧稳定版、成熟库或简化模型对同一输入计算结果。环境层可以在干净容器、真实数据库和受限权限账号中运行。责任层则要求有发布权限并承担业务后果的人查看证据、剩余风险与回滚条件。

改 README 标点通常只需作者自检。登录权限、批量删除、付款回调、数据库迁移和 App 签名应增加独立测试设计、干净环境与人工确认。影响用户数量、数据可恢复性、金钱或法律责任、发现延迟和回滚难度，都可以提高复核等级。缺少真实账号或设备时，结论应写未验证。

## 两个 AI 可能共享盲点

两次请求使用同一份需求摘要，摘要漏掉旧版 App 仍在使用，两个模型都很难补出这个条件。第一位 AI 的解释还会引导第二位观察同一方向。实现把上限写成 100，测试也断言 100，实际需求却是 99，绿色只说明两份生成物一致。

复核任务应提供原始目标、仓库与变更范围，要求寻找能推翻方案的输入、版本冲突、权限绕过、恢复失败和未测试假设。两个模型依赖同一篇过时文章时，来源仍不独立。平台政策、价格、界面与版本需要回到当前官方资料核对。

## 建立可追溯的测试依据

高风险行为应记录原始需求来源、适用标准、正常与失败样本、判定规则、执行环境、被测提交、测试设计者、执行者、共享假设和证据位置。报名接口的 HTTP 语义可以来自 RFC，权限来自角色表，重复请求依据幂等规则，数据库结果依据唯一约束。

依据也要版本化。官方 API、数据库版本、商店政策和业务规则变化后，旧测试可能继续通过。只有 `PASS`，没有输入、预期和比较过程，复核者无法判断脚本本身。

差分测试可以把同一输入交给新旧解析器或两种查询实现。差异只表示结果不同，仍需规范和业务规则裁决。完整参考系统成本过高时，可以写一个慢但直观的简化模型，或使用蜕变关系。例如排序后再次排序应保持结果。

## 测试代码也要接受反证

复核测试时先找断言，再确认它能观察业务结果。权限测试若替换了授权中间件，只能证明替身按脚本工作。真实组件应保留在关键集成边界，替身用于隔离昂贵或不可控依赖。

可以在隔离副本做三次破坏实验。删除核心业务调用、交换两个重要返回值，应让相关测试失败；再让外部依赖报错，检查系统是否按预定策略返回、回滚或保留待确认状态。最后一种实验的测试可以通过，因为它验证的是正确的故障处理。每次恢复改动后再运行正常样本。安全扫描和渗透测试也只能覆盖给定规则、范围与时间，报告要写清身份、环境、工具版本和未覆盖项，不能把未发现漏洞写成没有漏洞。

## 一次双重验证怎样执行

先冻结候选提交和构建产物，记录哈希、依赖与环境。实现者提交需求映射、测试和已知限制。复核者先依据原始需求、Diff 与公开标准独立列出风险和测试，随后才对照第一份材料。

双方用各自准备的关键样本在干净环境运行。数据库变更还要检查迁移前后、失败恢复和备份，客户端要在目标设备验证核心动作。结论分为通过、带条件通过、失败和无法验证。分歧由可重复实验裁决，仍无法裁决的部分进入 ADR 或风险记录。

以拆分 `users.name` 为例，十条英文姓名迁移成功远远不够。复核者应检查单名、中文姓名、空值、组织名称和人工修正记录，并在数据库副本比较行数、约束、外键和应用读取。迁移中途失败后，还要验证事务或恢复脚本能回到一致状态，并实际把备份恢复到另一数据库。

若部分姓名没有可靠拆分规则，先新增字段并保留旧列，记录待人工确认项，经过兼容期再决定是否删除。这里暴露的是需求缺口，继续增加同类测试样本无法解决。

调用第二个 AI 时，要求它声明看过哪些材料、共享哪些来源以及能否运行代码。让它提交反例和证据，每项意见指向文件、需求、标准或实验。无法复查的意见只能作为待验证假设。
