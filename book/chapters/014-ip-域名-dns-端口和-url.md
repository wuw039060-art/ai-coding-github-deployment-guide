# IP、域名、DNS、端口和 URL

浏览器需要一个明确地址才能发请求。人们习惯记 `example.com` 这样的域名，网络连接最终还要找到相应地址和服务入口。DNS 负责查询名称，IP 标识网络位置，端口区分服务，URL 则把协议、主机、路径和其他信息写在同一个地址中。

这些概念经常同时出现，解决的问题各不相同。域名能解析，不说明应用正在运行。端口有进程监听，也不说明 HTTPS 证书正确。URL 路径写错，服务器可达仍会返回 404。

## IP 地址标识网络接口

IP Address 译为 IP 地址。IPv4 常写成四段十进制数字，IPv6 使用更长的十六进制表示。设备可以同时有多个 IP，也会因网络变化获得不同地址。家庭路由器内的电脑常有私有 IP，只在本地网络使用。路由器对互联网使用公网 IP，并通过地址转换让多台设备共享连接。云服务器通常有公网访问入口，也可能同时有私有网络地址。

`127.0.0.1` 是 IPv4 回环地址，通常指当前设备自身。`localhost` 常解析到回环地址。开发服务器只监听回环地址时，其他设备不能直接访问。`0.0.0.0` 在服务监听配置中常表示所有 IPv4 网络接口，不是一个让用户在浏览器中访问的普通目标地址。把服务监听到所有接口会扩大访问范围，需要防火墙和认证。

家庭公网 IP 可能由运营商动态分配，断线或过一段时间会变化。云平台提供的实例 IP 是否固定，取决于产品和配置。删除、停止或重建实例可能改变地址。域名可以通过 DNS 记录指向当前地址。地址变化时，记录也要更新。生产服务若依赖固定入口，应使用平台提供的固定 IP、负载均衡或域名目标，并核对费用。

不要把某次查询到的 IP 永久写进 App。平台迁移、CDN 和故障切换都会改变目标。使用受控域名能在不更新客户端的情况下调整后端入口。同一个域名也可能返回多个 IP，用于分布式服务与负载均衡。不同地区和网络查到的结果可能不同。

## 域名是分层名称

Domain name 译为域名。`www.example.com` 可以从右向左看。`.com` 是顶级域，`example.com` 是注册域名，`www` 是其下的子域。MDN 对域名的说明强调，域名提供人类可读的地址，并通过 DNS 与 IP 联系。注册域名得到的是在一定期限内的使用权，需要续费并遵守注册规则。

子域可以分配给不同服务；`www.example.com` 放网站，`api.example.com` 放 API，`status.example.com` 放状态页；它们可以指向不同平台；裸域也称 Apex domain，例如 `example.com`；`www.example.com` 是子域；两者可以分别配置，也可以让一个重定向到另一个；证书与部署平台都要包含实际使用名称。

注册商负责域名注册关系、续费和联系人。DNS 托管商提供 Nameserver 与记录管理。两项服务可以来自同一公司，也可以分开。Nameserver 译为域名服务器。注册商处配置的权威 Nameserver 决定谁回答该域名 DNS 查询。只在旧 DNS 控制台改记录，而注册商已经指向新 Nameserver，改动不会生效。

迁移 DNS 托管时，先导出现有记录，特别是邮件、验证与子域记录。切换 Nameserver 后验证网站、邮件和第三方服务。不要只复制网站 A 记录。域名控制权很重要。开启两步验证、自动续费与到期提醒，使用组织可恢复账户。联系人邮箱失效会影响找回和转移。

## DNS 把名称查询为记录

DNS 是 Domain Name System 的缩写，中文常译为域名系统。浏览器需要访问域名时，会通过系统和 DNS 解析器查询记录。解析器可能先用缓存。没有缓存时，它会从 DNS 层级找到权威服务器并取得答案。MDN 对 Web 工作方式的说明用 DNS 查询作为浏览器连接服务器前的一步。

DNS 返回的不只 IP。不同记录类型承担不同目的。A 指向 IPv4，AAAA 指向 IPv6，CNAME 为名称设置别名，MX 处理邮件，TXT 常用于验证和策略信息。CNAME 使用范围和根域限制要按 DNS 提供商与标准行为判断。部分平台提供 Flattening 或 ALIAS 一类产品能力，它们不是普通 CNAME 的完全同义词。

DNS 控制台常要求 Type、Name、Value 和 TTL。Type 是记录类型；Name 是主机名称；Value 是目标；TTL 表示解析器可以缓存答案的时间；不同控制台对 Name 的填写方式不同；有的填写 `www`，有的接受完整 `www.example.com`；根域可能写 `@`、留空或显示域名本身；必须看当前提供商说明和保存后的最终记录。

TTL 低可以让后续变化更快被重新查询，也会增加查询频率。TTL 高能延长缓存。修改前降低 TTL 是否有帮助，取决于旧记录已经被缓存多久。保存成功只表示控制台接受记录。权威服务器更新、解析器缓存与本机缓存可能让不同用户短时间看到不同结果。

## DNS 传播是多个缓存逐步过期

人们常说“DNS 正在传播”。更准确的现象是权威记录已经改变，不同解析器仍可能缓存旧答案。缓存到期后才重新查询。排查时先查权威服务器答案，再查公共解析器和本机结果。记录查询时间、网络和返回值。只刷新浏览器无法清除所有上游缓存。

旧 TTL 是判断等待时间的重要线索。改动后立刻把 TTL 调低，无法让已经缓存的旧高 TTL 答案提前失效。重复删除和重建记录会让状态更难解释。确认目标值正确后，保留配置并观察。紧急迁移可以提前规划 TTL 和双端兼容。

同一 IP 上可以运行许多网络服务；Port 译为端口，用 0 到 65535 的数字区分入口；HTTP 常用 80，HTTPS 常用 443；URL 省略标准端口时，浏览器会按协议使用默认值。开发服务器常用 3000、5173、8000 或其他端口。这些只是工具常见选择，并非固定标准。真正端口以启动日志和配置为准。

程序监听端口后，操作系统才会把进入连接交给它。防火墙还可能阻止外部访问。端口开放、监听与应用正常是三项不同检查。数据库常监听自己的端口，不应因为 App 要联网就直接暴露公网。后端通过私有网络或本机连接数据库，用户只访问 Web 入口。

## 监听地址与端口要一起看

程序显示 `127.0.0.1:3000`，说明只监听本机回环接口的 3000 端口。同机反向代理可以访问，远程电脑不能直接连接。显示 `0.0.0.0:3000`，表示监听所有 IPv4 接口。是否真能从公网访问，还要看云安全组、系统防火墙、路由和服务认证。

Docker 端口映射又多一层。容器内部监听 3000，宿主机可以映射为 8080。用户访问宿主机 8080，Docker 转给容器 3000。排错时记录“哪个进程在什么网络命名空间监听什么地址与端口”。只说“3000 开了”不够。

URL 是 Uniform Resource Locator 的缩写，中文常译为统一资源定位符。MDN 将 URL 分为 Scheme、Authority、Path、Parameters、Anchor 等组成。

看下面的示例。

```
https://api.example.com:8443/v1/orders?status=open#recent
```

`https` 是协议方案；`api.example.com` 是主机；`8443` 是显式端口；`/v1/orders` 是路径；`status=open` 是查询参数；`recent` 是片段标识。片段通常由浏览器在本地使用，不会作为普通 HTTP 请求目标的一部分发送给服务器。查询参数会进入请求，应避免放入密码和长期令牌，因为 URL 可能进入历史、日志和分析系统。

## 协议方案决定怎样访问

`http` 与 `https` 使用 Web 协议，后者通过 TLS 保护传输并验证服务器身份。`file` 用于本地文件，`mailto` 可以交给邮件应用。浏览器还可能处理自定义 App Scheme。同一主机的 HTTP 与 HTTPS 是不同源，服务行为也可能不同。生产网站通常把 HTTP 重定向到 HTTPS。

浏览器地址栏省略方案时会尝试补全或搜索。技术文档和配置应写完整 URL，避免把域名误当搜索词。自定义 Scheme 可能打开已安装 App，也可能被恶意链接滥用。点击前确认来源，App 还要验证收到的参数。

URL Path 使用正斜杠，例如 `/docs/start`。它由 Web 服务器或应用路由处理，不一定对应服务器磁盘上的同名文件。静态网站中，`/images/logo.png` 常映射到发布目录中的文件。动态应用中，`/users/42` 可以由程序查询数据库，没有名为 `users/42` 的磁盘文件。

路径区分大小写的行为由服务器和平台决定，Linux 静态文件通常区分。开发时统一精确大小写最安全。`../` 在 URL 中表示上级路径的语义，服务器会规范化。文件上传和下载接口必须防止用户利用路径跳出允许目录。

## 绝对 URL 与相对 URL

绝对 URL 包含协议和主机，例如 `https://example.com/docs/start`。相对 URL 根据当前页面地址计算，例如 `../images/logo.png`。相对地址方便同一网站在不同域名部署。写错层级会在某些页面正常、某些页面 404。根相对路径 `/images/logo.png` 从网站根开始，路径相对 `images/logo.png` 从当前目录开始。

前端使用 API 地址时，要知道相对请求指向当前网页 Origin。网页部署到新域名后，请求目标也会变化。独立 API 通常用环境配置提供完整基址。不要在发布代码中写 `http://localhost:3000` 作为生产 API。用户浏览器会请求用户自己的电脑。

部署平台默认域名可以打开，`www.example.com` 返回“找不到服务器”。控制台显示自定义域名仍在等待 DNS 验证。维护者在 DNS 添加了 CNAME，但写到了已经停用的 DNS 提供商。注册商当前 Nameserver 指向另一个平台，因此公网查询没有这条记录。

他把记录加入实际权威 DNS，等待缓存更新。平台验证通过并申请证书，HTTPS 可以访问。最后设置裸域重定向到 `www`。这个故障中，代码和构建一直正常。判断依据是默认域名可用、自定义域名解析失败与权威 Nameserver 不一致。

## 一个端口故障例子

后端启动日志显示监听 `127.0.0.1:3000`。Caddy 配置转发到 `localhost:3001`，用户请求得到 502。应用正常运行，但代理连接了错误端口。修改代理上游为 3000，重新加载配置并验证。没有必要让应用改为公网监听，也不应开放 3000 防火墙。

若代理与应用在不同 Docker 容器，`localhost` 又指当前代理容器，不能访问另一个容器。应使用 Compose 服务名与容器端口。第七卷会详细演示。

域名注册保证名称归属在有效期内。DNS 告诉查询者去哪里。HTTPS 证书证明连接的服务控制对应名称并保护传输。三者缺一都可能影响访问；域名到期后，DNS 可能停止；DNS 指向错误平台时，证书验证无法完成。证书过期时，DNS 仍能返回 IP，浏览器会发安全警告。

托管平台常自动申请证书，前提是域名已经正确绑定。自建服务器要配置自动续期并监控失败。不能把浏览器当前有锁标志当作永久保证。

## NAT、代理与“真实 IP”

NAT 是 Network Address Translation 的缩写，中文常译为网络地址转换。家庭路由器与云网络常让多个私有地址通过公网入口通信。服务端看到的连接来源可能是 CDN、负载均衡或代理，不是用户设备。代理可以在受控 Header 中传递客户端地址。应用只信任自己配置的代理链。

攻击者可以自行填写普通 Header。若应用无条件信任 `X-Forwarded-For`，限流和审计会被绕过。框架需要正确设置可信代理数量或地址。IP 也不是稳定用户身份。家庭共享、移动网络、VPN 与企业出口都会让多人共用或变化。认证仍用账号与凭据。

域名可以同时有 A 与 AAAA 记录。客户端会根据网络与算法选择连接。IPv6 记录指向错误时，一部分网络失败，另一部分通过 IPv4 正常。故障表现为不同用户或网络结果不一致。分别查询 A 与 AAAA，并测试服务是否在对应地址监听、证书是否相同。

没有实际 IPv6 服务时，不要保留过时 AAAA。删除前确认邮件、CDN和其他子域没有依赖。服务器防火墙也要覆盖 IPv4 与 IPv6。只配置一套规则可能留下意外入口。

## DNS 验证记录不要随意公开长期值

平台绑定域名时常要求 TXT 验证，证书机构也可能用 DNS 验证。值用于证明域名控制，按平台说明添加。有些验证记录可以长期保留，有些应在完成后移除。先查官方说明。删除正在用于自动续期的记录会让未来证书失败。

域名转移码和账户恢复码不属于普通 DNS 记录，不能发给部署平台之外的人。截图 DNS 控制台时遮盖内部主机和验证值。多个平台同时要求同名记录时，确认记录类型是否允许多值。覆盖旧值可能中断邮件或验证。

Windows PowerShell 可以使用系统提供的 `Resolve-DnsName` 观察公开记录。

```
Resolve-DnsName example.com
```

运行位置是 Windows PowerShell，命令只查询。成功时显示记录类型、名称和地址。公司策略或旧系统可能没有该命令。macOS 与 Linux 常有 `dig` 或 `nslookup`，是否预装由系统决定。

```
dig example.com A
```

只查询自己或公开域名。不要用端口扫描和大量 DNS 请求测试不属于你的系统。查询结果记录解析器与时间。

## URL 编码为什么会出现百分号

URL 中某些字符要经过 Percent-encoding，也就是百分号编码。空格常显示为 `%20`，中文路径会转换为 UTF-8 字节的编码形式。编码让 URL 可以安全传输，不等于加密。服务器日志仍能还原内容。敏感数据不要放 URL。

重复编码会让 `%2F` 变成 `%252F`，路径匹配失败。前端、代理和后端应明确由谁编码和解码。查询参数使用标准 URL API 构建，避免手工拼接。用户输入中的 `&`、`=` 和 `#` 会改变结构。

| 目标 | 常见记录 | 要确认的内容 |
| --- | --- | --- |
| 域名指向 IPv4 | A | 地址是否固定、服务是否监听 |
| 域名指向 IPv6 | AAAA | IPv6 网络与防火墙是否可用 |
| 子域别名到平台域名 | CNAME | 根域限制与平台验证 |
| 邮件接收 | MX | 优先级与邮件商要求 |
| 所有权或邮件策略验证 | TXT | 值、名称与保留期限 |

表格给出常见用途，部署平台会给出精确类型、名称与目标。复制时不要多加域名后缀。同名可以有多条某类记录，冲突规则由 DNS 标准和提供商决定。保存后查询实际答案。

## 迁移域名入口的安全顺序

新平台先使用默认域名验证。添加自定义域名，让平台准备证书。提前降低旧 DNS TTL，并等待旧缓存期经过。新旧后端在切换期间都能服务兼容请求。修改 DNS 指向新入口，观察权威与多个解析器。

确认流量稳定后再关闭旧服务。保留回滚时间和旧记录值。邮件与其他子域不随网站误改。切换完成后恢复合适 TTL，更新监控、文档和账单。旧平台删除前导出日志与数据。

路由器端口转发把公网入口送到内网设备；防火墙决定流量是否允许；应用还要监听正确地址；三项任一缺失都会无法连接。三项都开放也不代表服务安全，仍需要认证、TLS 和更新。个人开发不要把本地数据库与开发服务器直接转发公网。需要演示时使用受控部署或有身份保护的隧道，并查其数据政策。

完成测试后移除转发与临时规则，外部扫描可能很快发现开放端口。

## 一个 TTL 时间线例子

旧 A 记录 TTL 为 3600 秒，下午两点有人查询并缓存。两点十分修改权威记录，那个解析器仍可用旧值到约三点。另一个解析器两点二十分第一次查询，会直接得到新值。于是两个用户结果不同。维护者检查权威答案确认已更新，保持旧服务继续可用，等待缓存过期。没有反复修改记录。

具体过期时间受查询时点和解析器行为影响，记录观察结果，不承诺全球同一秒切换。

网站迁移主要修改 A、AAAA 或 CNAME。MX、SPF、DKIM 与 DMARC 等邮件记录承担收信和防伪，删除会影响邮件。DNS 控制台里 TXT 记录很多，名称与用途不同。迁移网站时原样保留邮件商要求，除非邮件也在计划迁移。

SPF 可能使用一个 TXT 策略，盲目新增第二条会造成问题。按邮件商官方文档合并授权来源。发送测试邮件并查看邮件商验证状态。网站打开不能证明邮件 DNS 正常。

## 证书中的域名必须匹配

证书可以覆盖单个域名、多个名称或通配符。`*.example.com` 通常不自动覆盖裸域，也不覆盖更深层级，具体按证书规则。用户访问 `api.example.com`，服务器却提供 `www.example.com` 证书，浏览器会警告。反向代理需要为每个站点选择正确证书。SNI 允许同一 IP 上根据域名提供不同证书。老旧客户端兼容性以实际目标为准。

证书续期监控至少提前告警。自动任务成功还要从公网握手验证新有效期。

企业网络可能让同一域名在内网解析私有地址，在公网解析公开地址，称为 Split DNS。办公室正常、手机网络失败，比较两个解析器。不要把内网私有 IP 当成公网目标发布。VPN 会改变 DNS 与路由。排错记录是否连接 VPN、使用哪个网络。关闭 VPN 仅作对照，不能违反组织安全政策。

内部域名和拓扑属于敏感信息，分享日志时遮盖。证书仍要与实际名称和信任体系匹配。

## 域名重定向与 DNS 不同

DNS 只回答名称记录，不把 `/old` 路径重定向到 `/new`。路径重定向由 Web 服务器、CDN 或应用返回 HTTP 3xx。注册商提供的 URL Forwarding 也是其运行的一项 Web 服务，不是 DNS 标准记录。使用时查 HTTPS、状态码和查询保留。

想让 `example.com` 跳到 `www.example.com`，先让两者都解析到能提供证书的入口，再配置 HTTP 重定向。用 Network 检查状态与 Location，避免 JavaScript 跳转影响搜索与可访问性。

## 本章验收清单

能拆解完整 URL，区分域名、DNS、IP、端口与路径。能解释 localhost 为什么只指当前设备。能只读查询 A 与 AAAA，找到权威 Nameserver 和记录 TTL。不会为修网站删除邮件记录。

能把默认域名正常、自定义域名失败定位到绑定、DNS 或证书。修改前保存旧值与回滚。

通配记录让未明确创建的子域也匹配，例如 `*.example.com`。多租户预览域名可能使用。错误通配会把拼错域名送到真实服务，掩盖配置问题。应用仍要验证 Host，不能为任意子域提供敏感页面。明确记录通常优先于通配，具体解析按 DNS 规则。证书也要覆盖实际域名。

不再使用通配时先查询依赖项目，避免删除所有预览入口。

## 域名接管风险

DNS CNAME 仍指向已删除的第三方项目时，攻击者可能在该平台认领目标并通过你的域名提供内容。下线顺序先移除 DNS 或平台绑定，再删除外部资源。定期扫描悬空记录和平台提示。发现可接管线索时私密报告，不自行认领他人域名。修复后验证 DNS 与 HTTPS。

责任表记录每个子域对应平台和负责人，项目下线包含域名清理。

面向中国大陆提供公开网站时，域名、服务器位置、备案与内容要求可能涉及当地法规和服务商政策。是否需要备案取决于部署位置、服务类型和当时规则。这类信息会变化，本书在部署章节只引用检索日的官方主管部门与服务商资料，并写明截至日期。不要依据旧博客把结论写成永久不变。

域名解析正常也不保证不同地区网络质量一致。上线前从目标地区和运营商测试，记录 DNS、连接时间和失败比例。CDN、跨境网络与第三方 API 都可能影响。

## 最小观察练习

选择一个公开网站，抄写完整 URL。标出 Scheme、Host、Path、Query 与 Fragment。没有的部分写“无”。使用浏览器 Network 查看主文档 Request URL。比较地址栏片段是否出现在请求中。不要对不属于你的服务器做端口扫描。

若自己有域名，进入注册商只读查看 Nameserver，再进入实际 DNS 控制台找 A、AAAA 或 CNAME。不要修改。记录每条记录的名称、类型、目标和 TTL。成功结果是能指出域名由谁注册、谁托管 DNS、哪个记录指向网站、浏览器最终访问什么 URL。

域名返回旧网站，查权威 DNS 和缓存。IP 能访问、域名不能，查 DNS 记录与证书。域名能解析、连接被拒绝，查端口监听与防火墙。自定义域名显示证书错误，查平台域名绑定、DNS 指向和证书状态。不要点击浏览器继续访问生产登录页。

API URL 在开发机正常、用户设备失败，检查是否写了 localhost、私有 IP 或仅 HTTP。手机上的 localhost 指手机自身。URL 中出现 `#` 后参数没到服务器，检查片段与查询参数是否混淆。敏感数据不要放进任一 URL 部分。

## 域名问题先固定查询位置

AI 可以解析 URL、解释 DNS 查询结果、比较权威与本地答案，画出域名到服务的路径。它也能根据监听与代理配置寻找端口不一致。不要把注册商登录、转移码、完整验证令牌或私有 DNS 区域交给 AI。执行 DNS 修改前要展示将改的记录与回滚值。

域名所有者、续费、Nameserver、DNS 删除与转移需要亲自确认。开放端口、改变防火墙和忽略证书错误也保留人工决定。下一章会沿着已经找到的 URL 继续前进，解释 HTTP 方法、状态码、HTTPS 和 TLS 怎样完成一次请求与响应。
