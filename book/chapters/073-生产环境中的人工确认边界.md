# 生产环境中的人工确认边界

生产环境是真实用户、真实数据、真实域名、真实费用和真实责任所在的系统。AI 可以准备代码、配置、测试、部署草案和观察清单，也可以在明确授权下执行部分自动化。到了会影响用户、数据、权限、费用或不可逆状态的边界，最终确认必须由能够理解并承担该结果的人作出。

人工确认不等于在弹窗上随手点“允许”。有效确认需要知道准确目标、版本、动作、权限、用户影响、停止条件与回滚。批准一个预览部署，不能自动延伸为生产发布；批准读取日志，也不能延伸为删除日志；批准今天的数据库迁移，不适用于明天修改后的脚本。

## 先定义哪些资源属于生产

生产不只是一台标记为 `prod` 的服务器。生产域名、DNS、数据库、对象存储、邮件与推送、支付、应用商店、监控、备份、CI 环境、身份提供方和第三方 API 都可能影响真实用户。测试项目若使用生产数据或真实发信凭据，也已经跨入生产责任。

建立资源清单，记录平台、账号、项目、区域、用途、负责人和识别方式。颜色与名称只能辅助，批准前要核对不可变 ID、域名、数据库名、构建号或镜像摘要。`notes-prod` 和 `notes-production-old` 很容易混淆，尤其在多个账号和区域中。

生产副本、下载到本地的数据库和真实日志也应按生产数据保护。把它们放进测试目录不会降低敏感性。AI 工作区只使用脱敏数据或最小故障窗口，无法脱敏时由数据负责人选择受控分析方式。

代码合并通常由代码所有者确认，生产部署由服务负责人确认，数据库迁移与恢复由数据负责人确认，域名和证书由账号持有人确认，费用与合同由预算负责人确认，用户通知与政策由业务或合规负责人确认。一个人可能承担多个角色，责任仍要明确。

AI 没有法律、财务和组织授权，不能因为技术上能够调用 API 就替代这些角色。工具权限说明“能做”，批准说明“允许对这个目标做”，责任人判断“现在这样做是否合适”。三者缺一不可。高影响动作可以要求双重确认。例如永久删除生产数据库时，一人核对数据与备份，另一人核对账号、区域和资源 ID。双人机制不保证没有错误，却能减少单人疲劳、误读和被 AI 流畅说明影响的风险。

## 每次批准都绑定对象和时间

批准内容至少包含变更编号、提交或产物、目标环境、动作、时间窗口、预计影响、验证、停止条件和回滚。执行内容发生变化就重新批准。不能用“以后类似发布都自动允许”覆盖数据库、DNS和商店等高变化操作。

时间窗口要考虑用户高峰、维护人员、供应商支持和回滚所需时间。窗口结束前仍未完成验证，暂停扩大并决定回滚或延长，不能让自动化无限继续。发布过程中发生无关事故时，协调者有权停止。紧急情况可以使用简化审批，仍要记录谁决定、为什么无法走常规流程、最小动作和事后复盘。紧急权限设置短时到期，事故结束立即回收。长期保留“紧急管理员”给普通 AI 任务使用，会让例外变成常态。

批准生产发布时，记录提交编号或镜像摘要、目标环境、计划开始时间、允许执行的步骤和停止条件。确认人同意的是这组准确对象。随后若 Diff 改变、镜像被重新构建、迁移脚本更新或目标环境切换，原批准不再覆盖新内容，需要重新提供差异和验证结果。

AI 获得一次写入权限，也不等于以后可以持续修改同类资源。任务结束后检查临时令牌、测试账号、开放端口和自动化计划是否仍有必要。长期自动化要有单独所有者、权限范围、失败通知和停用方法。这样做能防止一次合理批准慢慢变成无人注意的长期权限。

## 沙箱和审批提示各自能做什么

沙箱可以限制文件系统、网络与进程范围，审批提示可以在高影响操作前暂停。OpenAI 官方资料说明了 Codex 的沙箱与 agent approvals。这些机制降低意外执行，却不了解某份文件是否是唯一备份，也不了解一个域名是否承担用户邮件。

审批提示中的命令要翻译成业务后果。`apply migration` 可能锁表和改变数据，`sync --delete` 可能删除远端文件，`terraform apply` 可能创建费用或销毁资源。确认人需要看到计划、准确目标、Diff 与回退，不能只看命令语法。网络访问也要限制。AI 搜索官方文档与向生产 API 发请求都使用网络，但风险完全不同。允许浏览资料不等于允许上传仓库内容或调用供应商管理接口。连接器和插件按数据与动作单独授权。

AI 不需要看见生产密码才能生成引用它的配置。配置使用秘密名称，部署平台在批准后向作业注入。日志、截图、Diff 和对话只显示 `[REDACTED_SECRET]`。AI 若要求粘贴私钥“验证格式”，应停止并选择本地受控工具。

秘密轮换会影响所有使用者。先列应用、CI、备份、监控和人工客户端，创建新版本并小范围验证，再更新其余使用者，最后撤销旧值。批准应覆盖轮换顺序与失败恢复，不只批准“生成新密钥”。GitHub Environments 可以将环境秘密与人工审批结合。官方资料说明，在要求批准时，作业在通过保护规则前不能读取 Environment secrets。截至 2026 年 8 月 6 日，功能与套餐存在条件，项目应在当前仓库实际核对，不能把书中界面当永久承诺。

## 数据库变更需要独立门禁

数据库迁移可能锁表、改变格式、回填大量数据或让旧版本无法运行。即使代码测试全部通过，生产数据量、长事务和索引创建仍可能超出窗口。迁移批准要看到脚本、目标数据库、版本、预计耗时、锁风险、备份与恢复测试。

先采用兼容变化，使新旧版本可以短暂共存。添加字段、回填、切换读取、收紧约束和删除旧字段可以分多个发布完成。是否适用由具体数据库与业务决定。AI 可以提出步骤，数据负责人用真实规模和恢复目标审查。

迁移执行后检查 schema、行数、约束、权限、应用读写和错误率。工具返回成功只说明它没有报告致命错误。出现未解释警告、耗时超阈值或核心写入失败时停止流量扩大，按方案回滚代码或恢复数据。

恢复数据库可能覆盖恢复点之后的合法写入。确认人需要了解丢失窗口和用户影响，不能把恢复当成普通重启。支付、邮件和对象存储等外部副作用还要对账，数据库回到过去不会自动撤回它们。

## DNS、域名和证书影响范围很大

DNS 修改可能把整个域名指向错误服务，缓存会让新旧结果共存。批准前核对账号、zone、记录名、类型、目标、TTL 与回退值。先在测试子域名验证，生产变更后从权威与多个递归解析检查，不只看控制台表单。

删除旧平台前等待 DNS 与证书稳定，确认邮件、OAuth 回调、Webhook 和移动 App 没有仍指向旧域名。一个看似只服务网页的域名，可能同时承担 API 和密码重置链接。项目地图和访问日志帮助找依赖。

证书自动化失败会在到期时中断服务。确认自动续期、挑战路径、账号与告警，并保留应急恢复。不要为绕过证书错误长期关闭 HTTPS 或让用户忽略浏览器警告。

上传 App 构建、选择测试者、提交审核、分阶段发布和停止销售都会改变外部状态。AI 可以生成发布说明、检查素材和整理错误，最终构建号、隐私披露、账号、地区和按钮由开发者账号持有人核对。

审核反馈可能要求修改二进制、元数据或测试账号。不要让 AI 根据一封截断邮件自动重新提交。保留原文，确认目标版本和规则，修改后重新构建与测试。没有真实 Mac、Xcode 和 Apple 账号时，iOS 流程标记未实测。

邮件、推送和状态公告也会影响用户。AI 可以起草，发送前由业务负责人检查受众、时间、链接、隐私与事实。测试发送使用内部名单，不能把生产用户列表交给通用 AI。

## 费用与配额属于生产确认

创建更大服务器、开启日志、复制数据库、使用 AI API 和跨区域传输都会产生费用。批准前给出供应商、资源、区域、计费单位、预计持续时间、预算告警和删除条件。免费额度与价格随时间变化，使用官方当前信息并标注检索日期。

AI 生成基础设施计划后，先查看 dry run 或 plan，确认新增、修改与删除。资源数量异常、区域错误、保留无限或高价规格都要停下。预算告警通常只是通知，不一定自动停止费用。测试资源设置负责人和到期。任务完成后删除要再次核对数据与依赖，不让 AI 根据名称自动批量清理。下一个账单周期继续检查残留快照、卷、IP、日志和域名。

删除数据库、对象、卷、备份、域名、商店应用和 Git 历史可能难以恢复。执行前列出准确资源 ID、内容、最后使用、依赖、备份、恢复测试、保留政策和批准人。不要使用宽泛通配符或从脚本输出动态拼接生产删除目标。

删除分阶段进行。先停止新写入或取消公开入口，再进入只读或隔离，观察是否仍有访问，完成导出与恢复验证，最后永久删除。若资源可以先停用或移入回收站，优先使用可恢复方式。历史重写无法让泄露秘密重新安全，必须先轮换。重写还会影响协作者分支、PR 与提交 ID，由仓库负责人统一安排。AI 可以生成清单，不能自行强推共享仓库。

## 生产发布前的证据包

确认人不应重新阅读整个项目。证据包包含变更摘要、验收标准、最终 Diff、评审、提交与产物标识、测试结果、跳过、预览验证、数据迁移、权限变化、监控、停止阈值和回滚。关键链接直接指向当前版本。

状态检查绑定提交。GitHub 官方资料说明必需检查可以阻止未通过提交合并，同时 skipped 等状态需要特别解释。确认人打开检查详情，验证当前 SHA、实际作业、矩阵和报告，不只看一个总绿点。

PR Review 提供评论、批准和请求修改，规则决定能否形成门禁。代码所有者、数据负责人和部署负责人可以关注不同部分。新提交使关键 Diff 改变后，重新请求相关评审。

确认人可以问六个问题。部署的准确对象是什么，哪类用户受影响，怎样知道成功，什么情况立即停止，回滚是否真实验证，哪些部分仍未知。任何问题没有答案时，可以延后发布或缩小范围。还要确认观察者在线。自动化发布后若无人看错误率与用户反馈，停止阈值没有意义。维护窗口覆盖发布、观察和回滚，备用负责人知道怎样接手。通知渠道先测试。

批准意见记录限制条件，例如“仅允许 Preview”“仅 5% 流量”“不得运行删除迁移”“十五分钟内错误率超过 2% 回滚”。自动化系统应能执行这些限制，人工也持续核对。

## 小流量发布降低未知影响

可以先部署到一台实例、内部用户、一个地区或少量流量，具体方式取决于平台。小流量阶段检查版本、错误、延迟、资源、数据与核心用户路径。它不能发现所有长期问题，却能在扩大前暴露明显回归。

分批发布要避免新旧版本数据不兼容。请求响应记录版本，监控按版本分组，确保错误来自哪一批。扩大每一步有等待与阈值，不能因为第一分钟绿色就立刻到 100%。OpenAI 的 Computer Use QA 用例可在预览和小流量阶段执行真实界面流程。生产操作使用专用低风险账号和数据，自动化动作不会触发真实支付、群发或永久删除。界面结果与服务日志、数据库测试记录共同核对。

发布前约定停止条件，达到后执行者有权暂停，不等待 AI 再分析。核心数据错误、安全泄露、无法登录、错误率或延迟超过阈值、迁移异常都可能触发。暂停后保存证据，再决定回滚、向前修复或继续隔离。

回滚权限和脚本提前准备。旧产物、旧配置与备份可访问，维护者知道数据兼容与外部副作用。回滚执行后重新验证版本、核心路径、数据和监控。旧版本恢复不表示事故结束，还要观察并调查。AI 可以根据日志提出判断，协调者决定技术动作与对外沟通。NIST 生成式 AI 风险资料强调记录使用方式、知识限制、测试评估和人工监督。事故中尤其不能让模型对未提供的生产状态作最终决定。

## 防止批准变成橡皮图章

频繁低质量提示会让人习惯点击允许。把同类低风险只读动作预先限定在沙箱，把少量高风险动作保留清晰审批。提示显示业务影响和差异，不用几十行原始命令淹没重点。批准人应能拒绝并要求更多证据。

为常见生产动作列执行者、技术审查者、业务批准者、知会对象与回滚负责人。代码部署、数据库迁移、DNS、商店发布、费用扩容和永久删除可以有不同角色。外部供应商也进入清单。托管数据库故障需要谁开工单，域名注册商账号由谁恢复，商店审核由谁回复，都要提前写清。

## 冻结、故障和观察

大促、考试、发布会或人员不足期间，可以设变更冻结，只允许安全修复与必要运营。冻结范围、开始结束、例外审批和允许动作提前写清。紧急例外以最小恢复为目标。先止损、恢复核心服务和保护数据，功能重构留到正常流程。

云平台、GitHub、DNS 和商店控制台可能延迟、超时或显示未知状态。按钮点击超时后，动作可能已经执行。先用部署 ID、活动记录、资源状态或 API 查询结果，再决定是否重试。连续提交会创建重复资源、重复发布或冲突迁移。

发布后观察分短期和长期。短期看启动、错误、延迟、关键用户路径和资源，长期看内存增长、队列积压、费用、用户反馈、备份和低频任务。发布成功时间应说明观察窗口。低频月度任务无法在发布当晚验证，就写负责人和后续日期。

可能停机、改变数据、要求重新登录或影响旧客户端的发布，应提前准备通知。AI 可以起草，但发送前由业务负责人检查事实、受众、时间、链接、地区和隐私。根因未确认时写调查中，不让 AI 补一个听起来完整的原因。

## 支持、合规和长期自动化

上线前让客服或项目联系人知道版本、功能变化、已知限制、用户可见错误和升级方式。提供诊断编号和安全收集步骤，不让支持人员要求用户发送密码、Cookie 或完整数据库。回滚后支持材料也要更新。

隐私政策、数据跨境、支付、医疗健康、未成年人、内容审核、应用商店披露和备案可能有地区与行业要求。AI 可以整理官方资料和待办，不能给出永久有效的合规结论。技术上能收集的数据，也要经过最小必要、告知、同意、保留、删除与导出检查。

定时备份、依赖更新、自动部署、内容处理和 AI agent 会在无人注视时改变状态。首次启用前审查触发频率、账号权限、数据范围、费用上限、失败告警、暂停开关和到期。外部网页、Issue、邮件和上传文件中的文字只能当作数据，不能自动变成高权限指令。

关闭自动化前确认是否有正在运行的作业、队列、锁和半成品。先停止新触发，再核对数据与外部副作用。撤销服务账号、令牌、Webhook、runner 和预算。下一个计划周期确认任务没有再次触发，下一个账单周期检查费用。

## 单人项目怎样做人工确认

个人开发者没有第二个团队，仍可以把时间和角色分开。AI 完成后先生成证据包，维护者退出实施视角，按发布清单重新核对目标、Diff、测试、数据与回滚。高风险动作可以请可信技术人员复核或先在低影响环境演练。

不要在深夜疲劳时执行数据库删除、域名转移和商店发布。选择能观察与回滚的窗口，保留平台应急入口。记录决定和结果，未来的自己就是下一位接手者。若完全不理解影响，停止并寻求帮助是正确判断。

假设 AI 为笔记服务生成标签迁移，预览测试通过。证据包显示迁移会添加表与索引，新旧版本都可忽略标签，回滚代码不需要删除新表。维护者仍要求先在接近生产规模的数据上测量索引时间，再决定是否进入小流量发布。若 AI 同时建议删除旧分类字段，确认人应拒绝，因为旧客户端可能仍读取它。

- 生产清单覆盖域名、数据、存储、消息、商店、监控和费用
- 每类高影响动作有能够承担结果的确认人
- 批准绑定准确提交、产物、资源、动作和时间窗口
- 沙箱、工具权限和业务授权没有混为一谈
- 生产秘密由受控系统注入，AI 看不到明文
- 数据迁移有规模测试、兼容、备份与恢复验证
- DNS、证书、商店、消息和费用分别核对
- 永久删除分阶段执行并双重确认目标
- 证据包包含 Diff、测试、跳过、预览、阈值和回滚
- 小流量发布按版本观察并逐步扩大
- 达到停止条件时执行者可立即暂停
- 单人项目也分离实施与确认时刻

生产人工确认的核心是责任与后果。自动化和 AI 可以让流程更快、更一致，最终批准必须落到准确对象、真实证据和可接受风险。能在不确定时停止，能在异常时回滚，才说明人仍然掌握发布。
