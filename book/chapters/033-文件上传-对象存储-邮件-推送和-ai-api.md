# 文件上传、对象存储、邮件、推送和 AI API

现代应用的数据不只在数据库。用户上传图片，对象存储保存文件；邮件服务发送确认信；推送服务把通知送到设备；AI API 接收任务并返回生成结果。每增加一个外部服务，就增加权限、费用、失败和恢复边界。

本章先把它们放回系统位置。读者不需要同时注册所有服务。只有产品确实需要时，才选择一项并完成最小、安全的接入。

## 文件为什么不全放数据库

图片、音频和视频体积大，传输方式与结构化记录不同。对象存储为文件数据提供 Bucket、Object、Key 和元数据模型。数据库保存文件记录，例如所有者、对象 Key、原始文件名、类型、大小、状态和创建时间。文件字节保存在对象存储。

页面需要文件时，后端检查权限，再返回受限下载或短时签名 URL。公开资源可以通过明确策略和 CDN 提供。把文件直接塞进应用服务器本地目录，在多实例和重新部署时很容易丢失或不一致。

Bucket 是对象容器，Object 包含文件数据与元数据，Key 是 Bucket 中的唯一标识。AWS S3 官方说明也使用这三个概念。Key 看起来可以包含斜杠，例如 `users/17/avatar/abc.jpg`，对象存储内部模型未必等同普通文件夹。

不要直接使用用户原始文件名作为唯一 Key。重名、特殊字符和路径欺骗都会造成问题。生成随机标识，原始名称单独保存用于显示。Key 也可能进入日志和 URL，不要含邮箱、身份证号等敏感信息。

## 一次受控上传流程

客户端先向后端请求上传。后端验证登录、用途、大小上限和配额，生成对象 Key 与临时上传授权。客户端把文件直接上传对象存储，减少后端转发大文件的负担。上传完成后通知后端。后端确认对象存在、大小和类型，必要时进入病毒扫描、图片解码和转码队列。验证完成前状态为待处理，不对其他用户公开。

成功后数据库记录变为可用，页面取得受控访问 URL。失败对象按保留策略清理。

扩展名可以改，浏览器提交的 `Content-Type` 可伪造，文件头也不能单独证明安全。文件名更由用户控制。OWASP 建议组合允许扩展名、类型、文件签名、随机文件名、大小限制、授权、存储隔离与恶意内容扫描。

允许列表优于试图列出所有危险类型。头像只需要 JPEG、PNG 或 WebP，就不接受 HTML、SVG、压缩包和可执行文件。即使允许图片，也要用安全图片库解码并重新编码，防止伪装内容与元数据问题。图像处理库也要更新。

## 文件放在哪里

OWASP 建议优先把上传文件放到不同主机，或至少放在 Web Root 之外。对象存储天然与应用文件目录分开，访问策略仍要配置。私有 Bucket 默认不公开，后端通过签名 URL 短时授权。AWS S3 当前文档说明通用 Bucket 与对象默认私有，并建议保留公共访问阻止，除非明确需要。

公开产品图片可放公开读取区域，用户证件与私密附件不能靠难猜 Key 保护。日志、备份和缩略图也继承数据敏感性。原图删除后，派生缩略图与 CDN 缓存要按策略处理。

大文件一次上传在移动网络容易失败。分片或可恢复上传允许断线后继续，具体由存储 SDK 提供。后端先限制最大总大小和允许分片数量。未完成上传占用空间，需要到期清理。客户端显示已上传字节与可重试状态。不要在最后合并失败时显示百分之百成功。

完成后验证对象大小和校验值。仅收到客户端“完成”不能证明存储成功。

## 删除文件是一项跨系统操作

用户删除头像时，数据库记录、对象、缩略图、缓存和备份保留期可能不同。先按业务决定软删除还是立即删除；任务队列执行对象清理，成功后记录状态；失败可以重试。对象存储启用版本控制后，普通删除可能只创建删除标记，旧版本仍占空间。AWS S3 的 Versioning 能帮助恢复误删，也需要生命周期和权限管理。

隐私删除要求与灾难恢复备份可能存在保留冲突，政策要透明并符合法律与合同。

应用通常调用邮件服务 API，不在 Web 请求中自己维护完整邮件服务器。后端保存 API 密钥与发送请求。注册确认、密码重置和订单通知使用模板与变量。用户输入需要转义，不能把未经处理的 HTML 注入邮件。

发送 API 接受只说明服务商收到了任务。最终投递还可能退信、延迟、被拒或进入垃圾邮件。使用 Webhook 接收送达、退信和投诉，验证签名并去重。把状态写入数据库供客服查询。

## 事务邮件与营销邮件

事务邮件由用户操作触发，例如验证码和订单确认。营销邮件需要订阅、退订和合规管理。两类邮件使用不同模板、发送策略和名单。不能因为用户注册就无限发送营销内容。退信和投诉会影响发送信誉。停止向永久退信地址重复发送。

域名需要 SPF、DKIM 与 DMARC 等配置，按邮件供应商当前文档设置。网站 DNS 迁移要保留这些记录。

重置链接使用随机、短期、单次 Token，服务端存安全表示。请求页面不要透露某邮箱是否存在。链接只允许修改对应账号，使用后立即失效。改密码后可撤销其他会话并通知用户。回调域名必须在允许列表，防止攻击者提供跳转地址窃取 Token。

邮件正文不包含旧密码，也不让用户回复凭据。

## 推送通知的路径

设备或浏览器先取得推送权限与订阅 Token，把它安全关联到用户和设备。可信后端向推送服务发送消息，推送服务再尝试到达设备。Firebase Cloud Messaging 当前模型包含可信发送环境与客户端应用。服务端密钥不能放进 App 或网页。

Token 会轮换或失效。发送返回无效时清理记录，用户退出账号时解除关联。通知到达不等于用户阅读，顺序和时效也不绝对。关键业务状态仍以服务器查询为准。

Web Push 使用浏览器 Push API、Service Worker 与推送服务。MDN 说明订阅端点应避免泄露，并且 Push 需要安全上下文。原生 Android 与 iOS 推送通过平台服务和 App 配置，权限与后台行为不同。不能把网页教程直接套进 Flutter 发布。

用户拒绝通知后尊重选择，不反复弹窗。先解释通知价值，再由用户主动开启。点击通知的深层链接要验证登录和资源权限，不能凭通知内容绕过后端。

## AI API 是外部服务调用

AI API 与地图、邮件相似，后端持有密钥并发送请求。不同之处在于输入可能很大，输出不确定，费用随 Token、媒体和模型变化。客户端把任务交给自己的后端。后端验证用户、配额和内容，去除不应发送的个人信息，再调用供应商。

响应经过格式校验和安全检查后保存必要结果。高风险操作不能直接执行模型输出。供应商 API 版本、模型名称、价格、数据保留和地区能力会变化。正式接入只引用其当前官方文档并记录检索日期。

网页和 App 包都能被用户检查。即使变量来自构建环境，只要进入客户端就会暴露。后端使用按项目限制的密钥，设置额度和费用告警。不同环境使用不同密钥。泄露后立即撤销并轮换，查看调用日志与费用。只从仓库删除不能撤回已复制凭据。

代理后端还要认证和限流，否则攻击者可以免费调用你的付费接口。

## AI 调用的超时与任务状态

生成任务可能慢，使用任务队列比让 HTTP 请求无限等待更可靠。后端返回任务 ID，前端查看状态。超时后供应商可能仍在处理。重试前确认请求幂等和计费行为。流式输出提升体验，客户端仍要处理断线、部分内容和取消。已显示文本不一定已经通过完整安全检查。

记录供应商请求 ID、模型版本、参数类别和费用数据，不在日志保存完整敏感提示词。

调用可能 DNS 失败、连接超时、返回 4xx、返回 5xx、限流或给出格式错误。每类处理不同。认证失败不应持续重试，限流按响应等待，暂时 5xx 可有限重试。输入不合规则反馈给用户或开发者。

设置熔断与降级。邮件失败时预约仍可成功并稍后补发，头像处理失败时保留待处理，不把损坏文件公开。把供应商状态与自己请求日志分开记录，避免把内部错误错误归因于第三方。

## 一个活动报名系统

用户报名后，数据库创建报名记录。后台任务发送确认邮件，邮件状态单独保存。用户上传资格证明，先进入私有 Bucket，扫描通过后管理员才能查看。下载使用短时 URL。活动前一天，推送服务发送提醒。未授权通知的用户仍能在应用内看到日程。

AI API 可帮助生成个人行程摘要，但输入只含必要公开日程，不发送身份证明文件。四个外部能力均可失败，报名记录仍是权威业务事实。补偿和重试围绕它进行。

上传成功但别人能遍历私密文件，立即关闭公共访问并检查日志。不要只改前端链接。邮件接口 200 但用户没收到，查看投递事件、退信和 DNS 认证。API 接受不等于收件箱送达。推送重复，检查任务重试与幂等 Key。不要仅在客户端去重。

AI 费用异常，按用户、端点、模型和时间分析，限制入口并轮换可能泄露密钥。

## 对象元数据

对象元数据包含 Content-Type、大小、缓存策略和自定义标签。错误 Content-Type 会让浏览器下载或错误解释文件。上传完成后由可信服务确定公开元数据，不直接采用客户端声明。下载时设置安全的 Content-Disposition。

用户文件名仅作为显示值，输出到 Header 时正确编码，避免换行和特殊字符注入。缓存公开图片可以很长，私有签名 URL 和敏感文件不使用公共缓存。

原图上传到私有临时区，扫描和解码成功后生成多尺寸缩略图。数据库记录每个派生对象状态。处理进程不覆盖原文件，便于重新生成。公开页面只引用验证后的派生图。EXIF 可能包含位置和设备信息。按产品隐私策略移除不需要元数据。

处理失败保留错误原因和有限重试，超过次数进入人工检查，不无限循环。

## 压缩包与文档预览

压缩包可能包含路径穿越、极高解压比例和大量文件。不要在 Web 根目录直接解压用户上传。限制解压总大小、条目数与嵌套深度，在隔离环境处理。文件名规范化后仍检查目标路径。PDF 和 Office 预览器也可能有漏洞，使用受维护工具并隔离。无法安全预览时提供受控下载。

管理员下载可疑文件前给出警告，不在日常工作电脑自动打开。

后端先查询文件记录和当前用户权限，再生成短时签名 URL。URL 到期后需重新申请。签名 URL 是临时凭据，泄露期间持有者可访问。聊天和日志不保存完整 Query。需要一次下载或更强控制时，通过后端代理并记录使用，代价是带宽和性能。

共享链接有撤销 ID 和到期，不能永久使用对象原始公开 URL。

## 跨域与对象存储

浏览器直传需要存储服务允许前端 Origin、方法与 Headers。CORS 只决定浏览器是否允许读取，不授予对象权限。Origin 使用精确生产和预览域名，不无条件通配带凭据请求。预检失败时查看 Network 和存储 CORS 配置。不要关闭浏览器安全功能。

上传授权、Bucket Policy 和 CORS 三者分别检查。

模板进入版本控制，包含主题、HTML、纯文本和变量清单。纯文本版本帮助不支持 HTML 的客户端。变量缺失时不要发送半成品。渲染前校验必需字段。邮件中的按钮同时提供可见 URL，用户能辨认目标域名。敏感链接使用短期 Token。

上线前在多种邮箱和手机检查，深色模式下保证可读。

## 退信与投诉

硬退信表示地址长期无效，停止继续发送。软退信可能是邮箱暂满，可有限重试。投诉意味着收件人标记垃圾邮件，要进入抑制名单。忽略会损害域名信誉。Webhook 事件验证签名并幂等处理。状态按邮件消息 ID 关联。

删除邮件服务前导出必要抑制名单，迁移后继续尊重用户选择。

注册请求把邮件任务写入队列，立即返回账号创建结果。Worker 读取并调用供应商。任务包含模板 ID、收件人引用和业务事件，不在普通日志记录完整正文。失败按错误类别重试。无效地址和认证失败不持续重试。

重复任务用业务 Key 去重，避免用户收到十封确认信。

## 通知偏好

用户选择接收哪些通知、通过邮件还是推送。安全告警可能有不同法律与产品规则。偏好存服务端，多个设备共享。设备本地关闭系统通知时，服务器推送仍可能失败。营销通知提供退订，事务通知保持必要最少。通知正文避免显示敏感内容在锁屏。

删除设备 Token 不删除用户偏好，二者是不同数据。

通知点击可打开订单或消息。App 收到 ID 后仍从 API 获取资源并检查权限。用户已退出时先登录，登录后再继续目标。资源已删除时显示清楚结果。链接 Schema 和版本保持兼容，旧 App 收到新类型要安全忽略。

不要把完整 Token、支付信息和私人正文塞进通知 Payload。

## AI 输入的最小化

只发送完成任务所需内容。生成活动摘要不需要用户证件和完整账号资料。在进入第三方 API 前去除直接标识符，必要时用内部占位 ID。输出重新关联由受控后端完成。查供应商数据保留、训练使用、地区与删除机制。企业合同和普通 API 条款可能不同。

用户需要知道 AI 参与了什么和结果怎样使用。高风险领域加入人工复核。

AI 读取用户文件或网页时，内容可能包含诱导模型泄露秘密或调用工具的文字。把外部内容视为不可信数据，不当作系统指令。模型没有直接访问数据库管理员密钥。工具调用使用允许列表、参数验证和人工确认。删除、付款、发信等动作不能仅凭模型文字执行。

记录工具请求与批准者，输出仍按普通不可信输入处理。

## AI 输出格式验证

要求 JSON 不保证模型每次返回有效 JSON。后端使用 Schema 解析，失败时重试或进入人工处理。字段类型、长度、枚举和业务关系都要检查。模型生成的 URL 和代码不能直接运行。结构化结果保存供应商请求 ID 与模型版本，便于追踪变化。

面向用户展示时标明可能出错，提供纠正和反馈入口。

先创建新密钥，用测试环境验证。生产更新并部署后确认新密钥有调用，最后撤销旧密钥。若供应商只允许一个有效密钥，安排窗口并准备降级。不要先撤销再研究配置。密钥按邮件、存储、推送和 AI 分开，避免一个泄露影响全部。

服务账号权限只允许必要操作，读取与删除权限分开。

## 外部服务状态表

为每项服务记录正常、延迟、失败、限流和配置错误的用户表现。为每种状态定义重试与降级。对象存储失败时暂缓上传，邮件失败时排队，推送失败时保留应用内通知，AI 失败时允许人工或稍后重试。

核心业务不能因非关键通知故障全部回滚。依赖等级在设计时明确。供应商恢复后控制重放速度，避免积压任务同时冲击。

费用可能包含存储容量、请求次数、数据取回、出站流量、图片处理和早删费用。只看每 GB 存储价会漏掉下载。缩略图减少移动端出站，缓存公开资源减少重复读取。私有文件缓存策略仍以权限为先。生命周期把不常访问对象转为冷存储或过期，恢复速度和最低保存期会不同。

设置预算告警，按 Bucket、前缀或标签区分测试和生产用量。价格写查询日期。

## 孤立对象清理

上传后未创建数据库记录，或记录删除后对象任务失败，会出现孤立对象。清理任务比较待处理状态与创建时间，只删除超过安全窗口且无有效引用的对象。不要仅根据对象不在当前页面出现就删除，可能有历史版本或后台任务引用。

清理先生成候选报告，在测试环境验证。生产批量删除使用版本控制或可恢复保留。

每个用户、组织和文件类型设置大小与数量上限。检查在授权前完成，最终对象仍核实大小。并发上传可能同时通过“剩余配额”检查。数据库使用预留或事务计数，避免超额。删除进入保留期时，配额是否立即释放由产品决定。界面说明占用计算方式。

管理员扩容有审计和费用提示，不能让用户修改自己的配额字段。

## 邮件链接追踪与隐私

供应商可能默认追踪打开和点击。是否启用要根据必要性、隐私说明和地区规则决定。密码重置等安全邮件不应依赖追踪像素判断成功。点击重定向还会增加安全和可用性依赖。关闭追踪时确认模板链接仍直达可信域名。启用时最小化参数和保存期限。

分析数据不等于用户本人阅读，邮件客户端会预取图片和链接。

同一新闻多次更新时可使用折叠或主题机制，只保留最新通知。具体能力按推送平台。告警类消息需要每条保留，营销类要限制频率。用户设置安静时段。批量发送分段执行并监控失败，不一次向全部用户发送未验证模板。

紧急停止开关能关闭某类推送，同时保留应用内消息。

## AI 成本与缓存

重复生成同一公开摘要可以缓存，Key 包含输入版本、模型与关键参数。用户私有内容不能进入公共缓存。限制输入长度、输出上限和每用户频率。大文件先提取必要片段，不整库发送。流式中断仍可能计费，指标记录开始、完成、取消和供应商用量。

成本异常时能够按功能关闭 AI，而不影响核心预约和资料读取。

生成内容可能包含错误或与受保护作品相似。公开发布前由人审查，尤其是品牌、法律和教育材料。要求引用时验证链接和原文，模型生成的来源可能不存在。事实结论回到可靠资料。保存用户授权与生成用途，提供删除和纠正流程。不要宣称 AI 输出天然无版权风险。

本书自己的技术事实也不会以 AI 输出为唯一依据。

## Webhook 签名失败

验证通常需要原始请求体。框架若先解析再重新序列化，字节变化会导致签名不匹配。按供应商当前 SDK 取得原始 Body、签名 Header 与时间戳。密钥只在服务端。失败请求返回拒绝并记录事件 ID 与时间，不记录完整敏感正文。

轮换 Webhook Secret 时支持新旧短暂重叠，验证成功后撤销旧值。

攻击者把 HTML 文件改名为 `avatar.jpg`，客户端声明 `image/jpeg`。旧服务只看扩展名，上传到公开 Bucket。访问文件时浏览器按错误元数据解释内容，带来安全风险。修复流程关闭公开读取，核查历史对象和访问日志。

新流水线限制允许格式，检查签名，用图片库解码再编码，生成随机 Key。原始文件保持私有待扫描。公开头像只使用处理后的派生图，并设置固定图片 Content-Type。失败上传定时清理。

## 什么算本章完成

文件、邮件、推送和 AI 各有独立权限、状态、重试、费用和退出记录。非关键服务失败不破坏核心业务事实。私有文件用授权 URL，上传经过多层验证。邮件与推送尊重用户偏好，AI 密钥只在后端并设置配额。

AI 可以草拟上传状态机、邮件模板字段、推送降级和外部 API 错误表，也能审查日志中的请求 ID。它不能自行批准公开 Bucket、发送营销邮件或上传用户隐私给第三方。每项数据用途与权限由人确认。

亲自使用未登录账号测试私有文件，验证过期 URL，检查退信与无效推送 Token。对 AI API 设置硬额度和服务端限流。每个外部服务都记录负责人、密钥位置、费用、数据地区、备份与退出方案。
