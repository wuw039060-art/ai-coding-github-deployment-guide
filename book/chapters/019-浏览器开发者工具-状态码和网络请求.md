# 浏览器开发者工具、状态码和网络请求

浏览器开发者工具常简称 DevTools。它能观察页面结构、样式、Console 消息、网络请求、存储与性能。对非专业开发者，最先掌握 Console 和 Network 已经能处理大量网页故障。

DevTools 显示的是当前浏览器、当前页面和当前时间发生的事。打开后没有请求，可能是页面早已加载。刷新并保留日志，才能捕获完整过程。

## 打开 DevTools

Chrome 官方文档列出菜单、右键 Inspect 和快捷键等入口。Windows 与 Linux 常用 `F12` 或 `Ctrl+Shift+I`，macOS 常用 `Command+Option+I`。系统或键盘设置可能占用快捷键，可以从浏览器菜单进入。

前置条件是使用自己的页面或有权调试的站点。DevTools 可以查看浏览器已经收到的数据，不给你服务器权限。成功结果是页面旁或独立窗口出现 Elements、Console、Sources、Network 等面板。界面会随 Chrome 版本、窗口宽度和语言变化，隐藏面板可能在更多工具菜单中。

截图时同时保留地址栏、面板名称和错误时间，遮盖账号、Cookie、Token 与个人响应。

Console 译为控制台。页面 JavaScript、浏览器和开发者输入会在这里产生消息。Chrome Console 参考说明可以按日志级别、来源与文字过滤。红色错误常包含错误类型、消息、文件和行号。点击来源可以打开对应代码。第一条错误比后续连带错误更有价值。

黄色 Warning 表示警告，可能不阻止功能。普通 Log 是代码主动打印。浏览器自身的安全提示与扩展消息也会出现。Console 不是聊天框。不要粘贴陌生网站要求的代码。它会在已登录页面权限内执行，可能读取数据或发起操作。

## 识别一个 JavaScript 错误

用户点击按钮没有反应，Console 显示 `TypeError: Cannot read properties of null`，来源 `app.js:42`。这通常表示代码期望找到一个对象，实际得到 null。先点击来源，查看第 42 行及调用栈。可能是选择器写错、元素还没创建或条件渲染改变。不要只搜索错误文字并复制第一个修复。

刷新后错误消失，可能与加载顺序有关。启用 Preserve log 观察导航前消息。重复操作记录稳定复现步骤。生产代码压缩后文件名和行号难读。Source Map 可映射回源码，是否公开要考虑源代码与安全策略。

先用 Clear 清空旧消息，再复现一次。按 Errors 过滤红色错误，输入关键文件名或文字筛选。扩展程序可能注入错误。无痕窗口或禁用扩展的测试配置可以形成对照。不要为了排错永久关闭所有安全扩展。

Console 设置可保留导航日志。多页面登录重定向时很有用。完成后恢复默认，避免下一次混入大量旧记录。Chrome 官方 Console 日志教程提供级别与过滤练习。界面标签需按当前版本复核。

## Network 记录请求

打开 Network 后刷新页面。每一行通常表示一个请求，列中有 Name、Status、Type、Initiator、Size 与 Time 等。Chrome 官方 Inspect network activity 教程通过示例观察这些信息。

红色请求常表示失败或被取消，但颜色不是唯一依据。读 Status 与 Console。状态为 `(blocked)`、`(canceled)` 或没有 HTTP 数字时，浏览器可能没有得到普通响应。选择一行后，会出现 Headers、Payload、Preview、Response、Initiator 与 Timing 等标签。具体排列随版本与请求类型变化。

Network 只记录打开面板后的活动。勾选 Preserve log 可在导航后保留，Disable cache 常只在 DevTools 打开时禁用浏览器缓存。

刷新后使用 Doc 筛选或查看 Type 为 document 的行。它代表当前页面主请求。确认 Request URL、Method 与 Status。主文档 200 而页面空白，继续看脚本、样式与 Console。主文档 404，地址或路由有问题。主文档 500，服务端生成页面失败。

发生重定向时，列表可能有多条文档请求。按时间追踪 3xx 与 Location。登录循环会出现重复地址。页面来自浏览器缓存时，Size 列可能显示 cache。需要对照时再使用 Disable cache 刷新，不作为用户长期设置。

## Headers 面板看请求目标与上下文

General 区域通常显示 Request URL、Request Method、Status Code 和 Remote Address。Request Headers 与 Response Headers 分别展示两边头部。

Request URL 应是实际 API，不应仍指 localhost 或测试域名。Method 应符合操作。Status 按第十五章分类。不要截图完整 Authorization 与 Cookie。Chrome 可能隐藏部分值，也不能依赖自动隐藏。分享前逐项检查。

Response Headers 中 Content-Type 能解释解析方式。Cache-Control、Age 与 ETag 帮助判断缓存。Access-Control 系列头与 CORS 有关。

POST、PATCH 与上传请求可能有 Payload。它可以是 Query String Parameters、Form Data、Request Payload 或文件信息。表单显示空字段，问题可能在前端收集。浏览器已发送正确字段，后端返回校验错误，则看 API 规则。

密码、Token 和个人数据会出现在 Payload。不要复制到 Issue。需要展示结构时，用无效占位符重建最小请求。上传文件失败时记录名称、类型和大小，可以换公开小样本复现。不要公开用户原文件。

## Preview 与 Response 的区别

Response 显示服务器返回的原始或格式化正文。Preview 尝试按类型友好展示，例如展开 JSON、渲染图片或 HTML。API 状态 500，Response 可能有错误代码和 Request ID。把 Request ID 提供给后端维护者，避免公开堆栈。

接口声称返回 JSON，Response 实际是 HTML 登录页，前端会 JSON 解析失败。继续查状态与重定向，可能认证失效。Chrome Network 参考说明可以在请求详情中查看响应、载荷、发起者与计时。

Initiator 可以显示 HTML 解析器、脚本文件和调用栈。图片请求由 HTML 标签发起，API 请求可能来自某个 JavaScript 函数。页面突然请求陌生域名，Initiator 帮助找到第三方脚本或浏览器扩展。来源是扩展时，文件 URL 可能带扩展标识。

广告、分析、字体和更新检查都可能产生外部请求。确认它们与隐私声明和内容安全策略一致。请求由 Service Worker 发起时，缓存和离线逻辑也要检查。

## Timing 帮助判断慢在哪里

Timing 把请求分成排队、DNS、连接、TLS、等待服务器和下载等阶段。名称与细节按 Chrome 当前参考。等待服务器时间长，可能是后端或上游处理慢。DNS 时间长，查解析与网络。下载时间长，查响应大小和带宽。

一次结果受缓存、网络和服务器负载影响。重复测量并记录环境，不根据一次毫秒数字作长期结论。后端日志耗时与浏览器 Timing 对照，能区分应用处理与网络传输。

动态页面 API 常显示为 Fetch 或 XHR。选择相应筛选，点击用户操作，再观察新请求。没有新请求，可能按钮代码没运行，先看 Console 和事件。请求出现但 4xx，检查 Payload、身份和 API。5xx 转向后端日志。

请求一直 Pending，可能服务器未响应、流式连接正常保持或网络中断。看 Type 与 Timing，不直接刷新。WebSocket 在 WS 筛选中，点开可以查看握手与 Frames。消息可能含私人数据，分享前脱敏。

## 状态码故障树

404 先看完整 URL、方法、部署路由和文件大小写。浏览器主文档 404 与 API 404 的检查位置不同。401 看认证凭据是否发送、是否过期。403 看已验证用户权限、组织策略或防火墙。429 看响应中的限流提示与客户端重试。

500 看应用运行日志。502 看代理到上游连接。503 看服务是否维护、容量或健康检查失败。504 看哪层超时。状态码只是入口，Response 和日志给出具体原因。不要让前端把所有错误改成 200，只为消除红色行。

Console 会说明哪个 Origin 请求哪个 URL，以及缺少或不符合的 CORS 头。Network 可能看到预检 OPTIONS 请求。记录前端 Origin、API URL、方法、请求头、预检状态与响应头。服务端允许准确来源和必要方法。

浏览器显示 CORS 错误时，上游也可能先返回 500，却没附 CORS 头。查服务端日志，不能只扩大允许来源。不要安装“关闭 CORS”扩展作为产品修复。它只改变自己的浏览器，用户仍失败，安全边界也被削弱。

## 导出 HAR 前先脱敏

HAR 是记录网络请求的文件，可供复现与分析。它可能包含 URL、Headers、Cookie、Payload 与 Response，风险很高。优先用最小截图和单个请求的无敏感信息。确需 HAR 时，使用测试账户与测试数据，清理凭据，放在受控渠道。

导出后打开文本检查，不只依赖工具的 Sanitized 选项。临时分享链接也要限制访问和到期。问题解决后按数据政策删除调试文件。

`blocked` 可能来自内容安全策略、混合内容、扩展、CORS 或浏览器隐私功能。`canceled` 可能是页面导航、代码主动取消或用户停止。点击请求与 Console 对照。混合内容表示 HTTPS 页面请求不安全 HTTP 资源，修复资源 URL 与服务 HTTPS，不能让用户关闭保护。

`net::ERR_NAME_NOT_RESOLVED` 指向 DNS，`ERR_CONNECTION_REFUSED` 常指目标可达但没有服务接受，具体错误以浏览器文本为准。没有 HTTP 响应时，后端访问日志也可能没有请求。按 DNS、连接、TLS 和浏览器策略继续排查。

## Application 面板只作为辅助

Application 面板可以观察 Cookie、Local Storage、IndexedDB、Cache Storage 与 Service Worker。面板名称和位置按当前 Chrome。

登录循环时查看 Cookie 是否存在和属性，不复制值。旧 PWA 问题查看 Service Worker 版本和 Cache Storage。删除站点数据会退出登录并清除草稿。先在测试账号和可恢复数据上操作。不要把 Clear site data 作为所有用户的首要建议。

Storage 显示的是当前 Origin。子域和端口不同，数据分开。确认地址栏与选择对象。

DevTools Device Toolbar 可以模拟视口、触摸和部分网络条件，适合检查响应式布局。它仍运行桌面 Chrome，不能替代真实手机浏览器。iOS Safari 的渲染、键盘、安全区域和权限要在真实设备或官方模拟器验证。Android WebView 也可能与 Chrome 不同。

网络限速模拟帮助观察加载提示，不能代表某地区真实 DNS 与丢包。记录模拟配置。最终验收至少使用一台目标手机，检查输入、滚动、旋转、深色模式和系统字体缩放。

## 重放请求会产生真实操作

DevTools 可能支持 Copy as fetch、Copy as cURL 或 Replay XHR。它们会复制或重发请求，可能创建订单、删除数据或消耗额度。只在自己的测试环境与无害 GET 上练习。复制内容先删除 Cookie、Authorization 和私人 Payload。

生产故障需要重放时，使用专门测试账号、幂等键和明确批准。不要把用户请求带到本地第三方工具。响应已返回 500，不表示重放安全。第一次请求可能已部分写入数据库。

Elements 中改文字和 CSS，只改变当前页面内存。刷新后通常消失，不会更新 GitHub 与服务器。这种临时编辑适合试颜色、隐藏元素和验证选择器。确定方案后回源码修改、测试、Commit 和部署。

Sources 的 Local Overrides 可以保存本地覆盖，可能让刷新后仍不同。排错结束时检查是否启用，避免误以为线上已更新。Console 给对象赋值也只影响当前运行状态。不能把它当成生产修复。

## Waterfall 读出请求先后

Network Waterfall 用横条显示开始、等待和完成。主 HTML 后才发现 CSS 与脚本，会形成依赖顺序。关键脚本加载后才请求 API，API 很晚开始可能来自前端初始化。API 早开始却等待很久，更像后端慢。

多个请求受浏览器连接和优先级影响，不能只按列表顺序判断。点击 Timing 看阶段。截图 Waterfall 时保留时间轴与筛选条件。缓存会显著改变结果，记录是否禁用。

Sources 可以打开脚本并设置 Breakpoint，代码运行到此暂停。适合检查变量和调用顺序。暂停会改变时间，可能导致请求超时或实时连接断开。不要在生产用户操作上长时间暂停。压缩脚本配 Source Map 更易读。第三方代码断点先确认许可证和调试权限。

结束后移除断点和异常暂停，避免下次页面看似卡住。

## Network Throttling 用于加载体验

选择较慢网络配置后刷新，可以观察骨架屏、图片延迟和超时提示。配置是模拟值，不等于某运营商；先清楚基线，再比较优化；开启缓存与禁用缓存分别测；记录浏览器版本、设备与页面版本；慢网下用户重复提交，需要按钮禁用、进度和幂等；只优化首页分数不够。

CPU Throttling 也可模拟较慢处理器，真实低端设备仍需验收。

过滤框可以按 URL、方法、状态、类型或域名缩小列表，语法按当前 Chrome 参考。先用简单文字搜索 API 路径。第三方域名请求集中失败，可能是其服务、网络阻止或内容安全策略。自己的域名正常时不重启后端。

所有请求 401，检查会话。只有一个端点 404，查部署与 API 版本。清除筛选后确认没有漏掉主文档。面板显示空白可能只是筛选条件仍在。

## 先看成功请求，再看失败请求

第一次使用 Network 面板时，单看一条失败请求很容易迷路。先在本地练习页面请求正确路径，记下请求方法、地址、状态码、响应类型和 Timing。随后把路径中的一个字符改错，再比较第二条请求。两次操作只差一个字符，Network 中的目标地址和状态码会给出清楚区别。

登录或保存功能也可以使用同样方法，但失败条件应选择测试账号的错误密码、缺少必填字段或练习环境中的无效记录，不能故意攻击生产服务。先保留成功样本，才能知道失败请求究竟少了哪个 Header、改变了哪段 Payload，或者收到怎样的 Response。只看红色文字容易被错误描述带走，对照两次请求更容易找到发生变化的边界。

对照时每次只改变一个条件。若同时清缓存、换账号、切网络和修改代码，即使问题消失，也无法知道哪个动作起作用。把浏览器版本、页面地址、操作时间和请求编号一起记下。以后让 AI 分析时，它得到的是一组可以比较的事实，而不只是“按钮没反应”的主观描述。

记录页面 URL 的脱敏形式、复现时间和时区、浏览器版本、操作步骤、Console 第一条错误和相关 Network 请求。请求项包含方法、状态、Content-Type、Request ID 与 Timing。Payload 和 Response 只保留无敏感最小字段。

形成正常对照，例如隐私窗口或另一账号。说明已尝试动作及结果。材料足够后再联系后端，避免一句“前端报错”。解决后记录修复提交和验证状态。

## WebSocket Frames 怎样观察

选择 WS 请求后，Messages 或 Frames 显示收发内容。连接握手状态 101 通常表示协议切换成功。连接成功却没更新，检查订阅消息是否发送、服务端是否确认、频道与权限。断开码和原因提供线索。

消息内容可能含聊天与 Token，截图前使用测试频道。二进制 Frame 需要协议工具解析。刷新会建立新连接，Preserve log 帮助比较旧连接。不要把多个标签页连接混为一条。

`location.href` 读取当前 URL，`navigator.userAgent` 提供客户端线索。执行读取表达式不会修改服务端。

```
location.href
```

即使只读，也只在自己有权调试的页面使用。不要运行读取 Cookie、Local Storage 或页面表单并上传的陌生代码。复制结果前遮盖查询参数。Console 历史可能保留输入，使用共享设备后清理会话。

## 截图怎样让读者看懂

界面截图只截需要的面板，同时保留面板名称、目标请求和关键列。用编号标注，不用颜色作为唯一线索。图注写操作前提、Chrome 版本和截图日期。界面变化风险高时，正文给稳定的对象名称与预期结果。

响应内容使用测试数据。URL、账号、扩展和通知先检查。模糊处理要不可恢复，优先重新制作干净截图。EPUB 提供高分辨率图片与替代文字，窄屏可以缩放。核心步骤仍在正文。

DevTools 显示本地时间，服务器日志可能 UTC。记录时区并转换。设备时间错误也会影响证书、Token 和事件顺序。Request ID 比只按时间更可靠。没有 ID 时，用路径、状态、账号测试标识和相近时间缩小。

多个请求并发，日志顺序不等于业务先后。使用客户端生成的操作 ID 或服务器事件序号。不要为了让两份日志时间一致而手工修改生产服务器时钟，服务器应使用可靠时间同步。

## 本章验收清单

能打开 Console 与 Network，刷新捕获主文档和 API。能找到 Status、Payload、Response、Initiator 与 Timing。能用第一条 Console 错误和第一个失败请求定位下一层。会识别缓存、CORS、DNS 与 5xx 的不同入口。

不在 Console 粘贴陌生代码，不公开 HAR 和凭据。DevTools 临时改动回到源码才能发布。

Network Request blocking 可以阻止匹配 URL，模拟图片、脚本或第三方 API 不可用。规则只影响当前调试浏览器。阻止分析脚本，页面核心功能应继续。阻止 API，界面应显示错误和重试。阻止字体，文字仍可读。

记录规则并在结束后关闭。遗留规则会让自己持续失败，其他用户正常。不能用本地 Blocking 证明服务器权限。它只是客户端故障模拟。

## Lighthouse 与 DevTools 指标只是线索

Lighthouse 可以审查性能、可访问性、最佳实践和 SEO，具体能力随版本。得分受设备模拟与网络影响。报告指出图片大或缺 Label，回到实际代码修复。不要为分数删除重要功能和可访问文字。

实验室指标补充真实用户监控。没有用户同意时不收集过度设备与行为数据。书中不会用单次 Lighthouse 分数宣称网站完成，关键流程还要真实验收。

## Console 安全警告要认真读

Chrome 可能阻止直接粘贴，以防 Self-XSS。不要按陌生网站指示绕过。开发者自己的调试代码也先在文本中阅读，确认只读取或作用于测试数据。高权限账号避免使用 Console 执行业务。

发现别人诱导粘贴代码，停止并检查会话与账号活动。若已经执行，保存代码与时间并联系安全负责人。登出和改密码是否足够取决于代码行为，可能还要撤销令牌与检查操作。

在自己的练习站点中，把图片路径改成不存在文件。打开 DevTools Network，清空记录并刷新。用 Img 筛选找到 404 请求。打开 Headers，确认 Request URL。Response 可能是平台 404 文本。Initiator 指向 HTML 或 CSS。

修正路径并重新部署。刷新后状态应为 200，Preview 显示图片。检查 Console 没有相关错误。记录故障现象、404 URL、来源文件、修复提交与新状态。完成后恢复练习站点。

## 常见错误

Network 空白，刷新页面并确认录制开启。状态全是 200，功能仍错，检查 Response 数据与 Console。点击错误后日志消失，开启 Preserve log 再复现。无痕窗口正常，检查扩展、缓存和本地存储。

只在本机看到错误，记录浏览器版本、账号与网络对照。不要立刻重启服务器影响所有用户。

AI 可以读取脱敏截图、请求详情和错误栈，生成故障假设与下一项检查。它也能整理 HAR，但必须使用测试数据。AI 要引用具体请求和状态，不能从红色颜色推断原因。任何建议关闭浏览器安全机制都要拒绝。

凭据、个人响应、生产操作和安全警告需要亲自处理。DevTools Console 不粘贴陌生代码，Network 资料不公开秘密。下一章会把前八章组件放进同一幅动态应用架构图，并建立从用户现象到日志位置的第一棵故障树。
