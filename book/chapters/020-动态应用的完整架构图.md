# 动态应用的完整架构图

前面分别认识了浏览器、域名、HTTP、会话、前后端、API、数据库和文件存储。动态应用把它们连在一起。用户只看到一个页面或 App，背后可能跨过十个组件。画架构图的目的，是让每个请求、数据和故障有位置。图不追求把所有供应商标志都放进去，只保留组件、边界和方向。

## 从用户动作开始画

选择一个具体动作，例如“登录后上传头像”；不要从服务器清单开始；写出用户设备、公开入口、后端、数据库和对象存储；用户输入账号，客户端 POST 登录；后端验证数据库，创建会话。用户选择图片，客户端请求上传授权，再把文件上传对象存储。后端更新数据库头像 Key。

每条箭头写协议或数据。浏览器到入口用 HTTPS，后端到数据库使用数据库连接，后端到对象存储使用服务 API。箭头没有说明权限时，图还不完整。标出匿名用户、普通用户、管理员与服务角色。

用户设备层包含浏览器或 App、本地缓存与界面。边缘入口层包含 DNS、CDN、TLS、负载均衡或反向代理。应用层包含静态前端、API、后台任务与实时服务。数据层包含数据库、对象存储、缓存和队列。外部服务层包含邮件、支付、地图、推送和 AI API。

监控与日志横跨各层。身份与秘密管理也横跨各层。它们不只是一个角落组件。小项目可以由一个平台提供多层能力，逻辑位置仍存在。Supabase 架构就把网关、PostgreSQL、Auth、Storage、Realtime 与 Functions 组合。

## 一次页面加载的数据流

1. 用户设备查询域名 DNS。
2. 浏览器连接 CDN 或平台入口并完成 TLS。
3. 请求 HTML。
4. 浏览器继续请求 CSS、JavaScript 和图片。
5. JavaScript 启动并请求 API。
6. API 验证会话。
7. 后端查询数据库。
8. 后端返回 JSON。
9. 前端更新页面。

MDN 的加载说明支持前四步，客户端与服务器实例支持动态请求部分。每一步都能单独失败。DNS 错误时没有 HTTP 状态。HTML 404 时前端不启动。脚本 200 但执行异常时 API 不发出。API 500 时静态页面仍显示。

密码从客户端通过 HTTPS 到后端。后端使用安全密码验证，不把明文存数据库。成功后创建 Session 或 Token。Cookie 设置 Secure、HttpOnly 和合适 SameSite。后续请求带会话，后端取得用户身份并检查资源权限。

身份认证回答“你是谁”，授权回答“你能做什么”。登录成功的普通用户也不能访问管理员接口。身份服务由第三方提供时，浏览器会重定向到其域名，再返回授权结果。回调 URL 与状态参数要验证。

## 文件上传流程的关键边界

客户端预览不代表服务器接受。后端验证身份、配额和元数据，生成安全对象 Key 与临时授权。客户端直接上传可以减少后端带宽。上传完成后，后端验证对象并创建记录。后台任务扫描、转码或生成缩略图。

对象存储原文件与公开缩略图可以使用不同 Bucket 和权限。数据库只保存 Key 与状态。删除用户内容时协调数据库、对象、缓存和备份保留。页面隐藏一条记录不能代表文件已从所有位置删除。

发送邮件、转码和生成 AI 摘要可能慢；API 把任务写入队列，立即返回任务 ID；工作进程从队列取得任务；任务成功后更新数据库，失败记录错误与重试；实时服务或轮询把状态告诉客户端。Web API 正常而工作进程停止时，用户能提交任务，进度永远不变。单独画出来后，排错会去队列和 Worker 日志。

队列本身也要持久化、监控和备份策略。任务可能重复，处理逻辑要幂等。

## 外部 API 是系统边界

后端调用邮件、支付或 AI 服务时，外部故障会进入自己的用户体验。设置超时、重试、限流与降级。重试适合暂时网络失败，不适合所有错误。支付请求重复可能重复扣款，使用供应商幂等机制与业务记录。

外部密钥留在后端秘密系统。供应商回调 Webhook 要验证签名、时间和重复事件。记录供应商请求 ID，发生争议时对照。日志不保存完整支付与隐私数据。

同一数据会出现在数据库、缓存、搜索索引、客户端和报表。需要指定 Source of Truth，也就是权威来源。订单状态通常以交易数据库为准。缓存可以过期重建，搜索索引用于查找，客户端只是显示副本。

多个系统都能独立改订单，会产生冲突。写操作集中经过受控服务，事件同步到其他系统。备份权威数据库后，还要保存对象存储和必要配置。可重建索引可以从数据库恢复，恢复步骤要演练。

## 环境分开但结构相似

Local、Preview、Staging 和 Production 是常见环境。Local 在开发电脑，Preview 对应分支，Staging 用于接近生产的验证，Production 服务真实用户。

环境有独立域名、数据库、密钥和存储。预览不应默认读取生产用户数据。测试邮件发到沙盒，支付使用测试模式。结构相似帮助发现差异，资源不必同规模。配置要明确来源，不能靠某个人电脑隐藏文件。

部署记录写出环境与提交。日志也带环境标签，避免在测试错误时重启生产。

数据库密码从秘密系统注入后端，只用于后端到数据库。对象存储管理密钥也留在后端。浏览器得到受限临时上传 URL。支付与 AI 密钥只沿后端到外部服务箭头使用。日志不打印。前端构建只接收公开 API 地址和公开项目标识。

Webhook Secret 用于外部服务回调验证，存后端。客户端不能取得。签名失败事件进入安全日志。在图中用不同颜色或锁标识秘密边界，并在等价文字中说明。分享图不写真实值。

## 故障域决定影响范围

Failure Domain 译为故障域，表示一个故障能同时影响哪些组件。数据库不可用会影响读写它的所有 API，静态首页仍可能打开。同一台 VPS 上运行 API、数据库和对象文件，机器故障会一起中断。拆到托管服务减少共同机器故障，也增加网络与供应商依赖。

单个外部邮件服务故障应只影响通知，不让预约事务失败。架构通过队列把两者分开。画图时圈出共同账户、地区和供应商。多个组件来自同一平台时，不要把它们误画成完全独立。

静态资源由 CDN 扩容，API 可以增加实例，数据库扩容连接与计算，队列增加 Worker。每层指标不同。API 增实例前，Session 与本地文件不能只在单机。数据库连接池总量要控制。后台任务要防止重复消费。

流量增长先测瓶颈。首页慢可能来自大图片，与数据库无关。数据库慢也可能因为缺索引，不需盲目加服务器。个人项目先保证监控、备份和可恢复，再考虑复杂自动扩容。Kubernetes 不是默认答案。

## 成本也沿组件产生

CDN 按流量或请求，应用按运行时间与资源，数据库按实例、存储和备份，对象存储还会有容量与传输，外部 API 按调用。免费额度会变化，也可能在超过后自动计费。为每个组件写账单所有者、预算提醒和关闭入口。

用户上传与 AI API 容易被滥用。认证、配额、大小限制和速率限制同时保护成本与稳定性。下线时停止计算仍可能保留数据库、快照、对象和域名费用。第六十七章给完整清单。

用户请求删除账号，后端验证身份并记录请求。事务删除或匿名化业务数据，对象存储清理文件，搜索索引与缓存同步。备份按保留政策在到期后清除。外部邮件和分析服务中的数据按各自能力处理。审计记录保留范围要符合法律与安全要求。

客户端删除本地缓存与凭据。App 卸载不能替代服务端账号删除。删除流程在测试租户演练，并生成不含私人内容的完成证据。无法立即删除的备份要向用户清楚说明。

## 责任表补充架构图

图只说明连接，责任表写谁管理。每个组件记录所有者、账号、部署方式、日志、备份、账单和下线。数据库由平台运行，项目仍负责表结构、权限和恢复验证。CDN 自动证书，项目仍负责域名续费与绑定。

外部 API 由供应商维护，项目负责密钥、用量、失败降级和用户告知。App 商店负责分发，项目负责签名与审核资料。责任没有人时标红并在上线前补齐。写“平台”仍要链接官方控制台和支持边界。

个人作品页允许短暂停机，支付与医疗系统要求更高。先定义用户可接受的中断和数据丢失，再决定冗余与恢复。RTO 表示期望恢复时间，RPO 表示可接受的数据时间损失。数值由业务承担者批准，并通过演练验证。

备份每天一次，最坏可能丢近一天数据。声称零丢失需要同步复制、事务与故障场景证据，不能口头承诺。高目标增加费用和复杂度。个人项目从可靠备份、监控和简洁架构开始。

## 单点登录扩大身份边界

使用 Google、Apple 或组织身份提供商登录，项目不直接处理密码，但依赖外部身份可用性与配置。后端验证提供商签发结果、Audience、Issuer、过期与状态。只相信客户端给出的邮箱会被伪造。

用户同一邮箱通过不同方式登录时，账号合并要明确验证，避免接管。提供备用恢复方式。提供商密钥轮换、回调域名和同意页面进入责任表。隐私政策说明数据来源。

紧急修复可能在控制台手工加变量、开端口或新建存储，图与仓库配置没有更新。时间久后没人知道来源。定期比较架构图、基础设施配置、平台资源和账单。无主资源先调查，不直接删除。生产变更通过记录与审查，完成后更新图。自动生成清单可以提供线索，人工确认业务用途。

发现漂移时先保存证据和恢复值，再把需要的配置纳入受控来源。

## 架构评审的四个用户动作

选择登录、读取、写入与删除各一个动作。沿图检查身份、权限、失败、日志与恢复。再模拟数据库不可用、对象存储拒绝、外部 API 超时和客户端离线。每种故障应有可读提示和检查入口。用普通用户、管理员和未登录者做负面测试。甲租户不能访问乙。

评审结果形成待办、负责人和验证期限，不用一句“架构合理”结束。

| 故障组件 | 仍可用 | 受影响 | 第一日志 |
| --- | --- | --- | --- |
| CDN 静态节点 | 已安装 App 本地功能 | 网页资源加载 | CDN 状态与入口日志 |
| API | 已缓存公开内容 | 登录、写入、同步 | 应用运行日志 |
| 数据库 | 静态首页 | 数据读写 | 连接与数据库日志 |
| 对象存储 | 文本数据 | 上传与图片 | 存储请求 ID |
| 邮件服务 | 核心事务 | 通知 | Worker 与供应商日志 |
| 实时服务 | 普通 API 查询 | 即时更新 | 连接与订阅日志 |

矩阵让产品决定降级。邮件失败不应阻止预约记录，数据库失败则不能假装保存成功。

## 一次数据库故障演练

在测试环境暂停数据库连接。静态首页应打开，API 健康或就绪状态按设计变化，写入返回可读错误。应用日志记录连接失败与 Request ID，不打印密码。监控告警到达负责人。恢复数据库后，连接池重新建立。

检查故障期间请求是否部分写入、队列是否堆积、用户是否重复提交。按幂等规则恢复。记录发现、响应与恢复时间。生产演练需要审批和回滚，不直接断真实数据库。

旧架构在 VPS 同时运行 API、PostgreSQL 和上传目录。迁移目标把数据库与对象存储交给托管服务，API 保留容器运行。先迁移测试数据和文件，验证权限与性能。生产切换前暂停或同步写入，复制最终增量，更新后端变量。

DNS 不一定变化，用户仍访问同一 API。应用内部箭头改变。回滚需要旧数据库保持只读或可恢复。完成后删除 VPS 数据前确认备份、保留和账单。架构图与责任表同步更新。

## 监控从用户入口开始

外部探针请求公开 HTTPS 地址，覆盖 DNS、证书、入口和应用。内部健康指标补充数据库与队列。只监控服务器 CPU 会漏掉域名过期。只监控首页会漏掉登录和后台任务。选择少量关键用户流程。

告警要有负责人、严重度和静默规则。频繁误报会被忽略。维护窗口明确标记。监控本身也会故障，定期测试告警通道。费用与隐私进入责任表。

## 本章验收清单

能从一个用户动作画出设备、入口、应用、数据和外部服务。每条箭头有协议、权限与日志。能从“打不开”“操作失败”“任务卡住”进入不同故障树。知道静态首页正常不能证明后端正常；图有日期、环境和待验证项；责任表覆盖账号、备份、费用与下线；实际控制台证据优先于源码推测。

新增文件上传，需要在图中加入对象存储、上传授权和后台扫描。责任表加入 Bucket、费用、备份和删除。新增登录，加入身份提供商、Cookie 或 Token、回调和会话存储。故障树加入 401、403 与回调失败。

新增 AI 摘要，加入外部 API、队列、用量限制和降级。密钥只在后端，客户端得到任务状态。每次架构变化关联 Pull Request 与部署版本。图作为交付物更新，不等季度复盘才补。

状态页显示数据库平台故障时，先验证自己的项目是否受影响。记录地区、组件和错误，不直接把全部责任推给供应商。用户公告写受影响功能、开始时间、当前措施和下次更新时间，不泄露内部安全细节。

服务恢复后验证积压任务、数据完整性和重复请求。供应商显示 Resolved 不等于自己的应用完全恢复。复盘评估超时、降级、备份和替代路线。是否多供应商要结合成本和复杂度。

## 日志与指标的最小集合

入口记录请求数、状态与耗时；应用记录错误、版本和 Request ID；数据库记录连接与慢查询；队列记录积压与失败；指标有告警阈值和负责人；日志保留时间按调查与隐私；Trace 可跨服务关联，成本也要控制。

不要记录密码、Token、完整请求正文和用户文件。调试开关有到期，结束后关闭详细敏感日志。监控面板链接进入运维手册，权限最小化。

把架构图打印或显示在大屏，从域名开始逐项指出控制台与日志。随机选择一个组件假设失败。参与者说明用户现象、告警、第一检查、回滚与负责人。找不到的入口记录为缺口。使用测试环境和无敏感数据。演练后修正文档并复测，不在生产临时尝试破坏。

完成标准是新人也能沿图找到证据，不能只由原作者口头解释。

## 多租户应用的权限线

SaaS 可能让多个组织共用数据库。每条记录带 Tenant ID，也就是租户标识。服务端从用户会话得到租户，不信任客户端直接传入。数据库查询、对象 Key、缓存键和实时频道都要隔离租户。漏一层就可能串数据。

管理员权限也分平台管理员与组织管理员。组织管理员只能管理自己的组织。用两个测试租户做负面测试。甲不能读乙数据，即使修改 URL、请求正文和对象地址。

浏览器 Console 记录脚本，Network 记录请求。CDN 与代理记录入口和上游；应用日志记录业务与异常；数据库日志记录连接和查询；工作进程记录任务；Request ID 从入口传到应用和任务，帮助关联；用户提供时间、账号的非敏感标识和操作。

日志集中存储便于搜索，也扩大敏感范围。最小记录、访问控制、保留和脱敏都需要设计。前端错误监控可以上报调用栈，Source Map 与用户信息要按隐私控制。

## 第一棵跨层故障树

用户说“网站打不开”；先问是否能解析域名；不能解析，查 DNS；能解析但 TLS 警告，查证书与域名；连接成功后看主文档状态；404 查路由与部署，5xx 查入口与应用；文档 200 但空白，查脚本请求与 Console。

页面显示但操作失败，查对应 API。4xx 查请求、认证和权限，5xx 查运行日志。API 正常但数据错，查数据库、缓存和业务规则。上传或后台任务卡住，查对象存储、队列和 Worker。只有单个用户失败，比较账号、客户端版本和本地状态。

登录按钮一直转圈。原因一是 JavaScript 异常，Network 没有请求。原因二是 API 504，后端调用身份服务超时。原因三是 API 200，但 Cookie 未保存，随后账户接口 401。

界面现象一样，证据不同。先看 Console 和 Network，再进入对应日志。图片不显示也可能是前端路径 404、对象权限 403、CDN 缓存旧错误或图片内容损坏。Preview 与 Response 能进一步区分。

架构图把候选位置列全，排错用证据逐步排除。

## 架构图要记录版本与事实边界

图中平台名称、域名和连接随项目变化。每幅图写明更新时间、适用环境和来源。推测连接用虚线或标为待确认。不要从 README 推断生产完全相同。读取部署配置、控制台与实际日志。无法访问数据库时，标记未验证。

图中不放秘密、完整内部 IP 和个人数据。共享给外部时简化安全敏感拓扑。重大改动后更新图。过时图比没有图更容易误导。

静态前端在 CDN。API 与工作进程运行在托管后端。PostgreSQL 保存用户与预约，对象存储保存商家图片，邮件服务发送确认。用户提交时间，API 在事务中检查并创建预约。数据库唯一约束阻止同一时段重复。API 返回预约编号，同时写邮件任务。

Worker 发送邮件并更新状态。失败后重试，用户页面仍能从数据库看预约成功。邮件失败不回滚已确认预约。管理员 App 使用相同 API，不直接连接数据库。权限检查确保商家只能查看自己的预约。

## 一个 Flutter App 总例子

Flutter 客户端安装在 Android 与 iOS，保存少量本地设置。登录、同步和文件都经过 HTTPS 后端。Flutter 架构最终编译到目标平台运行。App 启动先读取本地缓存，随后 API 更新。离线时显示上次同步时间，不把旧数据冒充最新。

推送通知只携带事件标识，App 打开后按权限从 API 取得详情。通知文本不包含高敏感内容。旧 App 版本与新 API 保持兼容。后端停机时，离线功能仍可用，在线操作给出明确错误。

选择一个项目，先写一个用户动作。列出设备、域名入口、前端、API、数据库、文件存储与外部服务。没有的写“无”。画箭头并标协议与数据。给每个组件写日志入口、数据负责人、备份方式与版本。

用一个成功流程沿图走一遍，再用一个失败流程指出第一个可见证据。无法确认的位置写“待验证”。成功结果由可用性判断。另一个人应能根据图找到日志和数据位置。

## 让 AI 修改架构图时先核数据流

AI 可以读取项目与部署配置生成候选架构图，整理请求和故障树。要求它引用具体文件和控制台证据。AI 无法从源码确认生产账号、真实 DNS、数据库备份和商店版本。未知项保留，不填成事实。

生产域名、数据位置、权限、秘密、付费和恢复责任必须亲自确认。图中每条高风险箭头都要有实际验证。第三卷到这里结束。第四卷会从源代码、依赖、运行时和构建开始，把网页从仓库交给部署平台。
