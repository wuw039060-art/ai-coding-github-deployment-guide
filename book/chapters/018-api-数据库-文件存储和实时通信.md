# API、数据库、文件存储和实时通信

动态应用要让多个组件合作。前端通过 API 请求后端，后端读写数据库，把大文件放进对象存储。需要即时更新时，客户端与服务器还会保持实时连接。这些组件可以由一个平台提供，也可以来自多家公司。先明确数据与权限怎样移动，再选择工具。

## API 是程序之间约定的入口

API 是 Application Programming Interface 的缩写，中文常译为应用程序接口。在 Web 项目中，API 常表现为一组 HTTP 地址、方法、请求字段和响应结构。例如 `GET /api/tasks` 取得任务列表，`POST /api/tasks` 创建任务。客户端不需要知道数据库表怎样存，只要按接口约定请求。

API 文档应说明认证、字段、状态、分页、错误和限流。没有文档时，前端与后端容易各自猜测。公开 API 也需要权限与用量限制。地址能被看到不代表任何人可以无限调用。

REST 使用资源与 HTTP 方法组织接口。`/users/42/orders` 可以表示某用户订单集合。GET 读取，POST 创建，PATCH 更新，DELETE 删除。项目未必严格遵守全部 REST 约束。理解资源、方法、状态与无状态请求已经足够阅读多数接口。

RPC 风格会用 `/generate-report` 一类动作地址。GraphQL 使用查询语言从一个入口请求所需字段。选择影响文档、缓存、权限和客户端工具。本书不要求同时学习多种 API 技术。案例以普通 HTTP JSON 为主，遇到项目现有方案再按官方文档理解。

## JSON 是常见数据格式

```
{
  "id": 42,
  "title": "检查部署日志",
  "done": false
}
```

JSON 用对象、数组、字符串、数字、布尔值和 null 表示数据。字段名和字符串用双引号。它不支持注释。服务端返回 Content-Type `application/json`。客户端解析前检查状态。服务器错误返回 HTML 时，直接按 JSON 解析会出现“Unexpected token”一类错误。

JSON 中日期常用带时区的标准字符串。金额不要直接依赖浮点误差，业务接口可使用最小货币单位或精确十进制约定。

数据库保存用户、订单、文章和关系。关系数据库使用表、行、列、约束与 SQL。PostgreSQL 是常见开源关系数据库，官方教程覆盖创建、查询、更新和事务。SQLite 把数据库引擎嵌入应用，数据通常保存在本机文件中。它能支撑本地 App、小工具、测试和不少网站，判断时要看运行拓扑与写入方式。多台应用主机需要共同写库、客户端需要远程连接，或写事务经常重叠时，PostgreSQL 这类客户端服务器数据库通常更合适。SQLite 仍可同时服务许多读取，一次只允许一个写事务，WAL 模式可以让读取与写入并行，但数据库相关进程必须位于同一台主机。

NoSQL 是一组非关系模型的统称，包括文档、键值、列和图等。它们解决不同问题。不要把 NoSQL 理解为“不需要结构”。个人项目若数据关系清楚，PostgreSQL 或 SQLite 往往足够。第三十一章会比较选择。

## 数据库约束保护最终规则

后端检查邮箱是否重复，两次并发请求仍可能同时通过检查。数据库对邮箱加唯一约束，最终阻止重复写入。外键保证订单引用存在用户。非空约束要求字段有值。检查约束限制合理范围。应用验证提供友好错误，数据库约束承担最终完整性。

事务把一组操作作为整体。例如创建订单、扣减库存和记录付款状态。中途失败时回滚，避免只完成一半。约束错误要转换成稳定 API 响应，不把数据库内部细节直接返回。

后端使用数据库凭据连接，验证请求后执行允许操作。数据库端口通常位于私有网络或仅本机可达。把 PostgreSQL 端口开放公网并使用简单密码，会扩大攻击面。云安全组和防火墙都应限制来源，数据库自身还要认证与 TLS。

托管后端服务可以给浏览器提供受限数据 API。安全依赖服务端权限策略。高权限管理接口仍留在后端。数据库控制台能查询数据，不说明 App 权限正确。要用普通测试账户验证真实 API。

## 对象存储保存大文件

头像、附件、音频和视频通常放进 Object Storage，也就是对象存储。数据库保存对象 Key、所有者、类型、大小与状态。对象存储通过 Bucket 组织，文件用 Key 定位。它看起来像目录，实际语义由平台决定。重命名常等于复制新对象再删除旧对象。

公开 Bucket 允许任何人按 URL 读取，适合明确公开资产。用户私人文件需要私有 Bucket 和受控下载。临时签名 URL 可以在有限时间授权上传或下载。有效期、操作和对象要限制，URL 本身在有效期内属于秘密。

前端限制文件类型和大小，为用户提供即时反馈；攻击者可以绕过，后端或存储策略还要检查；文件名由用户提供，不能直接当服务器路径；生成安全 Key，另存显示名称；防止 `../` 路径穿越和同名覆盖。扩展名、Content-Type 与真实内容可能不一致。需要验证文件签名、解码能力或安全扫描。图片重新编码可以减少部分恶意内容，仍要限制资源消耗。

上传成功后进入处理中状态。缩略图、转码和病毒扫描可由后台任务完成。处理失败要清理或隔离原文件。

## 为什么不把文件全放数据库

数据库可以存二进制，但大文件会影响备份、查询和迁移。对象存储为大文件传输、分片与 CDN 集成设计。小型 SQLite App 把少量图片放数据库可能简化备份。大型 Web 服务更常分开。没有绝对规则，要看大小、访问、事务与恢复。

分开后会出现一致性问题。数据库记录创建，文件上传失败，会留下空记录。文件成功，数据库写入失败，会留下孤儿对象。可以使用待处理状态、幂等任务和定期清理。删除用户时也要协调记录与对象，并遵守保留政策。

实时功能让聊天消息、协作编辑和任务状态较快出现在客户端。常见方式包括轮询、Server-Sent Events 和 WebSocket。轮询每隔一段时间请求，简单但有延迟与重复流量。长轮询让服务器等待结果。SSE 允许服务器在一个 HTTP 连接上向客户端发送事件，方向主要从服务端到客户端。

WebSocket 建立双向连接，客户端和服务器可以随时发送消息。MDN WebSocket 参考说明浏览器 API 能创建、管理连接并收发数据。实时不是绝对零延迟。网络、后台限制、服务器负载和重连都会影响。

## WebSocket 连接的生命周期

客户端使用 `ws` 或加密的 `wss` URL 建立连接。完成握手后发送消息帧。连接可能因网络切换、服务器重启或代理超时断开。客户端监听 open、message、error 与 close。断线后使用退避重连，避免所有用户同时快速重试压垮服务。

重连后要恢复身份与订阅，并取得断线期间遗漏的数据。单靠实时消息不能保证完整历史。MDN 的 WebSocket 客户端教程提供发送 ping 与接收 pong 的练习。生产系统还需认证、协议版本和流量控制。

连接建立时验证用户，订阅频道时再次检查权限；用户不能只靠知道房间 ID 就订阅别人消息；权限可能在连接期间变化；用户被移出项目后，服务器应停止推送并使订阅失效；消息内容同样验证；客户端发来的“我是管理员”不产生权限；服务端从已验证身份决定发送者。

日志不记录完整私人消息。保留消息 ID、频道、时间和错误足以排查多数问题。

## 消息顺序、重复与遗漏

网络重连可能让消息重复或乱序。每条业务消息可以有唯一 ID、服务器时间或序列号。客户端按协议去重与排序。“发送成功”可能只表示客户端写入连接，不表示服务器保存。聊天 App 通常显示发送中、已送达或失败等状态。

关键数据先写数据库，再广播事件。新客户端从数据库取得当前状态，实时通道只负责后续变化。协作编辑需要更复杂冲突算法，不靠最后一条消息简单覆盖。本书只建立位置认识。

Supabase 架构包含 PostgreSQL、Auth、Storage、Realtime、Functions 与 API 网关等组件。一个项目可以通过同一平台使用数据库、认证和存储。

Firebase 提供另一套托管后端产品，数据模型与服务组合不同。第三十四章会比较。组合平台减少安装与运维，仍要配置权限、数据模型、备份、地区和费用。默认示例不能直接成为生产安全策略。

Supabase Getting Started 为不同前端与 Flutter 提供快速入口。快速开始证明连接路径，不覆盖生产恢复与安全。

## 一个头像上传流程

用户在 App 选择图片。客户端检查尺寸并显示预览，向后端请求上传授权。后端验证身份，生成只允许特定 Key 的临时上传 URL。客户端直接上传对象存储。完成后通知后端，后端验证对象存在与类型，更新数据库头像记录。后台任务生成缩略图。

数据库保存对象 Key，不保存临时签名 URL。展示时后端生成受限读取地址，或公开头像直接使用 CDN URL。任何步骤失败都有状态。上传中断可以重试，数据库更新失败要清理孤儿，处理失败保留默认头像。

用户提交视频转码。API 创建任务记录并返回任务 ID。后台工作进程读取任务，更新进度。实时服务把变化推给客户端。客户端断线后重新连接，先 GET 当前任务状态，再订阅后续事件。这样不会依赖断线期间每条消息。

工作进程失败时写错误码，API 允许安全重试。重复点击使用同一幂等键，避免生成多个收费任务。文件产物放对象存储，数据库只保存位置与元数据。任务日志记录处理版本和耗时。

## API 版本与客户端兼容

移动 App 不能强制所有用户同时升级。API 新增字段通常向后兼容，删除或改类型会让旧客户端失败。可以在 URL、Header 或协议中表示版本。维护者要记录支持期限、最低 App 版本和迁移。

服务端先支持新旧格式，发布新客户端，等待采用，再移除旧接口。紧急安全问题可以要求升级，仍要给用户清楚提示。Web 前端更新较快，也可能有缓存旧版本。后端同样保留短期兼容，避免部署瞬间混用失败。

订单、日志和消息会持续增长。API 一次返回全部内容会增加数据库、网络和客户端内存压力。Offset pagination 使用页码与偏移，简单但数据插入时可能重复或跳过。Cursor pagination 使用稳定排序位置，适合连续列表。项目选择一种并写清排序。

响应包含下一页指示。客户端到末尾停止请求。每页大小有上限，不能由用户传入任意巨大数值。权限过滤要在分页前正确应用。先取全表再在前端隐藏会泄露数据。

## 搜索与数据库查询的边界

小数据可以用数据库索引与全文能力。复杂搜索可能使用独立搜索服务。搜索索引是数据库派生副本，不是唯一权威来源。数据库更新后，索引同步可能延迟。用户刚改标题，详情页已新，搜索仍旧。界面可以说明同步状态。

重建索引需要可重复流程。删除数据时也从索引清理，避免搜索结果继续暴露。搜索查询要限制复杂度和长度，防止资源耗尽。用户输入不直接拼进 SQL。

每个请求新建数据库连接成本高，应用常使用连接池复用有限连接。连接池大小要与数据库和应用实例数协调。平台扩到十个实例，每个实例开二十连接，总量可能超过数据库上限。用户看到间歇 500，日志显示连接不可用。

使用托管平台推荐的池化入口，设置查询超时并释放连接。长事务会占用资源，网络请求不应在事务中无限等待。监控活跃、空闲与等待连接。只提高上限可能把压力移到数据库。

## 缓存与数据库一致性

API 先查缓存，没有再查数据库并写缓存。更新数据库后要删除或更新对应缓存，否则用户看到旧值。Cache Aside 是常见模式，仍有并发窗口。重要余额与库存不从陈旧缓存作最终扣减判断。

缓存丢失时系统应从权威数据库恢复，性能会短时下降。大量键同时过期可能造成缓存雪崩，需要分散过期与限流。缓存内容也按租户和权限隔离。Key 漏 Tenant ID 会串数据。

上传对象后立即读取行为由平台保证决定。应用需要处理暂时不可见或处理未完成。生命周期规则可以把旧版本转低成本层或删除临时文件。规则是自动删除，配置前用测试 Bucket 和明确前缀。对象版本控制能恢复覆盖或删除，增加存储费用。是否启用与保留多久按数据价值。

数据库删除记录后，对象生命周期清理要有审计。先标记待删，确认保留期，再清除。

## Webhook 让外部服务回调

支付或邮件平台在事件发生后向你的 HTTPS Endpoint 发送 Webhook。它是外部服务作为客户端调用你的后端。服务端验证签名、时间与事件 ID。重复事件要幂等。先快速确认接收，再把慢处理交队列。

不能只按来源 IP 信任，平台地址可能变化。签名秘密保存在后端，并按官方流程轮换。本地开发可用受控转发工具测试，不公开无认证调试端口。生产日志记录事件 ID，不打印敏感正文。

支付平台因首次响应超时重试同一付款事件。后端若每次都发放权益，用户得到两份。数据库对供应商事件 ID 建唯一约束。第一次处理写入，第二次识别已完成并返回成功，不重复业务。接口先保存事件再异步处理，快速响应平台。处理失败由内部队列重试，不依赖供应商无限重发。

核对账单与本地订单，保留供应商请求 ID。不要用删除重复记录掩盖已发放权益。

## API 限流保护稳定与费用

Rate Limit 译为速率限制。可以按用户、IP、令牌或资源限制一定时间内请求。登录、上传和 AI 调用需要不同策略。超过限制返回 429，并给出可理解提示与合理重试信息。客户端指数退避，不每毫秒重试。

IP 可能多人共享，不能作为唯一账户限制。攻击者也会更换 IP。认证额度与全局保护组合。限流存储在多实例间共享，时钟与窗口算法要一致。监控误伤和绕过。

新版本要把 `full_name` 拆成两个字段。先添加新字段并允许旧字段，后端同时读写。迁移已有数据，再发布新客户端。确认旧客户端使用量下降后，停止旧字段写入。最后在备份和验证后删除。一步直接改名会让旧 App 失败。

迁移脚本进入 Git 版本，运行环境和结果记录。生产执行前在脱敏副本测试耗时与锁影响。失败时按设计回滚或向前修复，不手工随意改生产表。

## 通知与实时消息不是同一通道

WebSocket 适合 App 正在前台连接时更新。推送通知通过操作系统平台在 App 不活跃时提醒。通知可能延迟、折叠或被用户关闭，不能作为唯一业务记录。App 打开后从 API 取得当前状态。

通知正文避免敏感内容。设备 Token 属于可识别凭据，和用户、设备与注销状态关联。用户退出账号后撤销关联，避免下一位设备使用者收到旧账号通知。

用户导出数据可能生成大文件，使用后台任务与短期下载 URL。文件加密和访问按敏感性；导入前验证格式、大小、所有者和重复规则；先预览影响，再执行；失败不留下半套数据；CSV 会有编码、公式注入与日期格式问题；公开表格前处理以 `=` 等字符开头的危险单元格。

导入日志记录行号和错误，不回显敏感整行。原文件按保留规则删除。

## 数据库备份不包含所有组件

PostgreSQL 备份不包含对象存储文件、外部邮件、身份提供商配置和前端静态资源。完整恢复要列全部组件。对象存储版本与生命周期单独备份。秘密不能简单塞入数据库备份，应有恢复流程。

恢复到测试环境后，API 使用测试域名与禁用外部通知，避免向真实用户发邮件。校验记录数、关键查询、文件引用和权限。备份完成提示没有替代恢复结果。

订单写入数据库成功，向队列发消息失败，会漏掉邮件任务。Outbox Pattern 在同一数据库事务中写订单和待发送事件。独立发布器读取 Outbox 并发到队列，成功后标记。重复发布由事件 ID 和消费者幂等处理。

它增加表与 Worker，只有确实需要可靠事件时使用。小项目也可以用数据库任务表实现简单版本。监控未发送数量和最老事件。清理已完成记录要保留审计需要。

## 离线同步的冲突

App 离线修改笔记，另一设备同时修改。重新联网时不能只按设备本地时间覆盖。简单产品可以使用版本号和“检测冲突后让用户选择”。协作编辑需要更复杂算法。每次写入带当前版本。服务端发现版本过旧返回 409 与最新内容，客户端合并或提示。

删除也要同步 Tombstone，也就是删除标记，避免离线旧副本把数据复活。保留期与隐私删除协调。

邮件 API 接受请求只说明供应商接收，最终可能退信、进垃圾箱或延迟。保存供应商消息 ID 和投递事件。模板变量转义，避免用户内容注入 HTML。退订与事务邮件按适用规则分类。域名 SPF、DKIM 与 DMARC 配置影响信誉。使用邮件商官方验证，不从旧博客复制值。

测试环境只发到允许列表或沙盒，防止导入生产数据后误发。

## 数据保留与软删除

Soft Delete 用删除时间标记记录，允许短期恢复。查询必须默认排除，权限仍保护内容。保留期结束后硬删除数据库、对象和派生索引。备份按政策过期。法律保留可能暂停删除，需要明确授权。

软删除不是隐私删除完成。用户界面应说明恢复窗口与最终处理。管理员恢复有审计，避免普通用户恢复别人的数据。

## 本章验收清单

能画出客户端、API、数据库、对象存储、队列与实时通道。知道大文件和结构化数据为何分开。能解释事务、唯一约束、幂等和重连补状态。API 不直接信任客户端 ID。备份覆盖全部数据组件，恢复使用测试环境。对象、Webhook 与实时消息都有权限和日志。

把用户输入直接拼进 SQL，攻击者可以改变查询结构；使用参数化查询或成熟 ORM，不手工转义；数据库账户使用最小权限；只读报表不拥有删除表权限；应用连接不使用超级用户；输入验证改善业务，不能替代参数化；即使字段只允许数字，也由数据库驱动绑定参数。

错误不把 SQL 与连接信息返回。安全测试在授权环境使用测试数据。

API Schema 可以描述路径、字段、类型、错误和认证。OpenAPI 是常见 HTTP API 描述格式。从 Schema 生成文档与客户端能减少手写差异。生成结果仍需审查业务含义和权限。数据库 Schema 记录表、列、约束与关系，迁移是变化历史。两者不要混为一份。

发布前做兼容检查。删除字段、收紧类型和改变必填属于高风险变化。

## 软实时与严格实时的取舍

天气、统计和任务列表允许几秒延迟，可以轮询或缓存。协作光标需要更快连接，但也不等于事务最终状态。先定义用户可感知延迟与漏消息后果。轮询简单可靠时，不必加入 WebSocket。实时基础设施增加连接数、重连、订阅权限和监控。移动后台还会断开。

数据库仍保存权威状态。实时层可以重建，不单独承担不可丢业务。

删除请求验证身份、资源归属和当前状态。重要对象可以软删除并提供恢复窗口。批量删除先预览数量与筛选条件，限制上限，记录审计。后台执行大删除并提供任务状态。客户端重复请求保持幂等。资源已经删除可以返回合适成功或 404，按 API 约定。

对象存储、缓存、索引和外部副本进入同一删除工作流。

## 常见错误

API 404，检查基址、路径与部署路由。返回 HTML 却按 JSON 解析，先看 Content-Type 与状态。数据库连接超时，查网络、凭据与连接数。上传成功却无法打开，查对象权限、Key、Content-Type 和签名 URL 有效期。不要把 Bucket 全部设公开作为修复。

实时连接反复断开，查认证、代理超时、网络和心跳。重连成功但少消息，检查是否有状态补取。

AI 可以从接口文档生成请求示例，解释数据库关系、设计上传状态和实时重连测试。它也能分析脱敏日志中的请求 ID。不要给 AI 生产数据库密码、签名 URL 和用户文件。生成的权限策略必须用多个角色测试。

数据库权限、对象公开范围、用户数据、删除与备份需要亲自确认。实时功能也不能绕过服务端认证。下一章会把浏览器 DevTools 用作观察窗口，查看 Console、Network、状态码和 Response。
