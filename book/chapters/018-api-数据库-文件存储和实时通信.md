# API、数据库、文件存储和实时通信

动态应用不是只有一个网页。前端通过 API 请求后端，后端读写数据库，把大文件放进对象存储，把慢任务交给队列；需要即时更新时，客户端和服务器还会保持实时连接。这些能力可以由一个平台提供，也可以来自多家公司。先明确数据和权限怎样移动，再选择工具。

## API 是受控入口

API 是 Application Programming Interface 的缩写，中文常译为应用程序接口。在 Web 项目中，它常表现为一组 HTTP 地址、方法、请求字段和响应结构。例如 `GET /api/tasks` 取得任务列表，`POST /api/tasks` 创建任务。客户端不需要知道数据库表怎样存，只要按接口约定请求。

API 文档应说明认证、字段、状态码、分页、错误和限流。没有文档时，前端和后端容易各自猜测。地址能被看到不代表任何人可以无限调用。公开 API 也要认证、授权、速率限制和稳定错误结构。

REST 使用资源和 HTTP 方法组织接口。`/users/42/orders` 可以表示订单集合。RPC 风格会用 `/generate-report` 一类动作地址。GraphQL 使用查询语言从一个入口请求所需字段。选择会影响文档、缓存、权限和客户端工具。本书案例以普通 HTTP JSON 为主，遇到项目现有方案再按官方文档理解。

JSON 是常见响应格式。

```json
{
  "id": 42,
  "title": "检查部署日志",
  "done": false
}
```

客户端解析前先检查状态和 Content-Type。服务器错误返回 HTML 时，直接按 JSON 解析会出现“Unexpected token”一类错误。日期、金额、分页和空值要有约定，不能让每个客户端猜。

## 数据库保存权威结构化数据

数据库保存用户、订单、文章、权限和关系。关系数据库使用表、行、列、约束和 SQL。PostgreSQL 是常见开源关系数据库；SQLite 把数据库引擎嵌入应用，常用于本地 App、小工具、测试和一些小型网站。NoSQL 是一组非关系模型的统称，并不表示“不需要结构”。

个人项目若数据关系清楚，PostgreSQL 或 SQLite 往往足够。是否选择托管数据库、后端即服务或自己运维，要看运行拓扑、备份、权限、成本和团队能力。具体查询、迁移和备份流程放在 [后端和数据库参考](../../references/backend-database.md)。

数据库约束保护最终规则。后端检查邮箱是否重复，两次并发请求仍可能同时通过；数据库唯一约束最终阻止重复写入。外键保证订单引用存在用户，非空约束要求字段有值，检查约束限制合理范围。应用验证提供友好错误，数据库约束承担最终完整性。

数据库事务把一组数据库操作作为整体。例如在同一事务中创建订单、扣减库存和记录付款状态。中途失败时回滚，避免这些写入只完成一半。数据库回滚不会撤销已经发生的外部扣款、邮件发送或对象上传；跨系统步骤还需要幂等、补偿和对账。约束错误要转换成稳定 API 响应，不把数据库内部路径和 SQL 堆栈直接返回给用户。

数据库端口通常不直接暴露公网。后端使用受限数据库账号连接，验证请求后执行允许操作。云安全组、防火墙、数据库认证和 TLS 都属于边界。控制台能查数据，不说明 App 权限正确；要用普通测试账户验证真实 API。

## 对象存储保存大文件

头像、附件、音频和视频通常放进 Object Storage，也就是对象存储。数据库保存对象 Key、所有者、类型、大小和状态。对象存储通过 Bucket 组织，文件用 Key 定位。它看起来像目录，但实际语义由平台决定；重命名常等于复制新对象再删除旧对象。

公开 Bucket 适合明确公开资产。用户私人文件需要私有 Bucket 和受控下载。临时签名 URL 可以在有限时间授权上传或下载，有效期、操作和对象范围要限制。URL 本身在有效期内属于秘密，不应进入公开日志。

前端限制文件类型和大小，为用户提供即时反馈；攻击者可以绕过，后端或存储策略还要检查。文件名由用户提供，不能直接当服务器路径；生成安全 Key，另存显示名称；防止路径穿越和同名覆盖。扩展名、Content-Type 和真实内容可能不一致，敏感项目还需要扫描或重新编码。

数据库和对象存储分开后会有一致性问题。数据库记录创建，文件上传失败，会留下空记录；文件成功，数据库写入失败，会留下孤儿对象。可以使用待处理状态、幂等任务和定期清理。删除用户内容时，也要协调数据库、对象、缓存、索引和备份保留。

## 实时连接通知变化，不替代数据库

实时功能让聊天消息、协作编辑和任务状态较快出现在客户端。常见方式包括轮询、Server-Sent Events 和 WebSocket。轮询简单但有延迟和重复流量；SSE 主要从服务端向客户端发送事件；WebSocket 建立双向连接，客户端和服务器可以随时发送消息。

实时不是绝对零延迟。网络切换、浏览器后台限制、代理超时、服务器重启和重连都会影响。客户端监听连接打开、消息、错误和关闭。断线后使用退避重连，避免所有用户同时快速重试压垮服务。

关键边界在状态归属。数据库保存权威状态，实时通道只通知变化。客户端需要把当前状态与后续事件接起来，不能简单地读取状态后再开始订阅，否则两步之间的变化可能漏掉。一种做法是先建立订阅并暂存事件，再读取带版本或游标的状态，按协议合并之后的事件；支持事件重放的服务也可以从已确认游标续接。断线重连后同样要补取遗漏状态。单靠实时消息不能保证完整历史。消息可能重复、乱序或遗漏，每条业务消息应有 ID，并按协议用序列号或版本去重与排序，时间戳本身未必足以确定顺序。

连接建立时验证用户，订阅频道时再次检查权限。用户不能只靠知道房间 ID 就订阅别人消息。权限在连接期间变化时，服务器应停止推送并使订阅失效。客户端发来的“我是管理员”不产生权限，服务端从已验证身份决定发送者。

## 队列和工作进程处理慢任务

发送邮件、转码、生成缩略图、调用 AI 摘要和导出大文件可能很慢。API 不应让用户一直等到所有步骤完成。常见做法是把任务写入队列或任务表，立即返回任务 ID。工作进程读取任务，执行后更新数据库状态。前端通过轮询或实时通道显示进度。

Web API 正常而工作进程停止时，用户能提交任务，进度却永远不变。画架构图时把 Worker 单独画出来，排错才会去看队列和任务日志。任务可能重复投递，处理逻辑要幂等。重复点击提交，也要避免生成多个收费任务。

一个视频转码流程可以这样拆。API 创建任务记录并返回 ID；Worker 读取任务，调用转码服务；产物放对象存储；数据库记录产物 Key 和状态；实时服务把完成事件推给客户端。客户端断线后重新打开，按前述版本或游标方案衔接 GET 状态与订阅，并在必要时轮询确认任务最终结果。这样不依赖断线期间每条消息都被收到。

队列本身也需要监控。积压数量、最老任务、失败次数和重试结果都是指标。清理已完成任务要保留必要审计，不让表无限增长。

## Webhook 是外部服务回调你的后端

支付、邮件、身份和代码托管平台常在事件发生后向你的 HTTPS Endpoint 发送 Webhook。此时外部服务是客户端，你的后端是服务器。后端要验证签名、时间和事件 ID，不能只因为请求来自某个 URL 就信任。

Webhook 可能重复发送。支付平台因首次响应超时重试同一付款事件，如果后端每次都发放权益，用户会得到两份。数据库对供应商事件 ID 建唯一约束，第一次处理写入，第二次识别已完成并返回成功，不重复业务。

Webhook 入口应先验证请求，再把事件可靠写入任务表或持久队列，然后尽快确认接收，把慢处理交给工作进程。不能先返回成功、再仅靠内存启动任务，否则进程退出时可能丢失已经确认的事件。日志记录事件 ID、供应商请求 ID、结果和耗时，不打印完整支付正文和秘密。签名 Secret 保存在后端，并按官方流程轮换。本地测试使用受控转发工具，不公开无认证调试端口。

外部 API 调用也要设计超时、重试和降级。邮件服务失败不应让已经创建成功的预约回滚；支付扣款和权益发放则需要更严格的幂等和对账。外部密钥留在后端秘密系统，客户端只看到任务状态或公开标识。

## 版本、分页和兼容

移动 App、小程序和缓存中的 Web 前端不能保证同时升级。API 新增字段通常向后兼容，删除字段、改类型和改变必填更危险。可以在 URL、Header 或协议中表示版本。服务端先支持新旧格式，发布新客户端，等待采用，再移除旧接口。

订单、日志和消息会持续增长。API 一次返回全部内容会增加数据库、网络和客户端内存压力。Offset pagination 使用页码和偏移，简单但数据插入时可能重复或跳过；Cursor pagination 使用稳定排序位置，适合连续列表。每页大小要有上限，权限过滤要在分页前正确应用，不能先取全表再在前端隐藏。

API 限流保护稳定和费用。可以按用户、IP、令牌或资源限制一定时间内请求。登录、上传和 AI 调用需要不同策略。超过限制返回 429，并给出可理解提示。客户端指数退避，不每毫秒重试。IP 可能多人共享，不能作为唯一账户限制。

## 备份要覆盖所有数据组件

数据库备份不包含对象存储文件、外部邮件、身份提供商配置、前端静态资源和平台环境变量。完整恢复要列出全部组件。对象存储版本、生命周期和备份策略单独确认。秘密不能简单塞入数据库备份，应有恢复流程。

恢复到测试环境后，API 使用测试域名，禁用真实外部通知，避免向真实用户发邮件。校验记录数、关键查询、文件引用和权限。备份完成提示不能替代恢复成功证据。删除账号、软删除和保留政策也要覆盖数据库、对象、索引、缓存和备份。

一个完整头像上传流程可以作为练习。客户端预览图片，向 API 请求上传授权；API 验证身份和配额，生成特定 Key 的短期上传 URL；客户端上传对象存储；API 验证对象存在并更新数据库头像 Key；后台生成缩略图；展示时用公开 URL 或短期读取 URL。任何一步失败，都有状态和清理方式。

## 本章验收清单

能画出客户端、API、数据库、对象存储、队列、工作进程、Webhook 和实时通道。知道结构化数据和大文件为何分开。能解释事务、唯一约束、幂等、分页、限流和重连补状态。API 不直接信任客户端 ID，实时功能不绕过服务端认证。

最小练习选择一个自己的功能。先写一个 API 地址和它读写的数据库表或数据集合，再标出文件、后台任务与实时通知是否参与其中。没有的写“无”。最后写出第一处日志在哪里。不要用真实生产密码和用户文件做练习。

AI 可以从接口文档生成请求示例，解释数据库关系，设计上传状态、Webhook 幂等和实时重连测试。不要给 AI 生产数据库密码、签名 URL、Webhook Secret 和用户文件。数据库权限、对象公开范围、删除、备份和恢复需要亲自确认。下一章会把浏览器 DevTools 用作观察窗口，查看 Console、Network、状态码和 Response。
