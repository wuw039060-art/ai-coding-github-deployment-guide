# HTML、CSS、JavaScript、前端和后端

网页打开以后，浏览器主要处理三类内容。HTML 描述结构，CSS 决定呈现，JavaScript 处理行为与数据。它们共同组成网页前端。线上产品的后端通常运行在维护者控制的服务器或托管环境中，处理需要集中控制、保存秘密、访问数据库和执行业务规则的工作。本地开发或离线工具也可以在同一台电脑上运行后端，前后端按职责区分，不只看设备位置。

了解这组分工，不要求马上成为前端工程师。目标是用户说“页面坏了”时，你能先判断该看页面结构、样式、脚本、网络请求，还是服务端日志。

## HTML 负责内容结构

HTML 是 HyperText Markup Language 的缩写，中文常译为超文本标记语言。它用元素表示标题、段落、链接、图片、表单和按钮。

```html
<h1>活动报名</h1>
<p>请在周五前提交。</p>
<a href="/register">打开报名表</a>
```

`h1` 是一级标题，`p` 是段落，`a` 是链接。浏览器解析元素后形成文档结构。搜索引擎、屏幕阅读器和自动化工具也会使用这些语义。原生 `button`、`label`、`input` 等元素自带键盘和无障碍能力，比用可点击的 `div` 再补脚本更稳。

HTML 还引用 CSS、JavaScript、图片和元数据。引用路径写错，会表现为独立请求失败。正文能显示但没有样式，可能是 CSS 404；按钮存在但点了没反应，可能是脚本失败；图片缺失未必和数据库有关。

## CSS 负责呈现和布局

CSS 是 Cascading Style Sheets 的缩写，中文常译为层叠样式表。它选择 HTML 元素并设置颜色、尺寸、间距、布局和响应式规则。

```css
.notice {
  max-width: 40rem;
  padding: 1rem;
  background: #f4f7ff;
}
```

类名 `notice` 要和 HTML 中使用的类一致。CSS 的层叠意味着多条规则可能同时作用，优先级和顺序决定最终值。样式没生效时，DevTools 的 Elements 和 Styles 能显示实际匹配、被覆盖规则和最终计算值。

响应式布局让页面适应手机、桌面、长中文和文字缩放。不要只在自己的大屏幕验证。文字溢出、按钮换行、深色模式和触摸目标，都是前端质量的一部分。CSS 问题通常不会改变数据库数据，但会让用户误以为功能不可用。

## JavaScript 负责行为

JavaScript 是浏览器原生支持的编程语言。它可以监听点击、修改页面、验证表单、请求 API 和保存本地状态。

```js
const button = document.querySelector('#load')

button.addEventListener('click', async () => {
  const response = await fetch('/api/items')
  if (!response.ok) throw new Error(`HTTP ${response.status}`)
  const items = await response.json()
  console.log(items)
})
```

这段代码假定页面已有 `id="load"` 的按钮，并在按钮元素解析完成后执行，例如将脚本放在页面末尾或使用 `defer` 加载。点击后请求 API，并在解析前检查状态。真实项目还要捕获请求异常，显示加载中、空结果、错误和成功状态。JavaScript 出错后，后续脚本可能停止，于是用户看到“按钮点了没反应”。Console 的第一条异常、调用栈和发生版本，是定位前端问题的重要证据。

异步请求不会按代码书写顺序立刻完成。用户快速点击两次，两个请求可能并发，后返回的旧结果覆盖新结果。可以取消旧请求、禁用重复提交、使用请求序号，或在服务端用幂等键保护写操作。界面状态和后端状态要一起设计。

## 前端代码会发到用户设备

Web Frontend 译为网页前端。它在浏览器中呈现界面并处理交互。源码经过构建后会发送到用户设备，因此前端代码、公开配置和接口地址都可以被查看。前端适合做即时反馈，例如检查必填字段、计算预览、筛选已下载列表和保存未提交草稿。

前端不能作为关键规则的唯一执行者。报名页面用 JavaScript 限制每人一份，用户仍可以绕开界面直接调用 API。后端必须根据登录身份检查重复报名。隐藏管理员按钮只改善界面，不产生权限。API 要拒绝普通用户的管理员请求。

前端变量也要分级。API 公共基址、公开项目标识和客户端功能开关可以进入构建产物。数据库密码、服务端密钥、支付 Secret、AI API Key 和小程序 AppSecret 不能进入前端。变量名缺失时，构建可能失败，也可能运行时才暴露，发布前要检查产物是否含测试域名或密钥模式。

## 后端运行在受控环境

Backend 译为后端。后端代码可以读取数据库、保存秘密、发送邮件、调用付费 API、处理权限和后台任务。它可以是服务器中的常驻程序，也可以是托管平台函数。用户只通过 API 或生成页面间接使用它。

后端环境变量由部署系统注入，日志不能打印真实值。后端返回的数据也要最小化。用户有权查看订单，不表示响应要包含内部成本、其他用户邮箱或调试字段。

前端验证提供体验，后端验证承担最终安全和数据完整性。前端允许昵称 30 个字符，后端数据库只允许 20 个，就会到提交后才失败。字段规则应有共同规范和测试。后端错误返回稳定代码与可读提示，前端把提示放在相关位置；数据库堆栈和内部路径留在受控日志。

## 构建工具改变源码形态

现代前端常使用组件、TypeScript、模块和 CSS 工具。浏览器不一定直接运行原文件。构建工具转换、组合和优化，生成 `dist` 或其他输出。源码里的 `src/App.tsx` 可能变成带哈希的 JavaScript 文件。构建产物通常可重建，不应手工修改。直接改 `dist` 上线，下一次构建会覆盖，Git 历史也缺少来源。

开发服务器提供热更新和详细错误，生产构建启用压缩与优化。只测试开发模式会漏掉构建路径、环境变量、静态资源和缓存问题。Source Map 可以把压缩产物中的错误位置映射回源码，方便生产调试；是否公开 Source Map 要按安全与调试需要决定，秘密仍不能进入前端。

单页应用可以在浏览器内处理 `/profile` 路由。用户点击时不一定重新请求完整 HTML；用户直接刷新 `/profile` 时，请求先到服务器。静态托管若只找磁盘文件，可能返回 404。部署需要把未知前端路由回退到入口 HTML，同时不要吞掉真实 API 404。

## 一个报名流程分层看

HTML 提供姓名、邮箱和提交按钮。CSS 让字段在手机上可读。JavaScript 检查空值并 POST 到 `/api/register`。后端验证格式、身份和名额，使用数据库事务创建记录，再返回 201。前端显示确认编号。

邮箱重复时，后端返回 409 和稳定错误代码，前端提示“该邮箱已经报名”。数据库故障时，后端返回 500，前端提示稍后重试并保留用户输入。服务端日志用 Request ID 记录错误，不保存明文密码。这个流程包含界面、网络、业务和数据四层，任何一层都可能失败。

再对照另一个现象。按钮颜色不对，Elements 能找到元素，Styles 显示规则被覆盖，这是 CSS 层问题。按钮点后 API 返回空数组，Console 无异常，这是数据或请求层问题。按钮根本不存在，检查 HTML 或组件条件，也可能是权限让前端有意不渲染。

## 静态前端也能组成动态产品

前端可以部署在 Pages 或 CDN，构建成静态文件。页面运行后请求另一个域名的 API。产品整体仍是动态应用。部署要配置 API URL、CORS、HTTPS 和认证。API 地址公开没有关系，真正秘密留在后端。

API 暂时不可用时，静态页面仍能打开。前端应显示具体失败和重试方式，不让加载动画永久转圈。版本发布要考虑兼容。新前端使用新字段，后端尚未部署会失败；后端删除旧字段，缓存中的旧前端会失败。安排部署顺序或让 API 保持短期兼容。

前端的内存状态通常只存在当前页面运行期间，刷新后可能消失。本地持久化状态则可以保存在 Local Storage 或 IndexedDB，刷新不会自动清空。需要跨设备保留的草稿可以存到后端，但需要登录、网络和冲突处理。敏感 Token 不因方便就放 Local Storage。产品要明确哪些状态应保留，哪些只是临时筛选。

## App 和小程序也是前端客户端

本章虽然从网页讲起，但前端不只浏览器页面。Flutter、React Native、原生 iOS、原生 Android 和微信小程序都在用户设备或平台容器中运行界面代码。它们能读取本地状态、调用系统能力、展示表单和请求 API。它们也同样不能保存高权限秘密，不能替代后端权限检查。

移动端和小程序会多出发布与平台边界。App 有调试包、测试包和商店包，小程序有开发版、体验版、审核版和线上版。用户看到的问题可能来自客户端版本、平台审核配置、服务器域名白名单、系统权限或后端 API。排查时写清“哪个客户端、哪个版本、哪个环境、哪个 API”，不要只说“前端坏了”。

多端共用接口时，界面规则可以不同，服务端规则必须一致。网页隐藏删除按钮，小程序没有该入口，App 显示灰色，都不能阻止攻击者构造删除请求。后端根据已验证身份、资源归属和当前状态决定是否允许。客户端负责把拒绝结果翻译成用户能理解的界面。

离线能力也属于前端边界。App 和小程序可能先显示本地缓存，再同步后端。界面应标出上次同步时间或离线状态，不能把旧数据冒充最新。重新联网后的冲突处理由产品规则决定，服务端仍保存权威状态。

## 本章验收清单

能用结构、样式、脚本、请求和后端五层定位页面问题。知道前端代码和公开变量会发送给用户。能解释开发服务器与生产构建差异、路由刷新 404、Source Map 作用和前后端验证边界。不会把隐藏按钮当权限，也不会手改构建产物当长期修复。

最小练习从自己的静态练习页开始。找一段 HTML、一条 CSS 规则和一个 JavaScript 事件。分别写出它们影响的可见结果。临时禁用 CSS，观察结构是否仍可读；禁用 JavaScript 后，核心内容是否可见。不要在不属于你的网站修改或提交数据。

AI 可以读取项目结构，指出 HTML、CSS、脚本入口、构建配置和后端 API。它能解释 Console 错误与 Network 请求，并生成最小复现。让 AI 修改界面时要求保留语义、键盘和响应式。真实设备显示、用户数据、权限和生产构建仍要亲自验证。下一章继续追踪前端请求，解释 API、数据库、文件存储和实时连接怎样组成动态应用。
