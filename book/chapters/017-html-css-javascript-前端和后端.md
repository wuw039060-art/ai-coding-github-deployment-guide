# HTML、CSS、JavaScript、前端和后端

网页打开以后，浏览器主要处理三类内容。HTML 描述结构，CSS 决定呈现，JavaScript 处理行为与数据。它们共同组成网页前端。后端运行在用户设备之外，处理需要集中控制、保存秘密或访问数据库的工作。

了解分工并不要求成为前端工程师。目标是看到一个错误后，知道先查页面结构、样式、脚本、网络请求还是服务端日志。

## HTML 描述页面有哪些内容

HTML 是 HyperText Markup Language 的缩写，中文常译为超文本标记语言。它用元素表示标题、段落、链接、图片、表单和其他结构。

```
<h1>活动报名</h1>
<p>请在周五前提交。</p>
<a href="/register">打开报名表</a>
```

`h1` 是一级标题，`p` 是段落，`a` 是链接。浏览器解析元素后形成文档结构。搜索引擎、屏幕阅读器和自动化工具也会使用这些语义。不要只用可点击的 `div` 模拟按钮。原生 `button` 有键盘、焦点和无障碍语义。选择正确元素比事后补大量脚本更稳妥。

HTML 文件还引用 CSS、JavaScript、图片和元数据。引用路径错误会产生独立请求失败。

## CSS 决定内容怎样排布

CSS 是 Cascading Style Sheets 的缩写，中文常译为层叠样式表。它选择 HTML 元素并设置颜色、尺寸、间距、布局和响应式规则。

```
.notice {
  max-width: 40rem;
  padding: 1rem;
  background: #f4f7ff;
}
```

这段样式限制宽度、增加内边距并设置背景。类名 `notice` 要与 HTML 中使用的类一致。CSS 的层叠意味着多条规则可能同时作用，优先级和顺序决定最终值。样式没生效时，DevTools Elements 或 Styles 可以显示实际匹配与被覆盖规则。

响应式布局让页面适应手机与桌面。不要只在自己的大屏幕验证。文字缩放、长中文、深色模式和触摸操作都要测试。

## JavaScript 让页面响应操作

JavaScript 是浏览器原生支持的编程语言。它可以监听点击、修改页面、验证表单、请求 API 和保存本地状态。

```
const button = document.querySelector('#load')

button.addEventListener('click', async () => {
  const response = await fetch('/api/items')
  const items = await response.json()
  console.log(items)
})
```

代码找到按钮，点击后请求 API，再把数据打印到 Console。实际项目还要检查响应状态和错误，并把结果安全显示给用户。JavaScript 出错后，后续脚本可能停止。页面结构和已有样式仍能显示，于是用户看到“按钮点了没反应”。Console 的第一条异常与调用栈是重要线索。

## 浏览器怎样把三者放在一起

浏览器先解析 HTML，遇到外部 CSS 与脚本会继续请求。CSS 影响绘制，JavaScript 可以读取和改变文档。MDN 对浏览器加载过程的说明展示了这种多资源关系。脚本放置与加载方式会影响解析。大脚本阻塞页面时，用户会看到空白或无法操作。`defer`、模块和构建拆包能改善，具体由项目工具处理。

图片与字体也影响布局。图片没有尺寸时，加载后页面可能跳动。字体失败时浏览器使用回退字体，中文换行可能变化。页面最终效果来自源码、构建处理、网络响应与浏览器状态。只看某一个 HTML 文件不能解释全部运行行为。

Web Frontend 译为网页前端。它在浏览器中呈现界面并处理用户交互。源代码构建后会发送到用户设备，因此前端代码和公开配置可以被查看。前端适合即时反馈。例如检查必填字段、计算预览、筛选已下载列表和保存未提交草稿。它不能作为关键规则的唯一执行者。

假设报名页面在 JavaScript 中限制每人一份。用户可以绕开界面直接调用 API。后端仍要根据登录身份检查重复报名。前端隐藏管理员按钮只改善界面，不产生权限。API 要拒绝普通用户的管理员请求。

## 后端运行在受控环境

Backend 译为后端。服务端代码可以读取数据库、保存秘密、发送邮件、调用付费 API、处理权限和后台任务。MDN 对服务端的介绍把数据库、身份、内容生成与访问控制列为常见能力。

后端可以是一台服务器中的常驻程序，也可以是平台函数。用户只看到它暴露的 API 或生成页面。后端环境变量保存数据库密码和第三方密钥。代码提交到 GitHub，秘密由部署系统注入。日志不能打印值。

后端返回的数据仍要最小化。用户有权查看订单，不表示响应要包含内部成本、其他用户邮箱和调试字段。

前端验证提供即时体验。邮箱缺少 `@` 时可以立即提示，不必发请求。后端验证承担最终安全与数据完整性。前端与后端规则可能不一致。前端允许昵称 30 个字符，后端数据库只允许 20 个，用户提交后才报错。字段约束应有共同规范并测试。

后端错误要返回稳定代码与可读提示。前端把它放在相关字段附近。不要把数据库异常直接显示。网络中断时，前端区分“没有连接”与“服务器拒绝”。允许重试的操作要避免重复创建订单。

## 构建工具改变了源码形态

现代前端常使用组件、TypeScript、CSS 预处理与模块。浏览器不一定直接运行原文件。构建工具转换、组合和优化，生成 `dist` 或其他输出。源码中的 `src/App.tsx` 可能在产物中变成带哈希的 JavaScript 文件。浏览器错误调用栈经过压缩难读，Source Map 可以映射回源码。

开发服务器提供热更新和详细错误，生产构建启用压缩与优化。只测试开发模式会漏掉构建路径、环境变量和静态资源问题。构建产物通常可重建，不应手工修改。直接改 `dist` 上线，下一次构建会覆盖，Git 历史也缺少来源。

单页应用可以在浏览器内处理 `/profile` 与 `/settings` 路由。用户点击链接时，JavaScript切换页面，不一定重新请求完整 HTML。用户直接刷新 `/profile` 时，请求先到服务器。静态托管若只找磁盘文件，会返回 404。部署需要把未知前端路由回退到入口 HTML，同时保留真实静态文件与 API 路径。

服务端路由直接处理请求，可以返回 HTML 或 JSON。前后端都使用 `/api` 等清楚前缀能减少冲突。路由规则影响缓存和权限。不要让前端回退规则吞掉 API 404，返回一份 HTML 让客户端 JSON 解析失败。

## CSS 问题与数据问题的对照

按钮存在但颜色不对，Elements 能找到元素，Styles 显示规则被另一条覆盖。这是 CSS 层问题。按钮点后显示空列表，Console 无异常，Network API 返回空数组。界面正常，数据来自后端。转向请求参数和数据库。

按钮根本不存在，检查 HTML 或组件条件。用户权限可能让前端有意不渲染，也可能是 JavaScript 初始化失败。从可见现象分层，会比重新安装全部依赖更快。

HTML 提供姓名、邮箱和提交按钮。CSS 让字段在手机上可读。JavaScript 检查空值并 POST 到 `/api/register`。后端验证格式、身份和名额，使用数据库事务创建记录，再返回 201。前端显示确认编号。

邮箱重复时后端返回 409 和稳定错误代码，前端提示“该邮箱已经报名”。数据库故障时返回 500，前端提示稍后重试并保留用户输入。服务端日志用 Request ID 记录错误，不保存明文密码。整个流程包含界面、网络、业务和数据四层。

## 静态前端也能使用动态后端

前端可以部署在 Pages 或 CDN，构建成静态文件。页面运行后请求另一个域名的 API。产品整体仍是动态应用。部署要配置 API URL、CORS、HTTPS 和认证。前端源仓库公开时，API 地址也会公开，这没有关系。真正秘密留在后端。

API 暂时不可用时，静态页面仍能打开。前端应显示具体失败与重试，不让加载动画永久转圈。版本发布要考虑兼容。新前端使用新字段，后端尚未部署会失败。安排部署顺序或让 API 保持兼容。

构建工具会读取特定前缀环境变量，并把值替换进生成的 JavaScript。用户下载脚本后就能看到。变量控制台只保护构建前保存，不能保护已经进入产物的值。前端变量适合 API 公共基址、功能开关和公开项目标识。数据库密码、服务端密钥与签名秘密留在后端。

开发环境 `.env.local` 与生产平台变量可能不同。变量名缺失时，构建可能失败，也可能生成 `undefined`，直到运行才暴露。发布前检查构建产物是否含密钥模式和测试域名。泄露后立即轮换，不只删除产物。

## Source Map 的便利与边界

Source Map 把压缩产物位置映射回原始源码，错误监控可以展示真实文件和行。它显著改善生产调试。公开 Source Map 可能暴露原始源码、注释和目录。是否公开由项目安全与调试需要决定。也可以只上传给受控错误监控服务，不对用户发布。

版本必须匹配。新 JavaScript 配旧 Source Map 会把错误指向错误位置。部署记录与错误事件保存提交和资产哈希。关闭 Source Map 不能修复漏洞，只减少源码可读性。秘密仍不能进入前端。

前端依赖安装在开发或构建环境，打包器把实际使用代码放进产物。某些依赖也从 CDN 直接加载。第三方脚本在页面权限内运行，可能读取页面内容和发请求。分析、聊天和支付脚本都要评估来源、更新与隐私。

使用 Subresource Integrity 时，浏览器可验证外部资源哈希。版本更新要同步哈希与 CORS 配置。自托管减少外部运行依赖，也增加更新责任。依赖漏洞扫描给出线索。修复前确认依赖是否进入产物、漏洞是否可达，并测试升级兼容。

## 前端状态为什么会“刷新丢失”

组件内存状态只存在当前页面进程，刷新后重新初始化。需要保留的草稿可以进入 Local Storage、IndexedDB 或后端。本地保存要处理容量、过期、隐私和多标签同步。敏感 Token 不因方便就放 Local Storage。

后端保存可以跨设备，需要登录、网络与冲突处理。离线编辑后同步要定义谁覆盖谁。用户看到刷新丢失时，先确认产品承诺。临时筛选条件消失可能正常，未提交长文丢失则应提供草稿或离开提醒。

一个组件异常不应让整个页面永久白屏。前端可以在适当边界捕获错误，显示重试与反馈入口。错误边界不能吞掉所有错误并继续错误状态。记录调用栈、版本和操作，清理局部状态后再重试。API 错误与渲染错误分别处理。网络中断显示离线，权限拒绝引导申请或返回，未知异常提供请求编号。

用户输入尽量保留。重试提交要避免重复写入。

## 一个生产白屏例子

本地开发正常，生产打开白屏。主文档和脚本均 200，Console 显示读取缺失环境变量时异常。开发电脑 `.env.local` 有 `API_BASE_URL`，部署平台没有。构建仍成功，运行到请求代码才失败。修复是在生产环境配置公开 API 基址并重新构建。前端启动时加入配置校验和可读错误，部署检查验证变量存在。

最终从公开域名、无缓存窗口检查。不能把 `.env.local` 连真实其他秘密一起提交。

语义 HTML、键盘焦点、标签与替代文字让更多用户使用页面，也方便自动化测试。CSS 不应把焦点轮廓全部去掉。JavaScript 动态更新内容时，屏幕阅读器需要得到合适通知。弹窗打开后管理焦点，关闭后回到触发按钮。

颜色对比、文字缩放和触摸目标属于界面质量。只在鼠标和大屏验证会漏掉。EPUB 中的代码和图片也遵守相同原则，图片有替代文字，核心知识不依赖颜色和 JavaScript。

## 表单语义让浏览器帮助用户

`label` 把字段名称与输入框关联。正确 `type` 能让手机显示合适键盘，浏览器也可做基础验证。`autocomplete` 告诉密码管理器字段用途。占位文字不能替代 Label，用户输入后会消失，对比度也常不足。错误消息与字段关联，并保留输入。

提交按钮使用 `button type="submit"`，键盘回车也能触发表单。JavaScript 增强提交，基础结构仍清楚。密码字段不打印到 Console。浏览器自动填充是安全与易用能力，不应无理由阻止。

普通文档流让块级内容按顺序排列。Flexbox 适合一维排列，Grid 适合二维布局。Absolute 定位脱离普通流，滥用会导致文字重叠。页面在某个屏幕正常，换成长中文就溢出，说明布局依赖固定尺寸。使用弹性尺寸、换行与最大宽度。

表格适合数据关系，不用表格排整个页面。移动端宽表可以横向滚动或转为适合结构，不能缩到不可读。DevTools 调整视口并检查计算样式，最终仍用真实设备。

## JavaScript 的异步执行

网络请求、计时器和用户事件不会按代码书写顺序立即完成。`await` 等待 Promise，错误要用合适捕获。用户快速点击两次，两个请求可能并发，后返回的旧请求覆盖新结果。可以取消旧请求、使用请求序号或只接受最新结果。

页面离开后异步回调仍可能尝试更新已销毁组件。框架提供清理机制，网络请求可用 AbortController 取消。异步错误没捕获会出现在 Console。Loading、Success、Empty 与 Error 四种界面状态都要设计。

用户昵称含 `<script>` 一类文本时，页面应当作文字显示。直接拼接进 `innerHTML` 可能产生 XSS。使用 `textContent` 或框架默认转义。必须显示富文本时，用成熟 Sanitizer 与严格允许列表。URL 也要验证 Scheme，避免 `javascript:` 等危险目标。外部链接新窗口使用合适关系属性。

内容安全策略可以限制脚本来源，不能替代安全编码。出现策略阻止时查违规来源，不直接允许所有内联脚本。

## 前后端共享类型仍需运行时验证

TypeScript 能在开发时检查类型，网络返回仍可能不符合。后端升级、代理错误页和恶意请求都会带来意外数据。API 边界进行运行时验证。缺字段时显示可恢复错误并记录版本，不让整页崩溃。

共享生成类型能减少手写差异，仍要管理 API 版本。代码编译通过不证明数据库内容符合。后端也验证前端请求，不能相信 TypeScript 客户端保证。

本地页面正常，部署后无样式。Network 中 CSS 请求 404，Request URL 多了一层 `/app/app.css`。构建配置的 Base Path 与部署子路径不一致。HTML 生成了错误资源地址。修改基址并重新构建，CSS 返回 200。

验收包括首页、深层路由刷新与图片字体。只在根路径打开会漏掉相对路径错误。修复进入源码配置，不手改生产 HTML。

## 浏览器兼容以支持范围为准

项目先定义支持的浏览器与版本。使用标准 Web API，并根据需要编译语法与加载 Polyfill。Polyfill 用 JavaScript 补充旧浏览器缺少能力，会增加体积和维护。检测功能，避免按浏览器名称分支。

开发者工具中的兼容警告提供线索，最终在目标浏览器测试。Safari、Firefox 与 Chrome 都有实现差异。停止支持旧版本时给用户明确提示与理由，不让页面静默白屏。

首屏慢先看主资源大小、阻塞脚本、图片与字体。交互卡顿看长 JavaScript 任务和重复渲染。图片提供正确尺寸与现代格式，非首屏内容可以懒加载。关键文字不依赖巨大背景图。代码拆分让路由按需加载，过度拆分也会增加请求。用测量决定。

性能预算写入构建与监控，例如主脚本或图片上限。数字按产品和目标网络制定。

## SEO 与可分享信息来自 HTML

Title、Description、语义标题和规范 URL 帮助搜索与分享。Open Graph 等元数据影响社交预览。动态客户端渲染的内容要确认搜索引擎能获取，重要公开页面可以静态生成或服务端渲染。

登录后私人页面不应被索引，使用认证与响应策略。robots 只提供爬取指示，不保护秘密。链接在无 JavaScript 基础下尽量可导航，按钮与链接用途分清。

第三方字体失败时用系统字体；分析脚本失败不影响购买；支付脚本失败则明确提示并停止提交；每个外部依赖按关键程度设计超时与备用；不要让一个客服聊天脚本阻塞整个首页。用 Network Request blocking 在测试中模拟，注意它只影响当前浏览器。真实故障还要看 CSP 和代理。

降级路径也要测试与无障碍检查。

## 本章验收清单

能用结构、样式、脚本、请求与后端五层定位页面问题。知道前端代码和变量会发送给用户。能解释开发服务器与生产构建差异、路由刷新 404 和 Source Map 作用。表单同时有前后端验证。改界面后检查语义、键盘、手机与构建产物。不把隐藏按钮当权限，不手改 `dist`。

系统 `prefers-color-scheme` 可以选择浅色或深色。背景、文字、边框、链接与代码块都要一起调整。只把背景变黑会让深色图标消失。SVG 可以使用适配颜色或提供清晰边框，照片保留自然色。用户手动主题优先级与系统设置明确，保存到本地。首次加载避免闪烁，也不能用阻塞大脚本。

在高对比模式和打印中测试。颜色不承担唯一状态，错误同时有文字和图标。

`img` 提供宽高和替代文字；装饰图使用空替代文字，信息图给等价说明；不同屏幕用 `srcset` 等能力选择合适尺寸；视频提供字幕、控制与封面；自动播放声音会干扰用户并常被浏览器阻止；上传前端预览使用本地对象 URL，用完释放；预览成功不代表服务端接受。

来源不明媒体不嵌入。许可、文件大小、隐私元数据和 CDN 缓存同时检查。

## 模态框与通知的可用性

模态框打开后焦点进入，键盘焦点不跑到背景。Esc 关闭是否允许按风险设计，关闭后焦点回触发点。删除确认写出对象和后果，不使用只有“确定”的模糊文字。高风险操作要求额外确认或输入对象名。

Toast 通知短暂显示，不适合承载唯一错误。表单错误留在字段旁，系统状态有持久区域。屏幕阅读器通过 Live Region 得到异步结果，避免每个进度更新都打断。

中文、英文与其他语言长度不同；按钮不固定窄宽，文本允许换行；日期、数字和货币用本地化 API；翻译 Key 与默认文字进入版本管理；缺翻译时有可识别回退，不显示内部 Key；用户内容不自动翻译；数据库保存标准时间和货币单位，界面按地区显示。

从右到左语言会改变布局方向。若产品不支持，明确范围，不写“全球可用”。

## 前端测试分层

单元测试检查函数和组件，集成测试检查表单与 API 交互，端到端测试在浏览器走关键流程。测试通过只覆盖已写场景。真实设备、无障碍、网络和视觉仍需人工与专门工具。修复白屏先增加可复现测试，再改代码。测试使用模拟秘密和测试账号。

生产监控补充测试无法覆盖的浏览器与数据组合。错误事件关联前端版本。

## 最小代码观察练习

打开自己的静态练习页，找一段 HTML、一条 CSS 规则和一个 JavaScript 事件。分别写出它们影响的可见结果。临时禁用 CSS，观察结构是否仍可读。禁用 JavaScript 后，核心内容是否可见。不要在不属于你的网站修改或提交数据。

成功结果是能把“页面坏了”缩小为结构、样式、脚本、请求或后端之一。

AI 可以读取项目结构，指出 HTML、CSS、脚本入口、构建配置和后端 API。它能解释 Console 错误与 Network 请求，并生成最小复现。让 AI 修改界面时要求保留语义、键盘与响应式。后端权限和秘密仍要单独审查。

真实设备显示、用户数据、权限与生产构建要亲自验证。前端隐藏内容不能作为访问控制，浏览器代码中不能放高权限密钥。下一章会继续追踪前端请求，解释 API、数据库、文件存储和实时连接怎样组成动态应用。
