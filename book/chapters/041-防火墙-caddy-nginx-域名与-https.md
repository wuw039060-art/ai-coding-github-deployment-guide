# 防火墙、Caddy、Nginx、域名与 HTTPS

用户访问你的网站时，请求要经过域名解析、云平台安全组、主机防火墙、反向代理、应用端口和应用本身。任何一处错了，用户都可能看到打不开、502、证书错误或超时。入口层的任务，是让外部请求只从允许的门进来，再把它们转给正确的内部服务。

## 先保护 SSH

启用主机防火墙前，先确认 SSH 端口已经放行。很多人第一次开 UFW，就把自己挡在服务器外。稳妥做法是保持当前 SSH 会话不断开，先添加 SSH 允许规则，再启用防火墙，另开终端测试能否重新登录。测试成功后再继续改其他规则。

Web 服务通常只需要公网开放 80 和 443。应用自己的 3000、8000、8080 端口，如果只给反向代理访问，就绑定到本机地址或由防火墙限制。数据库、Redis、管理面板和内部监控不要直接暴露到公网。

云安全组和主机防火墙要一起看。外部访问失败时，先确认 DNS 指到正确 IP，再检查平台和主机两边的规则，最后看反向代理。只盯其中一个入口，容易来回改却没有效果。

## Caddy 和 Nginx 怎样选

Caddy 对初学者友好。它的配置短，自动申请和续期 HTTPS 证书，适合一台服务器上部署少量 Web 应用。你写清域名和后端地址，Caddy 会处理很多证书细节。第一版上线时，这种省心很值钱。

Nginx 更常见，也更灵活。它适合复杂转发、静态资源、旧系统和团队已有经验的场景。灵活也意味着配置项更多。改 Nginx 前先测试配置，再 reload。不要直接 restart。配置错了，restart 可能让原本还在服务的入口一起停掉。

两者都只是入口工具。它们不能修复后端应用错误，也不能替你做业务权限。502 表示代理没有拿到有效的上游响应，常见原因有后端未启动、端口或监听地址错误、连接被拒绝、上游提前断开或返回格式异常。超时也可能表现为 504，具体以代理日志为准。先查代理日志和应用日志，再改配置。

## HTTPS 和域名

HTTPS 自动签发有条件。使用 HTTP-01 验证时，证书机构要能访问域名的 80 端口；使用 TLS-ALPN-01 时需要 443 端口。若配置 DNS-01，则靠指定的 DNS TXT 记录验证，证书申请端不必从公网开放这两个端口，但实际网站仍需要可访问的 HTTPS 入口。还要确认 DNS、证书存储、服务器时间和签发限流。域名刚改解析时先核对实际结果，不要反复删除配置和重装工具。

小锁图标只说明浏览器建立了加密连接，不说明业务安全。还要确认域名正确、证书未过期、HTTP 自动跳转到 HTTPS、后台 API 也走 HTTPS、Cookie 使用安全属性。若有多个子域名，要分别确认。

HSTS 会让浏览器记住只用 HTTPS 访问某个域名。正式稳定后可以考虑。试验阶段不要随便开启，尤其是还在切换域名、证书和子域名时。开错以后，用户浏览器可能在一段时间内拒绝访问 HTTP。

## WebSocket、大文件和真实地址

WebSocket、SSE 和大文件上传需要额外注意超时、缓冲和请求体大小。WebSocket 还要检查 HTTP Upgrade 相关设置；SSE 是持续的 HTTP 响应，不使用 WebSocket 升级。默认代理配置可能适合普通页面，不适合实时连接和大文件。出现连接一会儿就断、上传到一半失败时，分别检查代理、应用和平台限制。

反向代理后，应用看到的客户端地址可能是代理地址。若应用需要记录真实 IP，要正确处理代理传来的头，并只信任自己的代理。不能随便相信客户端传来的地址头。否则用户可以伪造来源地址，影响审计和限流。

源站地址也要保护。若 CDN 或代理前面隐藏了源站，云安全组应限制只有可信入口能访问源站端口。否则攻击者绕过 CDN 直接打源站，你设置的缓存、限流和防护就可能失效。

## 入口故障记录

入口层排错要记录五件事。用户访问的域名，解析到的 IP，外部请求结果，服务器本机请求结果，代理和应用日志。超时、连接拒绝、502、404、证书不匹配，每一种都指向不同方向。

不要只写“网站挂了”。写清浏览器报什么、`curl` 报什么、证书域名是什么、后端端口是否监听、代理日志里是哪一行。入口层一旦记录清楚，后面很多故障会从玄学变成普通检查。

## 证书续期要提前发现

自动 HTTPS 的好处是少管证书，坏处是人容易忘记它仍然会失败。DNS 改错、80 端口被关、证书机构限流、服务器时间异常、磁盘满和代理配置错误，都可能影响续期。证书到期前要有告警，不能等用户截图。

检查证书时，看域名、到期时间、签发机构和证书链。多个域名共用一台服务器时，每个域名都要看。只检查主域名，可能漏掉 API 子域名、后台子域名和静态资源域名。

续期失败后先看日志。Caddy 和 Nginx 加 certbot 的日志位置不同。不要马上删证书目录重来。证书目录里可能有当前仍在使用的有效证书。先确认失败原因，再决定修 DNS、修端口、修权限或重新申请。

## 多域名和路径转发

一台服务器可以服务多个域名。反向代理根据 Host 头把请求分给不同应用。配置多域名时，先写清每个域名属于哪个项目、指向哪个后端端口、证书怎样签发。项目下线时，域名和证书也要一起清理。

路径转发看似方便，比如 `/api` 给后端，`/admin` 给后台，其他路径给前端。它会带来 Cookie、重定向、缓存和 WebSocket 的细节问题。初学项目能用子域名区分服务时，通常更清楚。

多个域名共用同一个后端时，也要检查应用是否知道外部域名。登录回调、OAuth、支付 Webhook、邮件链接和小程序业务域名，都可能依赖外部地址。代理能转发请求，不代表第三方平台也接受这个域名。

## 源站和可信代理

反向代理前面还可能有 CDN、负载均衡或云平台网关。每多一层，真实客户端地址、HTTPS 状态和请求大小限制都会变化。应用要只信任自己控制的代理传来的头。任何用户都能伪造的头，不能用来做审计和限流。

若只希望 CDN 访问源站，安全组要限制来源。否则攻击者可以绕过 CDN 直接打源站 IP。源站 IP 一旦泄露，不能只换域名。要收紧防火墙、检查日志、确认是否有未授权访问。

代理版本也要更新。Caddy、Nginx、OpenSSL 和系统证书包都有安全更新。入口层暴露在公网，比内部应用更容易被扫描。更新前测试配置，更新后验证 HTTP、HTTPS、WebSocket、上传和证书续期。

## 一次证书域名不匹配

假设一个后台域名从 `admin.old.com` 改到 `admin.new.com`。DNS 已经指向新服务器，代理也能转发，但浏览器提示证书不匹配。维护者查看证书，发现证书仍只包含旧域名。检查新域名的签发记录，才能判断问题是申请尚未完成、验证失败，还是代理仍加载旧证书。

处理时先确认新域名的解析与采用的证书验证方式。使用 HTTP-01 或 TLS-ALPN-01 时，再核对对应公网端口；使用 DNS-01 时检查 TXT 记录和 DNS 服务商权限。随后看证书工具日志。若旧域名仍在配置中，要判断是否继续保留。最后确认代理加载了正确证书，浏览器重新建立连接验证域名和证书链；无缓存窗口不能代替证书检查。

这类问题很适合写进域名变更清单。改 DNS，改代理配置，签发证书，改 OAuth 回调，改支付 Webhook，改小程序业务域名，改邮件链接，逐项确认。域名不是只有一条解析记录，它会出现在很多外部平台里。

## 502、404、403 和超时

不同错误要分开。502 多半是代理到后端失败。404 可能是路径没匹配，也可能是应用没有对应路由。403 可能来自代理权限、应用权限或静态文件权限。超时可能来自后端慢、网络不通、代理超时或防火墙丢包。

排错时先保留状态码和响应头。浏览器页面截图不够。`curl -i` 能看到状态、头和简短响应。再看代理日志里请求到了哪个 server block 或站点配置。多个域名和路径混在一台服务器时，日志能帮你确认请求落到哪里。

把错误码直接翻译成原因会误导。502 不等于后端挂了，后端可能只是监听错地址。404 不等于文件丢了，可能是代理把路径转错。每个错误码只给方向，证据还要从日志和本机测试来。

## 入口层验收

入口层上线后走一遍固定验收。HTTP 是否跳到 HTTPS。主域名和子域名证书是否正确。大文件上传是否成功。WebSocket 或 SSE 是否保持连接。后端真实 IP 是否被正确记录。管理端口是否只在允许范围内访问。

再看告警。证书到期提醒，站点不可用提醒，5xx 错误率，代理重启失败，磁盘日志增长，都应有人接收。入口层是用户看到系统的第一道门，它出错时，后端做得再好也没有机会解释。

## 让 AI 审代理配置

代理配置可以给 AI 看，但要去掉真实域名、内网地址和证书路径中的敏感部分。把域名改成 `example.com`，把后端地址改成 `127.0.0.1:3000` 这类示例。保留结构，删掉秘密。

让 AI 检查时，要求它回答几件事。公网开放了哪些入口。请求转到哪个后端。WebSocket 是否需要额外配置。上传大小是否受限。真实客户端地址怎样传递。HTTP 到 HTTPS 是否跳转。证书续期可能卡在哪里。

AI 生成 Nginx 或 Caddy 配置后，先用工具验证语法。再在测试域名或预览环境试。配置生效后，检查状态码、证书、日志和应用路径。不要把新配置直接覆盖生产入口。

代理配置还要和云平台规则一起看。AI 只能看到你给的文件，看不到安全组、DNS 和 CDN 设置。若它说配置没问题，外部仍打不开，就继续查平台层。入口问题常常跨过多个系统。

## 本章练习

准备一个测试域名或临时子域名。先确认 DNS 指向测试服务器。再用 Caddy 或 Nginx 把请求转发到一个本机测试端口。访问 HTTP 和 HTTPS，记录状态码、证书域名和代理日志。

然后故意停止后端测试服务，再访问域名。观察浏览器、curl 和代理日志分别显示什么。恢复后端后再访问一次。这个练习能让你把 502 和后端不可达联系起来。

最后检查防火墙。确认公网只开放 SSH、HTTP 和 HTTPS，或只开放你明确允许的端口。把安全组和主机防火墙都记录下来。入口层必须同时看两边。

## 常见误区

第一个误区是只改 Nginx 或 Caddy。入口失败可能来自 DNS、安全组、主机防火墙、证书、后端端口和应用日志。代理配置只是其中一层。

第二个误区是证书成功就认为安全完成。HTTPS 解决传输加密，不解决业务权限、Cookie 配置、后台入口暴露和源站保护。小锁图标只是开始。

第三个误区是把测试域名和正式域名混用。OAuth、支付、小程序业务域名和邮件链接都可能绑定域名。测试时随手改正式域名，会影响真实用户。

## 本章交付物

本章结束时，你应该留下入口表。每个域名对应哪个服务器，哪个代理配置，哪个后端端口，证书怎样续期，谁接收告警。入口表不写密钥，只写路径和责任。

还应有一份入口验收清单。DNS、HTTP、HTTPS、证书、代理日志、应用日志、WebSocket、大文件上传和真实客户端地址，逐项看一遍。入口层改动以后按清单验收。

AI 可以帮你解释 502、证书错误和代理配置。不要把真实私钥、证书密钥、完整访问日志、后台地址和管理面板入口交给它。下一章进入部署、更新、回滚、备份和恢复。
