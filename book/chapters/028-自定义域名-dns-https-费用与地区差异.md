# 自定义域名、DNS、HTTPS、费用与地区差异

平台自带地址已经能打开以后，自定义域名只是把用户入口换成自己的名称。网站文件仍在托管平台，DNS 告诉访问者去哪里，HTTPS 保护浏览器与入口之间的传输。绑定域名同时跨过域名注册商、DNS 服务和部署平台。三处界面可能由同一家公司提供，也可能完全分开。排错时先画清谁负责哪一段。

## 四个角色

域名注册商记录域名的注册与续费；DNS 托管商保存解析记录；部署平台提供网站地址和域名绑定；证书签发机构参与 HTTPS 证书验证与签发；同一家公司可以承担多个角色。把域名买在 Cloudflare，也可能直接用其 DNS 和 Pages。域名买在另一注册商，也能把 DNS 委托给 Cloudflare，再把站点托管到 GitHub Pages。

角色不清时，常在错误控制台修改记录。先查询当前权威名称服务器，再进入实际 DNS 管理位置。

`example.com` 常称根域或 Apex Domain，`www.example.com`、`app.example.com` 是子域。子域常用 CNAME 指向平台提供的目标名称。根域受 DNS 记录规则影响，平台可能要求 A、AAAA、ALIAS、ANAME 或供应商代理方式。不要把另一平台教程中的记录值照搬。

选择一个主访问地址，再把其他形式重定向过去。例如主站使用 `www.example.com`，根域跳转到 `www`。两边都能显示相同内容却不重定向，会造成链接和搜索统计分散。

## 为什么先在平台添加域名

平台需要知道这个域名属于哪个项目，才能验证所有权、配置路由并申请证书。只改 DNS，平台可能收到请求却不知道送给谁。GitHub Pages 官方建议先在仓库 Pages 设置中添加自定义域名，再修改 DNS，以降低子域被他人接管的风险。

Cloudflare Pages 也要求通过 Pages 项目的 Custom domains 流程关联域名。官方特别提醒，手工只建 CNAME 而不在 Pages 控制台关联，可能得到解析错误。

稳妥顺序是先确认平台自带地址正常，在平台添加域名，阅读平台给出的当前 DNS 目标，再去权威 DNS 创建记录，最后返回平台等待验证与证书。

前置条件包括拥有域名控制权、能修改权威 DNS、平台项目已经通过自带地址验收。操作窗口不要同时迁移网站内容和域名，减少变量。第一步在平台项目添加要使用的域名。记录平台显示的验证状态与所需 DNS 记录。不要从旧教程抄 IP。

第二步在 DNS 控制台检查同名旧记录。CNAME 与同名 A 记录通常不能并存。删除或替换会影响现有服务，先确认旧记录用途和恢复值。第三步按平台给出的名称、类型和目标创建记录。DNS 控制台有时自动补全域名，输入 `www` 即代表 `www.example.com`。确认最终显示值，避免重复成 `www.example.com.example.com`。

第四步等待解析传播并在平台重新验证。成功结果是域名状态有效，HTTPS 证书生效，浏览器打开正式地址没有证书警告。第五步检查根域、`www`、HTTP、HTTPS 和常用路径。确认只有一个主地址，其余按设计重定向。

## DNS 等待期间不要频繁改

DNS 记录带 TTL，递归解析器会缓存。修改后不同网络在一段时间内看到不同结果很正常。频繁删除重建会重置排错起点。先使用 DNS 查询工具确认权威记录与公共解析结果，再判断是否需要改。浏览器缓存、操作系统缓存和 DNS 缓存属于不同层。无痕窗口不能保证绕过所有 DNS 缓存。

平台仍显示验证中时，核对记录名称、类型、目标、代理状态和名称服务器。保留截图时遮住账号与无关域名。

浏览器访问 HTTPS 时，服务器提供证书，浏览器验证域名、有效期和信任链，再建立加密连接。TLS 的基础位置已在第十五章说明。托管平台通常自动申请和续期证书，前提是 DNS 正确指向并通过域名验证。证书未生效前不要强制所有流量跳转到一个无法建立 TLS 的地址。

GitHub Pages 当前设置提供 Enforce HTTPS。官方说明域名配置正确并可使用证书后可以启用。证书错误不是让用户点击继续的普通提示。先检查访问域名是否匹配、DNS 是否指向预期平台、证书状态与系统时间。

## CAA、代理与证书问题

CAA 记录可以限制哪些证书机构为域名签发证书。已有严格 CAA 时，平台使用的机构若不在允许范围，证书可能申请失败。DNS 代理会让解析指向代理网络，可能改变平台验证路径。按照托管平台与 DNS 商的联合说明设置，不要随意反复切换代理开关。

证书签发需要时间，失败时平台通常给出原因或重试状态。记录时间与错误，确认 DNS 稳定后再重试。不要上传来历不明的证书或私钥到第三方表单。托管平台自动证书不要求读者把私钥复制到网页控制台之外的地方。

通配 DNS 例如 `*.example.com` 会让许多未明确配置的子域也指向同一目标。它减少记录数量，也扩大误配置和接管风险。GitHub Pages 官方明确警告不要使用通配 DNS 记录，因为可能带来域名接管风险，即使已验证主域也不能消除。

个人项目优先逐个创建需要的子域。删除项目或迁移后，及时移除旧 CNAME，避免悬空记录指向不再控制的供应商资源。每季度检查 DNS 清单，确认每条记录都有负责人和用途。未知记录不要直接删除，先查服务依赖。

## 自带地址正常，域名错误

浏览器显示 DNS 名称不存在，检查权威 DNS 与记录是否生效。不要看构建日志，它不会收到请求。域名打开别人的项目，检查记录目标和平台域名归属。可能指向旧项目或错误账号。域名返回平台 404，自带地址正常，检查平台是否完成域名绑定，而非只加 DNS。

HTTPS 证书不匹配，确认访问的精确主机名、平台证书状态和 DNS 是否仍有旧记录。页面打开但资源请求旧域名，检查应用的站点 URL、绝对链接和环境变量，重新构建并部署。

域名通常按周期续费，首年促销价与续费价可能不同。隐私保护、溢价域名、转移和赎回也可能产生费用。托管平台可能按构建分钟、带宽、请求、函数执行、团队席位或额外功能收费。免费额度、超额价格和休眠规则会调整。

截至 2026 年 8 月 5 日，本书不写死任何平台的永久免费承诺。真正购买前打开注册商和平台官方定价页，记录币种、税费、续费价、配额与超额处理。为域名开启自动续费和到期提醒，并保留可用支付方式。域名过期会同时影响网站、邮件、API 和登录回调。

## 中国大陆使用注意

面向中国大陆公众提供网站时，服务器位置、接入服务商、域名实名、备案与具体业务许可可能影响上线流程。工信部 2024 年修订的办法规定，在中华人民共和国境内提供非经营性互联网信息服务应依法履行备案手续，并持续处理编号展示、信息变更和服务注销。办理材料与地区受理流程仍要核对所在地通信管理局和接入商的当前指南。部署到境外平台并不自动解决大陆访问质量或合规问题，跨境网络、DNS、支付与账号验证也可能影响维护。

实际项目应在上线前查询工信部门、域名注册商、云服务商和业务主管部门的当前官方说明。涉及经营、内容许可或个人信息处理时，寻求合格专业意见。正文会把这些内容放进“中国大陆使用注意”提示框，并写明检索日期，不把某次查询结果写成永久规则。

从旧平台迁移到新平台时，先让新平台自带地址通过验收，再添加域名并获取目标记录。保存旧 DNS 值与旧平台状态。适当降低 TTL 需要提前完成，因为旧 TTL 仍会缓存。切换 DNS 后同时观察新旧平台日志。

保留旧平台一段明确的观察期，不立即删除。确认主要网络解析到新目标、证书正常、核心功能和回调可用后，再按清单下线旧资源。若切换失败，恢复旧 DNS 值。回退时间仍受缓存影响，所以应提前向相关人员说明。

## 名称服务器决定去哪里修改

域名注册商会记录一组 Name Server，也就是名称服务器。它们指向当前权威 DNS 服务。你可能在注册商页面看到 DNS 编辑器，但域名已经委托给另一家，此处修改不会生效。先在注册信息和 DNS 查询中确认权威名称服务器。

更换名称服务器等于迁移整套 DNS。网站、邮件、验证、子域和 API 记录都要复制，不能只迁移主页记录。首次学习域名绑定时不要同时更换名称服务器。先在现有权威 DNS 添加站点记录，更容易隔离错误。

A 记录把名称指向 IPv4 地址，AAAA 指向 IPv6 地址，CNAME 把一个名称指向另一个名称。TXT 常用于所有权验证和邮件策略。MX 记录决定域名邮件接收。修改网站记录时不要删除 MX、SPF、DKIM 和 DMARC 等邮件相关记录。

同一名称的 CNAME 通常不能与其他常规记录并存。平台要求 CNAME 时，先查是否有同名 A 或 AAAA。根域不能在所有标准 DNS 场景直接使用普通 CNAME，供应商可能提供扁平化或别名能力。按当前平台给出的方式配置。

## 用查询结果代替肉眼猜测

Windows PowerShell 可用系统自带 `Resolve-DnsName` 查询，macOS 和 Linux 常用 `dig`。以下命令只读取公开 DNS。

```
Resolve-DnsName www.example.com
```

把 `www.example.com` 换成自己的测试域名。结果应显示当前记录类型、目标或地址。不要在书中把某个平台可能变化的 IP 写死。查询名称服务器可以运行。

```
Resolve-DnsName example.com -Type NS
```

正常结果列出权威名称服务器。若与自己编辑记录的平台不同，先查域名委托。不同公共解析器结果不同时，记录查询时间和 TTL，等待传播。不要每五分钟改一次目标。

## DNSSEC 的位置

DNSSEC 为 DNS 数据提供来源与完整性验证。它涉及注册商中的 DS 记录与 DNS 服务中的签名配置。正确启用能防止某些 DNS 篡改，错误迁移会让支持验证的解析器认为域名无效。更换 DNS 服务时先阅读双方迁移说明，协调 DNSSEC。不要仅删除页面上看不懂的 DS 记录。

个人静态站也可使用供应商托管 DNSSEC，但启用后要把它纳入域名迁移清单。

证书生效后，可以让 HTTP 请求跳转到 HTTPS。检查状态码和 Location，确保不会在 HTTP 与 HTTPS 之间循环。同时存在根域与 `www` 时，设计一次或少量明确跳转。多家平台各做一层重定向，容易形成循环或过长链。

内部链接直接写主 HTTPS 地址，减少不必要跳转。登录回调和 Webhook 白名单也更新为最终地址。HSTS 会告诉浏览器以后只用 HTTPS，影响较持久。初学项目在证书和所有子域稳定之前，不要贸然设置包含所有子域的长期策略。

## 域名验证记录不要随便删

平台、邮件、搜索工具和证书可能通过 TXT 或 CNAME 验证域名。完成验证后是否可以删除，由服务规则决定。给每条验证记录写用途和创建日期。多个随机字符串若没有说明，迁移时很容易误删。删除前查对应服务控制台和当前官方文档。某些服务只在初次验证读取，另一些会定期复核。

离开供应商后再删除其验证记录，减少攻击面和混乱。

DNS 仍指向第三方平台，而平台项目已经删除时，记录会悬空。若供应商允许其他账号认领相同自定义域名，攻击者可能接管流量。防护方式包括先在新平台验证，再切 DNS；下线时先移除 DNS，再删除平台资源；定期扫描悬空记录。

GitHub 建议先在 Pages 设置添加域名，正是为了降低配置窗口中的接管风险。不要使用大范围通配记录。一个遗忘的子项目会扩大到许多未登记名称。

## 域名转移与 DNS 迁移不同

域名转移是把注册管理从一家注册商移到另一家；DNS 迁移是更换权威名称服务器；托管迁移是更换网站平台；三件事可以分开完成；一次只改一层，验收后再继续，可以降低停机风险。注册转移通常涉及解锁、授权码、确认邮件和等待期，具体规则查注册商与 ICANN 当前说明。转移期间确保联系人邮箱可用。

转移不一定自动复制 DNS，也不一定改变名称服务器。操作确认页要逐项阅读。

企业邮箱常使用 `example.com`，网站也用同一域名。修改根域 DNS 时要保护邮件记录。站点平台只要求 A、AAAA 或 CNAME，不需要删除 MX。若控制台给出“一键接管 DNS”，先导出现有记录并核对邮件。

切换后发送和接收测试邮件，查看 SPF、DKIM 和 DMARC 是否仍通过。邮件系统不在本书实操范围，但不能在网站部署中被意外破坏。重要域名变更安排在有人可监控网站与邮件的时段，并准备旧记录恢复。

## 证书覆盖范围

`example.com` 的证书不一定覆盖 `www.example.com`，通配证书 `*.example.com` 通常也不覆盖根域。托管平台会按绑定名称申请合适证书。把根域和 `www` 都添加到项目，等待各自验证。不要看到其中一个有锁就认为另一个也完成。浏览器证书详情可查看签发给谁和有效期。现代平台自动续期，DNS 被改走或验证失败仍可能导致续期问题。

设置到期监控，提前发现证书续期失败。不要等用户报告红色警告。

新域名会影响绝对链接、登录回调、Cookie Domain、跨域允许列表、支付回调、邮件链接、站点地图和分析工具。静态展示页改 DNS 就可能完成，动态应用需要一张依赖清单。旧域名可以在观察期重定向到新域名。

Cookie 域配置错误会让用户反复退出。跨域列表遗漏会让 API 请求被浏览器阻止。第三方登录回调未登记会直接拒绝。迁移验收要覆盖这些真实流程，不能只打开首页。

## 费用与续费的记录表

记录域名、注册商、注册日期、到期日、自动续费、续费价格查询日期、支付负责人和恢复联系人。托管费用另记计划名称、计费维度、预算告警与查询日期。不要把促销首年价填成长期成本。账号开启多因素认证，恢复码安全离线保存。域名控制权高于单个网站项目，权限应更严格。

离职或合作结束时更新联系人和支付责任。域名因旧邮箱失效而无法续费，是可避免的运维事故。

| 现象 | 先查位置 | 关键证据 |
| --- | --- | --- |
| 名称不存在 | 权威 DNS | NS 与目标记录 |
| 指向旧站 | DNS 与缓存 | 当前目标、TTL、查询时间 |
| 平台 404 | 平台域名绑定 | 项目、精确主机名、状态 |
| 证书警告 | HTTPS 与 DNS | 证书名称、有效期、解析目标 |
| 页面正常但 API 失败 | 应用配置 | Network 请求 URL 与 CORS |
| 只有部分网络失败 | DNS 传播与地区网络 | 多解析器和多网络结果 |

先按现象进入一层，再查看证据。不要同时删除 DNS、重建项目和换证书。

## 域名截图怎样进入本书

域名与部署平台控制台属于允许推荐视频和当前截图的动态操作。本书只使用实际核对过的当前界面。截图隐藏账号、域名控制验证码、客户编号和无关记录。示例域名使用保留域名，不展示真实用户资产。

每张截图在图注写平台、界面位置与核对日期。界面变更后，正文的输入和预期结果仍应成立。旧截图若无法更新就移除，不用模糊标注假装当前可用。

下线前列出网站、API、邮件、回调和子域依赖。先通知使用者并停止新入口。从第三方服务移除自定义域名，撤销验证和证书绑定，再按计划删除 DNS。平台顺序若有安全要求，遵循当前文档。保留域名可以继续重定向到说明页，防止旧链接被利用。决定不续费前评估品牌与账号找回风险。

删除项目和 DNS 后，从多个网络确认不再指向旧资源。保存下线时间和操作人。

## 什么算本章完成

平台自带地址先通过验收，自定义域名在平台完成绑定，权威 DNS 记录与平台要求一致。HTTP 按设计跳转到唯一 HTTPS 主地址。根域、`www`、证书和常用路径从两个网络检查。域名续费、权限、DNS 记录用途和恢复值已有记录。

面向中国大陆的项目另行核对当前备案、接入与业务规则。本章的全球部署示例不能替代这一步。

一家小工作室把网站迁到新平台。负责人看到旧 DNS 记录很多，删除后只添加了新平台要求的 A 和 CNAME。网站成功，第二天客户邮件全部退回。被删记录中包含 MX 与邮件验证。网站平台不需要它们，邮箱服务却依赖它们。

恢复时先从变更记录找回旧 MX、SPF、DKIM 和 DMARC，按邮箱供应商当前文档核对。DNS 缓存传播后，收发逐步恢复。工作室随后把每条记录标注为网站、邮件、验证或其他服务。下一次迁移只改目标主机名对应记录。

正式迁移流程也增加网站、邮件、登录回调和 API 四组验收。DNS 编辑不再被当作单一网站操作。这个事故没有复杂代码。问题来自把域名视为网页专属资源。实际域名可能同时承载多个系统入口。

## 域名与费用判断要绑定检索日期

AI 可以把平台给出的 DNS 要求整理成待核表，解释查询结果，比较迁移前后记录，并生成不含账号信息的验收清单。它不能凭截图确认你拥有域名，也不应擅自删除旧记录。DNS 修改会影响真实服务，目标和恢复值要亲自核对。

亲自检查域名拼写、权威 DNS、旧记录用途、平台绑定状态、证书和续费。用手机网络与另一网络打开正式地址，确认主地址与重定向。第四卷到这里结束。读者已经能从源代码得到静态产物，选择发布路线，读部署日志并接入域名。下一卷进入后端与数据库，解释动态功能为什么需要另一组长期服务。
