# 契约、性质、模糊、变异与回归测试

AI 为课程 App 改了保存进度接口，普通单元测试全部通过。上线后，旧版手机因响应字段缺失而崩溃，异常长的标题耗尽了解析器内存，负数进度也被保存。修复几个月后，同类问题再次出现。

这些错误需要不同的测试依据。契约测试守住组件间约定，性质测试检查一类输入都应满足的规律，模糊测试寻找崩溃与越界输入，变异测试检查断言能否识别被故意改坏的代码，回归测试则保存已经发生的错误。它们互相补充，任何一种都不能单独覆盖全部风险。

## 示例测试的边界

常见测试给函数一个输入，再断言一个输出。

```
def test_save_progress():
    result = save_progress(user_id="u1", course_id="c1", seconds=60)
    assert result.seconds == 60
```

它只证明这一组输入在当前环境得到预期结果，没有覆盖负数、极大值、重复请求、并发更新、数据库超时和旧版客户端。覆盖率也只说明代码被执行过。一条测试调用保存函数却不检查数据库状态，照样可以覆盖很多行。

检查测试时，暂时遮住名称，只看准备条件、执行动作和观察结果。只断言没有抛异常，往往会放过业务错误。异步测试还应等待业务完成条件，固定睡眠会让机器速度左右结果。

## 契约测试守住接口约定

契约是消费者与提供者对请求、响应或消息达成的可执行约定。它可以描述方法、路径、必要字段、类型、状态码和示例交互。Pact 一类消费者驱动契约工具会记录消费者实际依赖的交互，再让提供者验证真实实现。

旧版 App 依赖整数型 `progress_seconds`，新后端把它改成 `position`。后端自身测试可能全绿，旧版消费者契约会立即失败。提供者可以在兼容期同时返回新旧字段，等旧版使用率降到允许范围再删除旧字段。

契约测试只覆盖交互边界。它无法证明真实数据库迁移完整，也无法发现生产权限配错。OpenAPI 或 GraphQL Schema 描述允许的结构，消费者契约记录具体消费者依赖的交互。消息契约还应包含事件版本、幂等键、时间语义和重复处理规则。

## 性质、模糊与变异测试

性质测试描述输入范围和始终成立的不变量，再由工具生成大量样本并缩小失败案例。课程进度可以检查保存值不小于零、不超过课程总时长，同一幂等键不会产生两条记录，序列化往返后业务字段保持一致。

性质必须包含允许例外。进度通常不下降，用户主动重置课程时却可以下降。随机生成一万组数据也不等于穷尽所有输入。失败后应保存最小样本、随机种子、工具版本和环境，并把样本加入固定回归测试。涉及创建、保存、重置和删除的顺序问题，可以用状态机性质测试。

模糊测试持续改变文件、URL、JSON 或协议帧等外部输入，观察崩溃、越界、超时、内存错误和未处理异常。好的目标范围窄、运行快，对同一输入尽量产生相同结果，并能接受空、长和畸形数据。没有崩溃不代表结果正确。失败样本还可能包含用户数据，保存 CI 工件时要限制访问。

变异测试故意把 `>=` 改成 `>`、反转条件或删除函数调用，再运行原测试。测试仍然通过，说明相关断言可能没有观察到业务结果。存活变异体也可能与原行为等价，因此需要人工判断。变异测试成本较高，优先用于权限、金额、状态机和公共库。

## 回归样本先证明能复现

线上出现某个 Unicode 组合导致保存失败，应先保留脱敏后的最小输入、环境、错误与预期。修复前测试必须失败，修复后才通过。若它在旧版本上也通过，就没有抓住原问题。

一场故障可能需要多层回归。解析器保存失败样本，接口保存错误响应，端到端测试确认界面处理结果。真实时间、随机数、第三方接口和共享账号会让样本不稳定，需要隔离或固定。重复且过时的回归测试也应清理，删除前确认风险已由更稳定的测试覆盖。

## 一次接口修改怎样组合测试

假设 AI 要把整数秒扩展为带小数的毫秒。契约测试确认旧客户端仍收到整数秒，新客户端能读取新增字段。性质测试生成边界值，检查规范化、序列化往返和幂等。模糊测试攻击 JSON 解析、数字格式与深层嵌套，变异测试改动比较符和权限分支，历史上的负数、溢出与重复提交进入回归集合。

随后在真实数据库、一版旧 App 和一版新 App 上跑少量端到端测试。每次保存代码时运行快速单元测试、少量性质样本和当前模块契约。拉取请求增加提供者契约、数据库集成、迁移和关键回归。长时间模糊、变异与状态机测试可以定期运行，发布前再检查真实构建产物和环境。

测试目录应写明命令、环境、预计时间和数据清理方式。报告至少记录代码提交、命令、环境、样本或种子、耗时与跳过项。CI 变绿后还要确认任务确实执行，没有因条件表达式被跳过，也没有把失败设成允许继续。

让 AI 为每项测试说明它试图推翻什么，再故意改坏一处业务条件。测试没有失败时，先修断言，不能把绿色结果当作完成证据。
