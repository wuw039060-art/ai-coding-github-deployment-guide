# PocketBase 与 Supabase 的边界选择

PocketBase 和 Supabase 都能很快提供数据库、认证、接口与管理能力。选型仍要落到写入模式、迁移、备份、权限、运维能力和故障后果。软件版本、托管能力与兼容承诺会变化，实施前应重新核对官方文档。

## 先区分三种责任

PocketBase 把嵌入式 SQLite、实时订阅、认证、管理界面和接口放在一个可独立运行的程序里，也支持用 Go 扩展。它适合先用原型、局域网工具和边界清楚的小项目评估，部署与本地复现路径较短。截至 2026 年 9 月 23 日，[官方文档](https://pocketbase.io/docs/)仍提示 1.0 之前不保证完整向后兼容，不建议用于生产关键应用，除非维护者接受阅读变更记录并不时手工迁移。SQLite 本身的成熟度不能替 PocketBase 作出兼容承诺。

Supabase 托管平台以 Postgres 为中心，组合认证、接口、实时通信、存储与函数。平台承担不少基础设施工作，项目仍要设计表结构、行级权限、密钥使用、数据生命周期和费用控制。

自建 Supabase 是另一份责任表。服务器加固、各服务配置、Postgres 维护、扩容、备份、灾难恢复、监控与在线时间都由使用者负责，托管版的部分能力也可能不存在。选型时要先决定托管或自建，再比较数据和应用边界。

## 部件少也要验证恢复

PocketBase 部件紧凑，数据目录、上传文件和迁移目录比较容易定位。反向代理、TLS、系统服务、日志与恢复依然要配置。复制 SQLite 文件也不能自动成为可靠备份，活跃写入时的一致性、文件同步和新机器上的权限都需要演练。

SQLite 能支撑许多正式应用。边界主要来自并发写入、长事务、可用性目标和扩容方式。项目若要求多节点高可用、复杂分析或大量并发写入，应以真实负载试验，不能只看启动速度。

Supabase 提供关系约束、SQL、数据库迁移和细粒度行级权限，也引入更多组件与概念。前端可用的公开密钥不允许绕过权限策略，服务角色密钥和 Secret Key 不能放进客户端。[Supabase 数据库备份说明](https://supabase.com/docs/guides/platform/backups)明确指出，数据库备份不包含 Storage 中的文件对象，只包含相应元数据；文件必须另行备份。恢复数据库也不会自动恢复邮件和付款系统的外部状态。

最小权限练习可以创建两个用户与两行各自拥有的数据，确认双方只能读写自己的记录，再测试未登录请求和越权请求。成功写入只能证明写入路径，无权限访问被拒绝才能说明边界生效。

## 从恢复与退出要求倒推

先列出不能丢失的状态。账号、业务记录、上传文件、权限策略、数据库函数和外部服务标识可能位于不同位置，再为它们写出允许丢失的数据量与恢复时间。

在隔离环境创建文本与文件，生成备份，破坏测试实例，再恢复到新位置。逐项检查账号、权限、记录、文件、时间字段和应用连接。备份文件存在只能证明复制完成，恢复成功才说明它能使用。

PocketBase 升级前要保存数据与迁移文件，在副本阅读并执行对应版本变更。Supabase 虽以 Postgres 和常见导出格式提供可移植基础，迁移仍可能涉及认证哈希、对象存储、实时订阅、函数、扩展和平台配置。导出表数据无法代表整个应用已经迁走。

退出清单应说明数据库和文件怎样迁移、用户身份怎样处理、权限规则存在哪里、客户端要更换哪些地址与密钥，以及停机窗口、回滚点和验收人。退出成本不会自动否定平台，它让团队看见未来迁移要做什么。

## 用同一条业务链试验

为两个候选方案实现相同流程。用户登录后创建一条自己的记录并上传文件，第二个用户无法访问，备份还能在新环境恢复。记录搭建时间、配置、权限规则、日志位置、升级步骤和恢复耗时。

再安排两个受控失败。撤销用户权限，检查接口和界面是否拒绝；让测试存储暂时不可写，确认系统没有返回虚假成功。故障只在隔离环境和可删除数据上进行。

结果表应填写谁负责、怎样验证、出错后去哪里看和多久能恢复。管理界面里的高权限访问不能代替普通客户端的权限测试。根据角色、对象和动作建立权限矩阵，再从真实客户端运行自动测试。

性能比较同样要使用相同数据规模、读写比例、查询、索引、硬件和网络。逐步增加负载，同时观察延迟分布、错误、CPU、内存、磁盘与连接，结束后核对记录数量和权限，防止系统靠丢请求换取好看的延迟。

个人原型和可在本机运行后端的工具常值得先试 PocketBase；它是后端服务，不能仅因使用 SQLite 就假定移动客户端自动具备离线同步。需要关系数据、托管服务且缺少数据库运维人员的小型正式应用，可以评估托管 Supabase，并验证套餐限制与恢复责任。受监管或高可用系统还要评审审计、隔离、灾难恢复与支持责任，快速入门体验不足以承担这类决定。

选型记录要注明检索日期、价格与政策来源、支持渠道和重新评审条件。费用、数据量、地区要求或兼容承诺发生变化时，重新运行关键试验。
