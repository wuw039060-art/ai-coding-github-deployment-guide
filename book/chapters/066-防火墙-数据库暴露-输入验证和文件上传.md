# 防火墙、数据库暴露、输入验证和文件上传

安全不能等上线后再补口号。它体现在每个入口公开给谁、每个请求由谁判断、每个文件能否被安全处理。很多小项目出事，原因很普通。数据库直接暴露公网，上传目录能执行脚本，服务端相信了客户端传来的角色。

## 先列出真正需要公开的入口

公开入口越少，排错和防护越简单。一个普通 Web 应用通常只需要 80 和 443 对公网开放。SSH 只给管理员使用，可以限制来源、使用密钥登录并关闭密码登录。数据库、Redis、管理面板、对象存储控制台和 Docker socket 通常不应直接暴露给公网。

在服务器上检查监听端口和防火墙状态时，先读，不急着改。

```text
sudo ss -lntp
sudo ufw status verbose
```

若确实要开放端口，先确认用途、来源、认证、日志和撤销办法。不要为了“先试一下”把数据库端口开给全网。临时入口要有到期时间，事后关闭。

云平台还会有安全组、负载均衡、防火墙、平台访问控制和应用自身认证。服务器里关了端口，不代表云安全组没开。应用有登录，也不能替代网络边界。两层都要看。

## 防火墙不等于应用授权

防火墙控制谁能连到入口，应用授权控制连进来以后能做什么。只允许公司 IP 访问管理后台，可以降低暴露面。用户登录后能否删除订单，仍要由应用根据身份和资源所有者判断。

反过来也一样。应用有权限校验，不代表数据库可以裸露公网。数据库协议、密码爆破、未修漏洞和配置错误都会扩大风险。数据库应放在私有网络、受控安全组或托管平台内部连接中。公开只读数据也应通过应用 API 暴露，便于限流、审计和格式控制。

错误页面也会暴露信息。生产环境不要把完整堆栈、SQL、环境变量、服务器路径和密钥片段展示给用户。用户需要简短提示和支持编号，维护者通过日志查细节。

管理入口要单独处理。后台、数据库管理、对象存储控制台、任务队列面板、监控面板和日志平台，不应该和普通用户入口使用同一套松散规则。能加单点登录、二步验证、IP 限制和审计日志，就不要只靠一个弱密码。

默认账号和示例口令要清理。很多工具启动后带有 admin、test、password 之类默认入口。上线前检查安装文档和容器镜像说明。若必须保留初始化入口，完成初始化后关闭或限制来源。

## 输入验证在服务端执行

前端表单校验是用户体验，服务端校验是安全边界。价格、角色、所有者 ID、库存、折扣、文件类型、数量和状态流转，都不能只相信客户端。攻击者可以绕过页面直接发请求。

服务端验证包括类型、范围、长度、枚举、权限、状态和业务规则。订单金额由后端按商品和优惠重新计算。删除资源时，后端检查当前用户是否有权删除。上传文件时，后端检查大小、类型、内容和后续处理。

SQL 注入、命令注入和模板注入本质上都是把用户输入当成代码执行。使用参数化查询、受控命令参数和模板转义，不把字符串拼进 SQL 或 shell。AI 生成代码时尤其要看这点，它为了快可能写出能跑但危险的拼接。

验证和清理要分开。验证判断输入是否允许，清理把输入转成安全格式。不要指望把字符串里危险字符删掉就能处理所有情况。不同上下文有不同规则。HTML、SQL、URL、文件名、Shell、JSON 和 Markdown 需要不同转义。最稳的办法是使用成熟库和参数化接口。

业务状态也要验证。订单已支付后不能再次改价，已删除资源不能继续分享，普通成员不能把自己改成管理员。客户端传来的状态只能当请求意图，不能当事实。服务端要从数据库读取当前状态再判断。

## 文件上传同时处理内容和去向

文件上传要同时考虑保存和后续使用。先限制大小、类型、数量和频率。再检查文件内容，不只相信扩展名和 Content-Type。图片要重新编码或去除危险元数据。压缩包要防止路径穿越和解压炸弹。PDF、Office 文档和 SVG 也可能带来脚本、链接和隐私问题。

上传文件的保存位置要与执行环境分开。用户上传目录不应被 Web 服务器当作可执行代码目录。对象存储地址也不要长期公开。更稳的做法是后端检查权限后生成短期访问 URL。

文件名由用户提供时，只当展示文本。保存时生成内部 ID，避免覆盖、路径穿越和特殊字符问题。下载时设置合适的 Content-Disposition 和 Content-Type，避免浏览器把用户文件当页面执行。

图片处理也可能消耗资源。超大图片、异常 EXIF、动画图片和压缩炸弹会让服务器内存飙升。处理前先限制尺寸和字节数，处理任务放入队列，超时后返回可理解状态。不要让用户上传一次就阻塞整个 Web 进程。

杀毒扫描或内容审核需要异步状态。文件刚上传不一定立刻可公开。可以先标记为 pending，扫描通过后再允许下载或展示。扫描失败要清理对象和数据库记录。审核队列本身也要有权限和日志。

## 代理限制和应用限制配合

代理、应用和对象存储都可能有大小、超时和并发限制。代理允许 100 MB，应用只允许 10 MB，用户会看到上传失败。应用允许大文件，代理先返回 413，后端日志可能完全没有请求。排查时先看哪一层拒绝。

限流也要分层。登录、注册、上传、搜索、AI 调用和支付回调需要不同策略。IP 可能多人共享，账号也可能被盗。限流触发后，返回可理解错误，并让客户端退避。不要让前端每毫秒重试，把小故障变成流量放大。

下载远程 URL 会引入 SSRF 风险。用户提交一个图片地址，后端去下载时，攻击者可能让服务器访问内网地址、云元数据服务或管理端口。解决办法包括优先使用允许列表、限制协议、校验解析出的全部地址、禁止内网和本机范围、禁止自动跟随未经校验的重定向、设置超时与大小限制，并使用隔离网络。域名解析结果可能变化，不能只在提交 URL 时检查一次；具体校验应按 [OWASP 的 SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)设计。

WebSocket 和长连接也要限制。聊天、实时看板和协作编辑常使用长连接。连接数、消息大小、鉴权续期、心跳和断线重连都要有规则。没有限制的重连会在服务短暂故障后形成风暴。后端返回限流或维护状态时，客户端应退避。

后台任务入口也不能忘。管理脚本、Webhook、队列消费者、定时任务和内部 API 有时绕过普通路由。支付回调、GitHub Webhook、对象存储通知要校验签名和来源。内部 API 若被公网访问，也要有认证、限流和日志。

## 一个被错误开放的数据库假设情境

设想一个团队为了让本地工具连生产 PostgreSQL，临时把数据库端口开到公网，并允许所有来源。测试结束后没人关。几周后，数据库出现大量失败登录和异常连接。应用本身没有新漏洞，但网络边界已经暴露。

正确处理先撤回公开访问，轮换数据库密码，检查账号权限和连接日志，再确认是否有异常读写。随后改用 VPN、堡垒机、云平台私有连接或短期授权。把“临时开放”写进变更记录，并设到期提醒。

这个案例也说明，安全事故不总来自代码。防火墙、安全组、数据库账号、备份链接、对象存储桶和日志平台都可能成为入口。

对象存储公开也很常见。开发者为了让图片能访问，把整个 bucket 设为公开。短期看页面正常，长期会把用户上传、备份或未审核文件一起暴露。更安全的方式是公开只读静态资源桶，用户文件通过后端鉴权或短期 URL 访问。每个桶写清用途，不把备份和用户公开资源混放。

防护还要配合日志。限制入口后，仍要记录被拒绝请求、异常登录、上传失败、限流触发和权限拒绝。日志不用于羞辱用户，它帮助你发现配置错误和攻击趋势。记录时继续脱敏。

## 安全默认值

新项目先采用保守默认值。管理入口不公开，数据库只允许应用访问，文件默认私有，错误默认给短编号，日志默认不打印秘密，上传默认限制大小和类型。需要扩大权限时，再写原因和撤销时间。

默认值还要写进模板。新建后端服务时，模板里包含鉴权中间件、请求大小限制、统一错误处理、参数化查询示例和日志脱敏。新建对象存储桶时，模板里默认私有。新建服务器时，模板里默认关闭密码登录，并只开放必要端口。

AI 生成代码时，也要给它安全默认值。权限不能只放在前端，SQL 应使用参数化查询，日志不得记录令牌，上传目录也不能执行文件。生成后仍要人工审查。AI 不知道你的生产边界，除非你把边界写给它。

## AI 可以审查边界

把项目交给 AI 做安全审查时，给它架构图、脱敏配置、路由列表、权限规则、文件上传流程和最近改动。不要给真实密钥、生产数据和可直接登录的账号。

让 AI 回答具体问题。哪些入口对公网开放。哪些请求只在前端校验。文件上传是否检查内容和大小。数据库是否只允许应用访问。日志是否泄露敏感信息。它给出的建议要落到配置、代码、测试和操作记录中。

最终检查。

- 公开端口和云安全组是否都有记录。
- 数据库、Redis、Docker socket 和管理面板是否避免公网暴露。
- 服务端是否重新验证价格、角色、所有者和状态。
- 文件上传是否限制大小、类型、内容和保存位置。
- 远程 URL 下载是否防 SSRF。
- 错误页面和日志是否避免泄露秘密。

安全检查还要覆盖客户端。前端隐藏按钮、小程序页面跳转限制、App 本地角色字段，都不能代替后端授权。移动端和小程序尤其容易把 AppID、包名、Bundle ID 当成可信身份。它们能说明请求来自哪个客户端形态，不能证明当前用户有权执行某个业务动作。

如果某个功能“只有内部人员知道入口”，也要当作公开入口审查。URL、二维码、小程序路径、深层链接和旧版本 App 都可能流出。没有权限校验的隐藏页面，迟早会被访问。
