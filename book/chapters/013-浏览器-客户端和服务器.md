# 浏览器、客户端和服务器

在浏览器地址栏输入一个网址，几秒后页面出现；这个过程至少有两个参与者；浏览器主动请求内容，提供内容的程序返回响应。主动发起请求的一方叫客户端，接收请求并提供服务的一方叫服务器。浏览器是一种客户端。手机 App、桌面程序和命令行工具也可以是客户端。服务器则是一种角色，也可以指运行服务端程序的远程计算机。先把角色与设备分开，许多网络错误就会容易定位。

图中从浏览器开始。DNS 查询返回服务入口，浏览器完成连接并发送 HTTP 请求。CDN 或反向代理可以直接返回缓存文件，也可以把动态请求转给后端。后端访问数据库和存储，再把响应逐层送回浏览器。

## 浏览器帮用户完成哪些工作

浏览器接收 URL，找到目标服务，发送网络请求，读取响应，再把 HTML、CSS、JavaScript、图片和字体等资源组织成页面。它还管理标签页、缓存、Cookie、下载、权限与安全提示。

MDN 对网页加载过程的说明指出，浏览器取得 HTML 后，会解析其中引用的样式、脚本和媒体，再继续请求这些资源。一个页面看起来像一次打开，Network 面板里可能有几十个请求。

HTML 说明页面结构，例如标题、段落、表单和链接；CSS 控制布局与外观；JavaScript 处理交互与动态数据；浏览器分别解析它们，再把结果绘制到屏幕；页面只显示一半时，不要直接判断服务器整体宕机；HTML 可能成功，图片路径却 404；CSS 可能被浏览器扩展阻止；JavaScript 可能在执行时抛出错误；每一种资源都有自己的请求和状态。

Client 译为客户端；它通常代表用户或另一个系统向服务端发起请求；浏览器访问网页时是客户端；Flutter App 调用登录 API 时也是客户端。同一个程序可以在一段关系中当服务器，在另一段关系中当客户端。你的后端接收浏览器请求时是服务器。它随后向邮件服务或 AI API 发请求时，又成为这些服务的客户端。

这一区分对排错很有帮助。用户点击“生成摘要”，浏览器请求自己的后端，后端再请求 AI 服务。浏览器收到 500，只能说明后端返回服务器错误。真正原因可能是后端密钥失效、上游超时或输入处理出错。

客户端持有用户界面与当前输入，不能被服务端完全信任。用户能修改浏览器请求，也能使用另一个程序直接调用 API。价格、权限、所有权和支付状态等规则要由服务端重新检查。

## 服务器也可以只是一段程序

Server 译为服务器。它可以表示一台远程计算机，也可以表示在某个端口等待请求的程序。说“服务器坏了”时，要继续问是机器不可达、入口代理失败、应用进程停止，还是数据库异常。本地开发服务器也是服务器程序。运行 `npm run dev` 后，它可能监听 `localhost:5173` 并返回网页。它只为开发提供内容，不适合作为公共生产服务。

一台 VPS 可以同时运行多个服务。Caddy 或 Nginx 接收 80 与 443 端口的 Web 请求，后端应用监听本机 3000，数据库监听另一个仅内部可见的端口。入口代理根据域名与路径把请求转给正确程序。

托管平台也运行服务器，只是把机器管理隐藏在控制台后。用户仍通过请求与响应使用服务，开发者主要看到部署、函数、日志与配置。

假设浏览器访问一个公开作品页。域名解析后，浏览器与托管服务建立连接，请求 `/index.html`。服务器找到现成文件并返回。浏览器解析 HTML，发现 `/styles.css` 和 `/images/photo.webp`，于是分别请求。服务器继续返回两个文件。浏览器应用样式并显示图片。

这个流程中，服务器没有根据用户身份生成不同内容。文件已经准备好，所以称为静态请求。CDN 可以把文件缓存到更接近用户的位置。如果图片返回 404，HTML 与 CSS 仍可能正常。打开 Network，筛选图片请求，检查 URL、状态和 Response。路径大小写错误、文件未进入构建产物或缓存引用旧名称都可能导致。

## 一次动态请求

用户访问 `/account`。浏览器请求页面或 API，并带上会话标识。服务端程序读取请求，验证身份，查询数据库，再把账户数据返回。MDN 的客户端与服务器概览用静态资源和动态资源对比这一过程。

服务端可以直接生成 HTML，也可以返回 JSON，让浏览器 JavaScript 生成界面。两种方式都会在服务端处理请求；框架名称不是判断动态与否的唯一依据；若数据库连接失败，服务端可能返回 500；若用户没有登录，可能返回 401；若用户已登录但无权访问，可能返回 403；状态码的具体含义会在第十五章展开。

动态服务的响应可能因用户、时间和数据不同。缓存设置要更谨慎，不能把甲用户账户页缓存后交给乙用户。

浏览器运行在用户设备中，代码和请求可以被查看与修改。若把数据库高权限账号放进浏览器，任何用户都可能取得。后端在受控环境保存数据库凭据，并提供范围明确的 API。浏览器发送“读取我的订单”，后端从登录身份得到用户编号，查询属于该用户的数据。

不能只相信浏览器提交的 `user_id`。攻击者可以把它改成别人编号。后端要根据已验证身份和权限决定允许访问哪条记录。部分后端即服务允许浏览器直接使用公开客户端密钥连接数据 API。安全依赖服务端执行的行级权限规则和受限公开角色。高权限服务密钥仍不能进入客户端。

## 请求与响应是一次对话的两个方向

Request 译为请求，包含方法、URL、请求头和可选正文。Response 译为响应，包含状态码、响应头和可选正文。浏览器请求首页时常使用 GET。提交表单可能使用 POST。更新与删除还会使用其他方法。方法表达意图，服务端仍要验证权限和数据。

请求头可以包含接受的内容类型、来源、缓存信息与身份凭据。响应头说明内容类型、缓存规则和安全策略。正文可能是 HTML、JSON、图片或空内容。一次请求成功到达服务器，服务端也可能拒绝。网络连接成功与业务操作成功不是一件事。Network 面板能同时显示传输和应用层结果。

浏览器会根据协议、主机和端口判断 Origin，也就是源。`https://example.com` 与 `https://api.example.com` 主机不同，属于不同源。端口不同也会改变源。网页脚本跨源读取响应时，浏览器会执行同源策略与 CORS 规则。服务端需要明确允许合适来源。配置错误时，服务器可能已经返回响应，浏览器仍阻止页面脚本读取。

CORS 不是登录和权限系统。允许某个来源发请求，不能证明请求者身份。API 仍要认证、授权和验证输入。初学阶段遇到 CORS 错误，先记下网页 Origin、请求 URL、方法、状态和 Console 完整提示。不要使用关闭浏览器安全功能的启动参数作为长期解决。

## 浏览器缓存会让客户端保留旧结果

浏览器可以缓存图片、脚本和响应，减少重复传输。开发者发布新版本后，旧缓存可能暂时继续使用。只有一台设备显示旧样式时，用无痕窗口、另一设备和 Network 面板形成对照。查看响应是否来自 memory cache、disk cache 或 Service Worker。

不要默认让用户清除全部浏览数据。它会退出其他网站并丢失本地状态。先确认缓存确实是原因，再清理当前站点或使用正确版本化资源。服务器可通过响应头控制缓存。静态文件常用带内容哈希的文件名长期缓存，HTML 更频繁重新验证。具体策略要与部署方式匹配。

Cookie 是浏览器为网站保存并按规则随请求发送的小段数据。它可以存会话标识、偏好或其他有限信息。服务端会话的真实数据通常留在服务器。Local Storage 与 IndexedDB 也能在浏览器保存数据。它们不会自动随每个 HTTP 请求发送。清除站点数据、使用不同浏览器或更换设备后，内容可能不同。

用户说“登录状态丢了”，可能是 Cookie 过期、浏览器阻止、服务端会话失效或后端令牌验证失败。先看请求是否携带预期凭据，以及响应设置了什么。详细认证与缓存会在第十六章讲。本章只确认它们属于客户端与服务器共同形成的状态。

## 服务器如何服务多个用户

Web 服务器会连续处理来自不同客户端的请求。每个请求都带有自己的连接、头部和正文。服务端不能把一个用户的临时数据放进所有请求共享的全局变量。并发请求可能同时修改同一数据。例如最后一张活动名额被两个人同时预约。服务端和数据库要用事务、约束或其他并发控制保证最终规则。

应用在多台实例上运行时，请求可能落到不同机器。本地内存中的登录状态无法天然共享。会话存储、数据库或可验证 Token 需要适应这种部署。个人项目访问量很小时，也应避免明显的数据串用。先使用数据库唯一约束与服务端权限，再考虑更复杂扩容。

命令行 `curl` 可以发送 HTTP 请求，适合检查 API。Postman 等工具提供图形界面。手机 App 使用系统网络库。监控服务也会定期请求健康地址。同一 API 在浏览器失败、curl 成功，可能与 CORS、Cookie、代理或浏览器扩展有关。两者都失败，更可能是服务端、网络或请求本身。

App 能发出浏览器不允许的跨源请求，因此服务端不能依赖浏览器 CORS 防止所有恶意调用。身份与权限仍由后端验证。机器人和搜索引擎也是客户端。公开网页要考虑 robots 设置、语义 HTML 和访问频率。robots 文件是一种约定，不是访问控制。

## 浏览器标签页与后端进程的寿命不同

用户关闭标签页后，浏览器不再显示页面。已经发送到后端的请求或后台任务可能继续执行。重复打开页面后再次提交，可能产生两份操作。服务端为创建订单、付款和任务提供幂等机制。客户端显示明确状态，避免用户在等待时连续点击。关闭页面后重新进入，可以根据任务 ID 查询结果。

浏览器进入后台时，手机和桌面系统会限制计时器与网络。依赖每秒轮询的进度条可能暂停。实时连接也可能断开。回到前台后，客户端重新获取权威状态。不能假设离开期间的每一条事件都被接收。

刷新页面会重新加载浏览器前端，不会重启服务器。清除浏览器缓存也不会修复后端数据库连接。重启后端会中断正在处理的请求。多实例平台可以逐步替换，用户未必感知。单台 VPS 重启服务会有短暂停机。

部署新前端通常生成新静态资源。旧标签页仍运行旧脚本，直到刷新。后端需要在一段时间内兼容旧客户端。排错时写清“刷新页面”“重新部署前端”“重启后端进程”“重启服务器”中的哪一项。它们影响范围完全不同。

## 用户代理信息只能作为线索

浏览器请求常包含 User-Agent 等客户端信息。它可以帮助识别浏览器系列和系统，内容可能被简化或伪造。不要用 User-Agent 作为身份认证。兼容性优先检测实际功能，并对不支持行为提供替代。

只有某个浏览器版本失败时，用同一账号、网络和 URL 做对照。检查浏览器特性、扩展、隐私设置和缓存。收集客户端信息要遵守隐私政策，避免为了调试建立不必要的设备指纹。

服务端渲染会在服务器生成初始 HTML，浏览器收到后先显示内容，再由 JavaScript接管交互。客户端渲染则让浏览器脚本请求数据并生成大部分页面。服务端渲染有利于首屏内容和搜索理解，增加服务端运行与缓存复杂度。客户端渲染部署静态文件简单，脚本失败时可能空白。

许多框架混合两种方式，还能在构建时生成静态页面。判断项目时查看构建产物与部署说明，不按框架名称推断。故障只出现在首次打开、刷新或客户端导航之一时，渲染路径差异是重要线索。

## 浏览器权限由用户设备决定

网页访问相机、麦克风、位置、通知和剪贴板时，浏览器会根据安全上下文与用户授权决定。服务器不能替用户点击允许。权限被拒后，页面应提供说明和替代输入。不要反复弹出请求。用户可以在站点设置中撤销。

HTTPS 往往是敏感能力的前提，本地开发可能有特殊例外。生产 HTTP 页面无法通过改 JavaScript 绕过。权限状态属于当前浏览器与站点。换设备或子域后需要重新判断。

反向代理面向用户接收请求，应用服务器执行后端代码。代理可以处理 TLS、压缩、静态文件与上游转发。用户访问 `https://example.com/api/tasks`，代理把 `/api` 转给本机 3000 端口。应用只监听回环地址，不直接暴露公网。代理返回 502 时，查上游地址、端口和应用状态。应用返回 500 时，代理通常只是转交，查应用日志。

配置重载前验证语法。错误代理配置会影响多个站点，修改要备份并准备回滚。

## 健康检查只检查指定行为

平台会请求 `/health` 判断实例是否可接收流量。简单健康检查只证明进程响应，深度检查可能连数据库与外部依赖。检查过浅，应用无法查数据库仍显示健康。检查过深，邮件服务短暂故障可能让整个 API 被移出。

将存活与就绪分开。Liveness 判断进程是否需要重启，Readiness 判断是否接流量。具体名称按平台。健康地址不返回秘密和完整配置，限制频率并记录版本。

一个标签页崩溃，其他用户正常，先查浏览器内存、扩展与特定输入。服务器故障通常影响更多客户端。页面处理巨大 JSON 或图片会耗尽设备内存，服务器已经成功返回 200。Network 的响应大小和浏览器任务管理器提供线索。

后端内存耗尽时，多个请求 5xx，服务可能重启。平台运行日志与内存指标会显示。同一句“页面崩了”要先问影响人数、设备和状态码。

## 服务端渲染错误为什么仍有网页响应

服务端生成 HTML 时发生异常，框架可以返回带错误页面的 500。浏览器能显示文字，不表示状态成功。前端路由的自定义 404 页面也可能错误返回 200。搜索引擎和监控会误判。状态应与含义一致。

查看主文档状态，不根据页面外观判断。错误页提供 Request ID，不展示堆栈。静态托管平台自己的错误页可能与应用风格不同，Response 与 Headers 能识别来源。

| 角色 | 主要工作 | 典型日志 |
| --- | --- | --- |
| 静态文件服务器 | 返回 HTML、CSS、脚本与图片 | 路径、状态、传输大小 |
| 反向代理 | TLS、域名路由、转发上游 | 上游地址、502、耗时 |
| API 应用 | 认证、权限、业务规则 | Request ID、错误、业务结果 |
| 数据库服务器 | 查询、事务、约束 | 连接、慢查询、失败事务 |
| 工作进程 | 处理队列中的慢任务 | 任务 ID、重试、结果 |
| 实时服务器 | 管理长连接与订阅 | 连接、频道、断开原因 |

小项目可以把多个角色放在一台机器，日志与责任仍不同。看到“服务器”时继续问角色。

## 从用户报错追踪一次请求

用户记录北京时间 14 点 32 分，点击保存后收到 Request ID `req-test-42`。Network 显示 PATCH `/api/profile` 返回 500。入口日志用 ID 找到上游状态和耗时。应用日志同一 ID 显示数据库唯一约束。数据库中另一用户已经占用昵称。

后端把冲突改为 409 和稳定错误码。前端在昵称字段旁提示已被使用。再次测试时不再显示笼统 500。追踪材料不用密码、Cookie 和完整用户资料。ID、时间、路径与测试账号足够关联。

Web 前端可以把构建版本放入公开配置，App 发送版本号。后端日志记录版本，帮助发现只有旧客户端失败；版本信息不能由客户端决定权限；攻击者可以伪造；它只用于兼容与诊断。错误监控事件包含前端提交哈希和 Source Map 版本。部署回滚后，客户端缓存可能仍混用旧资源，版本字段能识别。

隐私上不需要生成永久设备指纹。使用应用版本、浏览器大类和请求 ID 即可。

## 本章验收清单

能说出浏览器为什么是客户端，服务器为何既指设备又指程序。能沿图指出 DNS、入口、应用和数据库。能用 Network 区分主文档、静态资源和 API。知道刷新页面不会重启后端。遇到单用户故障先比较客户端状态，遇到全局 5xx 再查公共服务。任何请求材料都先脱敏。

这些能力足以进入后续部署。服务器进程管理和代理配置会在第六卷实操。

Web Worker 可以在页面主线程之外运行 JavaScript，避免大量计算阻塞界面。Service Worker 位于页面与网络之间，支持离线缓存、推送等能力。它们仍在用户设备和浏览器安全范围内，不能持有后端秘密。关闭浏览器或系统回收资源后，运行可能停止。

Worker 与页面通过消息通信，传递大对象也有成本。错误出现在专门线程的 Console 来源中。Service Worker 更新有独立生命周期。旧 Worker 控制已有标签页，新版本等待激活时，用户可能混用资源。更新策略要测试。

## CDN 也是用户眼中的服务器

静态请求命中 CDN 时，源站完全没有收到。CDN 作为当前请求的服务器角色直接响应。响应头 Age 与平台缓存标识可提供线索。源站日志空白不表示用户没有访问。CDN 找不到源站时又成为客户端，向源站请求失败并向用户返回 5xx。同一组件在两段关系中角色不同。

故障报告要写“用户到 CDN”或“CDN 到源站”，不要只写服务器连接失败。

浏览器可能预加载资源、恢复中断连接或根据页面提示预取。服务端不能假定每个请求都来自明确点击。GET 保持无副作用。创建和付款使用防重复设计。分析日志区分预取与真实交互时，以浏览器和协议证据为准。

页面声明过多 Preload 会抢占关键资源。Network Priority 与 Waterfall 能观察。用户取消导航后预取资源可能仍下载，移动流量与性能要测量。

## 一个完整故障例子

用户打开商店首页正常，点击“我的订单”后一直转圈。Network 显示 `/api/orders` 返回 502。Console 只有前端根据失败响应打印的错误。首页资源由静态托管提供，因此能打开。订单请求经过入口代理转到后端，502 表示入口没有从上游得到正常响应。维护者转向后端服务状态与代理日志。

后端日志显示进程启动失败，原因是数据库变量名拼错。修正变量并重新部署后，API 返回 200。最后在真实账户验证只返回自己的订单。这个例子从用户界面进入，经 Network 缩小到 API，再由代理与运行日志找到后端。清浏览器缓存不会修复变量名。

## 最小观察练习

打开一个无敏感信息的公开网页。按浏览器当前方式打开 DevTools，进入 Network，刷新页面。选择主文档请求，记录 Request URL、Method、Status 与 Content-Type。再选择一张图片或脚本，比较 URL 与状态。

成功结果是看到一个页面由多个请求组成。不要在 Console 粘贴陌生代码，也不要修改网站数据。第十九章会给出完整 DevTools 操作。

AI 可以根据 URL、状态码、Network 导出和服务日志画出请求路径，判断下一处检查位置。它也可以把客户端、入口、后端和数据库分开列出。提供材料时删除 Cookie、Authorization 头和个人响应数据。AI 看到浏览器错误，不能直接证明服务器内部原因，仍需要对应日志。

真实账户权限、用户数据、生产日志和浏览器安全提示需要亲自确认。关闭同源保护、忽略证书错误或公开内部端口都不能作为便捷修复。下一章会拆开 IP、域名、DNS、端口和 URL。它们共同回答浏览器要去哪里，以及请求交给哪个入口。
