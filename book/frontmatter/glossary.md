# 术语索引

本索引给第一次出现过的核心英文术语一个稳定中文解释。定义只覆盖本书所需范围，读者可以沿章节链接回到完整上下文。

## A

### AAB

Android App Bundle 的缩写，是提交到 Google Play 的发布包格式。Play 会根据设备从它生成适合安装的 APK。参见第 53、54 章。

### API

应用程序接口，是客户端与服务器、服务与服务之间约定请求和响应的方式。参见第 18、29、30 章。

### APK

Android Package 的常用缩写，是 Android 设备实际安装的应用包。发布到 Google Play 时通常优先提交 AAB。[参见第 53 章](../chapters/053-apk-aab-包名-版本号和-android-签名.md)。

### App Store Connect

Apple 用于管理应用记录、构建、TestFlight、商店资料和审核状态的后台。参见第 56、57 章。

### Archive

Xcode 生成并保存可供验证、分发或上传的发布归档。它包含构建产物和签名相关信息。[参见第 56 章](../chapters/056-archive-testflight-与-app-store-connect.md)。

## B

### BaaS

Backend as a Service 的缩写，中文可称后端即服务。平台提供认证、数据库、存储等后端能力，项目仍要配置权限和备份。参见第 34、35 章。

### Bind Mount

把主机上的现有文件或目录直接映射进容器。容器内修改可能立即改变主机文件。参见第 46、49 章。

### Branch

分支，是指向一组提交的可移动名称，用于让不同改动暂时分开。[参见第 9 章](../chapters/009-分支-合并-冲突-撤销与恢复.md)。

### Build

构建，是把源码、依赖与资源处理成可运行或可发布产物的过程。参见第 21、26、52 章。

### Build Command

构建命令，是部署平台在构建阶段执行的命令。它应产生平台约定的输出目录或发布包。[参见第 26 章](../chapters/026-build-command-output-directory-和环境变量.md)。

## C

### Cache

缓存，是为了减少重复计算或下载而保存的可再次取得内容。缓存失效和旧内容会造成版本错觉。参见第 16、59 章。

### CDN

内容分发网络，把可缓存内容放到靠近用户的节点，减少传输距离并分担源站压力。参见第 16、28 章。

### CI

持续集成，是在代码变化后自动执行构建、测试或检查的流程。绿色状态必须与具体提交、任务和跳过情况一起解释。参见第 10、70、72 章。

### Client

客户端，是主动向服务器发出请求的一方，可以是浏览器、手机 App 或另一项服务。[参见第 13 章](../chapters/013-浏览器-客户端和服务器.md)。

### Clone

克隆，是把远程 Git 仓库及其历史复制到本地。下载 ZIP 只有文件快照，不等于 Clone。参见第 8、11 章。

### Commit

提交，是 Git 中对一组已选择变化的本地记录。Commit 不会自动把内容上传到 GitHub。[参见第 8 章](../chapters/008-commit-push-pull-clone-和-sync.md)。

### Console

控制台，在浏览器开发者工具中用于查看日志、警告和 JavaScript 错误，也可执行临时表达式。参见第 19、60 章。

### Container

容器，是由镜像创建的隔离进程环境。删除容器会删除其可写层，不会自动删除外部卷。参见第 44、45 章。

### Cookie

Cookie 是浏览器为网站保存并随符合条件的请求发送的小段数据，常用于会话标识和偏好。[参见第 16 章](../chapters/016-cookie-session-token-缓存和-cdn.md)。

### CORS

跨源资源共享，是浏览器执行同源策略时允许服务器声明哪些跨源请求可被网页读取的机制。参见第 15、30 章。

## D

### Database

数据库，是按结构保存和查询数据的系统。应用应通过受控账号和业务权限访问它。参见第 18、31、32 章。

### Dependency

依赖，是项目运行或构建所需要的外部软件包、库或工具。锁文件记录一次解析得到的具体版本。参见第 21、22 章。

### Diff

差异，是两个文件状态或提交之间的增删变化。审查 Diff 可以发现范围扩大、秘密加入和测试被削弱。参见第 7、70、74 章。

### DNS

域名系统，把域名查询转换成地址或其他记录。修改 DNS 后会受到缓存和 TTL 影响。参见第 14、28 章。

### Dockerfile

Dockerfile 是描述镜像构建步骤的文本文件。可重复构建依赖明确的基础镜像、复制范围和安装命令。[参见第 45 章](../chapters/045-镜像-容器-dockerfile-和-registry.md)。

### Domain

域名，是用户可以读写的网络名称。注册、DNS、部署绑定和 HTTPS 是不同责任。参见第 14、28 章。

## E

### Environment Variable

环境变量，是进程启动时获得的名称和值，常用于环境差异与秘密引用。它进入浏览器构建后可能公开。参见第 26、65 章。

### `.env`

`.env` 是一种常见的本地环境变量文件名。它不是天然加密保险箱，真实秘密通常不应提交到 Git。参见第 12、26、65 章。

## F

### Firewall

防火墙按规则允许或拒绝网络流量。云防火墙、主机防火墙和应用监听需要分别检查。参见第 41、66 章。

### Flutter

Flutter 是跨平台应用开发框架。本书只讲读懂项目、构建模式与 Android、iOS 发布所需部分。参见第 51 至 58 章。

## G

### Git

Git 是分布式版本控制系统，在本地记录文件变化和提交历史。GitHub 是托管 Git 仓库与协作功能的平台。[参见第 5 章](../chapters/005-git-github-项目文件夹和仓库.md)。

### GitHub Desktop

GitHub Desktop 是 GitHub 的图形桌面客户端，可以查看变化、提交、同步、管理分支和解决部分冲突。参见第 7 至 9 章。

### `.gitignore`

`.gitignore` 告诉 Git 哪些未跟踪路径通常不应加入版本控制。它不会从历史中删除已经提交的秘密。[参见第 12 章](../chapters/012-gitignore-秘密泄露和历史中的敏感信息.md)。

## H

### Health Check

健康检查是平台或运维系统用来判断服务能否接收请求的探测。进程存活不等于业务健康。参见第 27、48 章。

### HTTP

超文本传输协议，规定客户端怎样发送请求、服务器怎样返回状态、头部和正文。[参见第 15 章](../chapters/015-http-https-tls-请求与响应.md)。

### HTTPS

HTTPS 是在 TLS 保护下传输的 HTTP。它保护传输过程，不证明网站内容本身可信。参见第 15、28、41 章。

## I

### Image

镜像，在 Docker 中是创建容器的只读模板，由文件系统层、元数据和默认启动设置组成。[参见第 45 章](../chapters/045-镜像-容器-dockerfile-和-registry.md)。

### IP Address

IP 地址是网络层用于定位接口的数字地址。一个域名可对应多个地址，一个地址也可承载多个网站。[参见第 14 章](../chapters/014-ip-域名-dns-端口和-url.md)。

## J

### journalctl

`journalctl` 是读取 systemd journal 日志的命令，可按单元、时间、优先级和实时跟随筛选。参见第 40、61 章。

### JSON

JSON 是常用的文本数据格式，由对象、数组、字符串、数字、布尔值和空值组成。API 请求与响应常使用它。参见第 18、29 章。

## L

### Lock File

锁文件记录包管理器解析出的具体依赖版本和完整性信息。随意删除会改变可重复安装结果。[参见第 22 章](../chapters/022-包管理器-锁文件-版本号和环境差异.md)。

### Log

日志是软件在特定时间记录的事件。有效日志要能关联版本、请求和环境，同时避免泄露秘密与用户正文。参见第 40、60、61 章。

## M

### Merge

合并，是把两个分支的变化组合到一起。两边修改同一位置且 Git 无法自动判断时会产生冲突。[参见第 9 章](../chapters/009-分支-合并-冲突-撤销与恢复.md)。

### Migration

迁移可以指数据库结构变化、数据搬迁或平台迁移。高风险迁移需要兼容方案、备份、演练和回退条件。参见第 32、42 章。

## N

### Nginx

Nginx 是常用 Web 服务器和反向代理。它可以终止 TLS、按域名接收请求并转发到应用。[参见第 41 章](../chapters/041-防火墙-caddy-nginx-域名与-https.md)。

### NoSQL

NoSQL 是一组非关系型数据库模型的总称。它没有统一查询方式，选择时要看真实数据关系和查询需求。[参见第 31 章](../chapters/031-sql-nosql-postgresql-与-sqlite.md)。

## O

### OAuth

OAuth 是让应用在有限范围内获得资源访问授权的框架。登录流程常与 OpenID Connect 配合。[参见第 30 章](../chapters/030-rest-websocket-身份认证和权限控制.md)。

### Object Storage

对象存储以对象和键保存文件，适合上传图片、附件和备份。数据库通常只保存对象标识和业务关系。参见第 18、33 章。

### Output Directory

输出目录是构建完成后部署平台要发布的文件夹。填成源码目录会造成资源缺失或泄露。[参见第 26 章](../chapters/026-build-command-output-directory-和环境变量.md)。

## P

### Port

端口把一台主机上的网络流量交给特定监听程序。云规则开放端口不代表应用已经监听。参见第 14、39、41 章。

### Preview

预览环境用于在生产发布前查看某次分支或提交。它仍可能访问外部服务和秘密，不能默认无风险。[参见第 27 章](../chapters/027-preview-production-部署日志和回滚.md)。

### Production

生产环境是真实用户和真实数据所在的运行环境。权限、变更、观察和回退要求高于本地与预览环境。参见第 27、73 章。

### Provisioning Profile

描述文件把 Apple 的 App ID、证书、设备或分发方式组合起来，帮助 Xcode 判断应用能怎样签名和安装。[参见第 55 章](../chapters/055-ios-macos-xcode-证书和-provisioning-profile.md)。

### Proxy

代理接收一方请求并代为访问下一跳。反向代理站在服务器入口，把外部请求转给内部应用。[参见第 41 章](../chapters/041-防火墙-caddy-nginx-域名与-https.md)。

### Pull

Pull 从远程取得变化并把它们整合到当前本地分支。操作前先保存或提交自己的变化。[参见第 8 章](../chapters/008-commit-push-pull-clone-和-sync.md)。

### Push

Push 把本地提交发送到远程仓库。它不会自动选择未提交文件，也可能被权限或分支规则拒绝。[参见第 8 章](../chapters/008-commit-push-pull-clone-和-sync.md)。

## R

### README

README 是项目入口说明，通常介绍用途、运行方式、版本状态和限制。它可能过期，需要与配置和实际命令交叉核对。参见第 10、11 章。

### Registry

镜像注册表保存和分发容器镜像。标签可能移动，摘要更适合精确记录发布内容。参见第 45、49 章。

### Release

发布版本是准备交付给用户的一组产物和说明。GitHub Release、服务器部署和应用商店 Release 各有不同含义。参见第 10、27、52 章。

### Repository

仓库是 Git 管理的项目目录和历史。远程仓库与本地仓库可以暂时不同步。参见第 5、8 章。

### REST

REST 是围绕资源和 HTTP 语义设计接口的一组架构约束。本书只使用其常见请求、状态和无状态交互。[参见第 30 章](../chapters/030-rest-websocket-身份认证和权限控制.md)。

### Rollback

回滚是恢复到已知可用版本或配置。涉及数据库和外部副作用时，回滚代码并不能自动恢复数据。参见第 27、42、49、71 章。

### Runtime

运行时是执行程序所需的环境和组件，例如 Node.js、Python、JVM 或 Flutter 引擎相关环境。参见第 21、22 章。

## S

### Secret

秘密是必须限制访问的凭据或敏感值，例如 API Key、数据库密码和签名口令。秘密进入历史后应轮换，不能只删当前文件。参见第 12、65 章。

### Server

服务器可以指提供服务的程序，也可以指运行这些程序的计算机。阅读上下文时要区分。参见第 13、36 章。

### Session

会话是服务器在多次请求之间识别同一登录状态的机制。浏览器通常只保存不可猜的会话标识。参见第 16、30 章。

### SSH

Secure Shell 的缩写，用于加密地远程登录服务器、执行命令和传输文件。首次连接要核对主机指纹。[参见第 37 章](../chapters/037-第一次使用-ssh-登录服务器.md)。

### Static Site

静态网站把已经生成的 HTML、CSS、JavaScript 和资源文件直接交给浏览器，不在每次请求时执行自己的业务后端。参见第 3、23、24 章。

### systemd

systemd 是许多 Linux 发行版的系统与服务管理组件。服务单元描述程序怎样启动、停止和重启。[参见第 40 章](../chapters/040-systemd-systemctl-journalctl-和服务日志.md)。

### systemctl

`systemctl` 是查看和控制 systemd 单元的命令。状态为 active 只说明管理器看到进程状态，仍要验证业务。[参见第 40 章](../chapters/040-systemd-systemctl-journalctl-和服务日志.md)。

## T

### TestFlight

TestFlight 是 Apple 的应用 Beta 测试分发服务，支持内部与外部测试者。外部测试可能需要 Beta App Review。[参见第 56 章](../chapters/056-archive-testflight-与-app-store-connect.md)。

### TLS

传输层安全协议，为 HTTPS 等连接提供加密、完整性和服务器身份验证。SSL 是仍被口语沿用的旧称。参见第 15、41 章。

### Token

Token 是代表身份、授权或一次操作的令牌。它应限制用途、权限和有效期，泄露后需要撤销或轮换。参见第 16、30、65 章。

### Transaction

事务把一组数据库操作作为一个整体提交或回滚，用于保护数据一致性。它通常不能撤销已发送邮件等外部副作用。参见第 29、32 章。

## U

### UFW

Uncomplicated Firewall 是 Ubuntu 常用的防火墙管理工具。启用前要先允许实际 SSH 入口并保留救援控制台。[参见第 41 章](../chapters/041-防火墙-caddy-nginx-域名与-https.md)。

### URL

统一资源定位符描述协议、主机、端口、路径、查询和片段。它不等于磁盘文件路径。[参见第 14 章](../chapters/014-ip-域名-dns-端口和-url.md)。

## V

### Volume

卷是由 Docker 管理的持久数据位置，可在容器重建后继续存在。未挂载不代表可以删除。参见第 46、49 章。

### VPS

虚拟专用服务器，是云平台在物理服务器上提供的虚拟主机。购买后用户承担系统更新、防火墙、服务和备份责任。参见第 36、43 章。

## W

### Webhook

Webhook 是一项系统在事件发生时向另一项系统发送 HTTP 请求的通知方式。入口需要验证来源、防止重放并记录失败重试。[参见第 33 章](../chapters/033-文件上传-对象存储-邮件-推送和-ai-api.md)。

### WebSocket

WebSocket 在一次握手后建立双向长连接，适合实时消息和状态更新。断线重连与身份过期需要单独处理。参见第 18、30 章。

## X

### Xcode

Xcode 是 Apple 平台开发、构建、签名、调试和归档的主要工具。Flutter iOS 发布仍需要真实 Mac 与 Xcode。参见第 55、56 章。

## Y

### YAML

YAML 是依靠缩进表达层级的配置格式。Compose 和部分 CI 配置使用它，Tab 与空格错位会改变结构。[参见第 47 章](../chapters/047-docker-compose-与多容器应用.md)。
