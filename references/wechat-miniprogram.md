# 微信小程序开发、体验、审核与发布参考

微信小程序运行在微信客户端提供的环境中，不是普通网页，也不是从应用商店安装的原生 App。它仍可能包含设备端页面、微信平台能力、自己的后端、数据库和文件存储。平台接口、类目、资质、包体限制、审核要求与控制台入口会变化；每次提审当天都应打开[微信开放文档](https://developers.weixin.qq.com/miniprogram/dev/framework/)和自己的微信公众平台账号重新核对。

## 小程序身份卡

```text
小程序名称：
主体与认证状态：
AppID：
管理员 / 项目成员 / 体验成员：
服务类目与所需资质：
代码版本与提交 ID：
基础库兼容范围：
开发工具版本：
服务器域名：request / upload / download / socket
后端环境 / 数据库 / 文件存储：
隐私保护指引版本：
开发版 / 体验版 / 审核版 / 线上版：
线上版本与后端兼容范围：
```

主体说明谁对小程序负责，AppID 标识具体小程序，项目成员决定谁能开发和上传，体验成员决定谁能访问体验版。它们不能用共享管理员账号代替。真实 AppSecret、接口令牌、支付密钥和私钥不写入身份卡、不进入前端代码、不贴给 AI。

## 一条完整交付路径

1. 在公众平台确认主体、AppID、类目、成员与必要资质。
2. 用正确 AppID 导入项目；在开发者工具中运行、调试并完成代码质量检查。
3. 后端使用测试环境，配置实际需要的服务器域名和 TLS；关闭“跳过域名校验”后再验证。
4. 上传代码成为开发版本，记录版本号、项目提交、上传者和说明。
5. 选择确定的开发版本作为体验版，让体验成员扫码测试真机、微信版本、权限和后端。
6. 准备隐私保护指引、类目、页面路径、功能说明、测试账号和审核所需材料。
7. 提交审核；根据原始反馈修正代码、资料或环境，再上传新版本重新验证。
8. 审核通过后，由授权人员核对将要发布的版本并发布线上版。
9. 在真实入口验证页面、登录、核心读写、分享或跳转、弱网和旧版本兼容，观察前端与后端日志。

开发者工具预览成功只证明开发环境的一次运行。上传成功只形成开发版本；设为体验版只扩大到受控体验成员；审核通过也不会替你完成最终版本核对和线上业务验证。每一个状态回答的问题不同。

## 版本状态不要混淆

| 状态 | 主要用途 | 尚未证明 |
|---|---|---|
| 本地开发 / 预览 | 单机调试页面、接口与设备能力 | 上传、体验成员和线上配置 |
| 开发版本 | 平台收到一次代码上传 | 该版本已经成为体验版或进入审核 |
| 体验版 | 受控成员扫码执行真机测试 | 审核通过或公众可用 |
| 审核版 | 平台正在检查指定提交 | 已经正式发布 |
| 线上版 | 平台向真实用户提供的版本 | 所有用户流程与后端都健康 |

版本页面可能同时出现多个候选。不要用“最新那一条”代替身份核对；比较代码版本、上传时间、上传者、提交说明和关联源码提交。审核反馈、体验记录和线上观察都要绑定同一个候选。

## 服务器域名与秘密边界

小程序网络请求受平台配置的合法域名约束。普通 HTTPS 请求、上传、下载和 WebSocket 可能对应不同类别；协议、域名与端口必须和真实请求一致。开发者工具中的“不校验合法域名、TLS 与证书”只适合局部开发诊断，不能作为发布方案。体验版和线上版要在正式校验开启时通过。

网络失败按这条顺序排查：

1. 当前运行的是哪个 AppID 和哪个版本状态。
2. 请求 URL 的协议、主机、端口与路径是否正确。
3. 对应类别的服务器域名是否已配置并生效。
4. TLS 证书、DNS、服务器监听和防火墙是否正常。
5. 后端是否收到请求，返回了什么状态和请求 ID。
6. 登录态、业务权限、超时与客户端错误处理是否正确。

AppSecret 代表服务端调用微信接口的高权限身份，不能放进小程序包。小程序把临时登录凭证发送给自己的后端，由后端通过受保护的 AppSecret 完成服务端交换，再建立自己的会话。前端环境变量、混淆和私有仓库都不能把发布到用户设备的秘密变安全。

## 登录、用户标识与权限

“用户从微信打开”不等于后端已经知道并授权这个业务用户。登录流程至少区分微信侧临时凭证、后端交换得到的标识、产品自己的账号绑定和业务权限。客户端传来的 `role`、价格、所有者 ID 和审核状态都要在服务端重新判断。

手机号、头像昵称、位置、相册、剪贴板等能力受平台接口和用户授权约束。不要把某次授权结果当作永久不变；用户可以拒绝或改变设置。拒绝后应保留不依赖该信息的功能，并说明需要时怎样再次授权。

## 隐私保护指引与真实代码一致

先画数据地图，再填写平台资料：

```text
数据类型：
触发页面和用户动作：
调用的组件 / API：
是否离开设备：
接收者：自有后端 / 微信能力 / 第三方 SDK
用途与必要性：
保存位置与期限：
删除或撤回路径：
对应隐私指引条目：
```

代码未调用不代表第三方组件没有调用，控制台勾选也不证明披露准确。提审前扫描实际依赖与权限接口，在体验版走一次拒绝、同意、撤回和账号注销路径。新增接口、插件、广告、客服、支付或分析能力后重新检查指引。涉及儿童、健康、金融、位置或用户生成内容时，类目、资质与治理责任也会增加。

## 体验版测试清单

- 使用体验成员自己的微信账号扫码，不用开发者本人的登录状态代替。
- 记录小程序版本、微信版本、设备系统、网络、时间和后端环境。
- 验证首次进入、冷启动、页面返回、前后台切换、权限拒绝与重新进入。
- 验证登录过期、弱网、超时、重复点击以及后端返回错误时的明确状态。
- 完成一条核心创建—读取—修改—删除路径，确认权限不能跨用户。
- 若使用上传、下载、WebSocket、地图、支付、订阅消息或跳转，分别测试实际平台入口。
- 比较旧线上版与候选后端的兼容性；客户端发布和数据库迁移分开控制。
- 清理测试数据，保留脱敏证据和仍未覆盖项。

体验版二维码属于受控测试入口，截图传播仍会扩大信息和支持负担。真实用户数据不用于体验测试，审核账号只获得最小业务权限。

## 审核材料与反馈

审核材料来自真实产品事实：准确的类目和功能说明、可到达的页面路径、必要资质、隐私指引、测试账号、特殊硬件或地区条件、后端可用时间。不要为了通过审核隐藏实际能力，也不要用 AI 编造资质、数据用途或承诺。

收到反馈后先保存原文并分类：代码功能、页面可达性、类目或资质、隐私与权限、内容治理、账号或环境。确认反馈对应的版本，再修改最小范围，重新体验并上传新的候选。审核人员可能使用不同设备、网络和时间；仅办公室网络可用的后端、一次性验证码或夜间关闭的测试环境会阻断核验。

审核耗时、次数与结果不可写成确定发布日期。发布时间应给观察、支持和回退留出窗口。

## 发布、灰度与回退边界

发布前保存：

```text
小程序 / AppID：
候选代码版本 / 源码提交：
体验记录：
审核结论与时间：
线上后端 / 数据库迁移：
发布人 / 批准人：
用户范围与平台提供的发布方式：
停止或回退条件：
发布后验证：
```

平台当前提供哪些分阶段或回退能力应在发布当天核对，不能根据旧截图设计事故方案。客户端回退也不能撤销已经发生的数据库写入、支付、消息和文件变化。保持旧客户端兼容、给高风险功能设置服务端开关、拆分数据库迁移，并准备更高版本修复，才是可操作的恢复能力。

## 常见错误对照

| 现象 | 先查 |
|---|---|
| 开发工具正常，真机请求失败 | 是否跳过了域名/TLS 校验、真实域名类别和证书 |
| 体验者打不开 | 是否为体验成员、二维码对应哪个 AppID 和体验版本 |
| 登录偶发失败 | 临时凭证是否被重复使用、后端交换与会话日志 |
| 审核看不到功能 | 页面路径、测试账号、地区/时间条件和后端状态 |
| 隐私接口不可用 | 实际接口、指引声明、授权交互与当前平台要求 |
| 发布后仍像旧版 | 线上版本身份、入口、缓存、本地数据和后端版本 |
| 修复造成旧版报错 | API / 数据格式是否破坏兼容、迁移是否提前执行 |
