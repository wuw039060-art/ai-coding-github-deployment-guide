# 后端与数据库运行参考

这份参考用于本地和托管环境中的 API、数据库、文件存储与恢复操作。主章解释组件关系和选型；这里保存检查清单、样例命令与证据格式。任何生产写入、迁移、恢复和删除都需要准确目标与人工批准。

## 系统身份卡

```text
环境：本地 / 测试 / 生产
API 地址与版本：
运行平台 / 区域：
数据库产品 / 实例 / 数据库名：
迁移版本：
文件存储桶 / 区域：
身份认证提供者：
秘密保存位置（不写值）：
备份频率 / 保留期 / 最近恢复演练：
负责人 / 值班入口：
```

浏览器或 App、API、数据库和文件存储是不同边界。客户端不应持有数据库管理员凭据。一次成功响应只能证明被测试的路径；健康检查成功不代表权限、写入、异步任务和恢复都正常。

## API 最小验证

先用没有副作用的健康或读取接口：

```bash
curl -i https://example.invalid/health
curl -i -H 'Accept: application/json' https://example.invalid/api/items
```

记录状态码、响应头、正文摘要、时间、环境和服务版本。带认证时不要把真实令牌写进命令历史、截图或工单。创建与更新操作使用测试账号和可识别数据，并准备清理或回退方式。

错误按边界分类：

| 现象 | 先查 |
|---|---|
| DNS 或连接失败 | 域名、端口、TLS、代理、服务监听 |
| 401 | 是否提供了有效身份 |
| 403 | 身份是否有目标资源权限 |
| 404 | 环境、路由、资源 ID |
| 409 | 重复、并发或状态冲突 |
| 422 / 400 | 请求结构与业务校验 |
| 500 | 对应请求 ID 的服务端日志与依赖 |
| 超时 | 客户端、代理、服务和数据库各层耗时 |

## 数据库连接检查

连接串通常包含协议、用户、主机、端口和数据库名；TLS、连接池和超时还可能来自独立参数。排错时显示结构但遮蔽密码。

```text
协议://用户:***@主机:端口/数据库名
```

逐层确认：DNS 能否解析、网络是否允许、服务是否监听、TLS 是否匹配、账号能否认证、账号是否拥有目标数据库权限。不要先把数据库端口向全网开放来“证明能连”。本地工具成功也不代表部署环境的网络和凭据相同。

## 迁移安全顺序

1. 阅读迁移脚本和生成来源，确认目标数据库与当前版本。
2. 在结构和数据量接近的非生产环境执行，记录耗时、锁与磁盘变化。
3. 检查应用新旧版本是否需要短暂共存；优先使用兼容的 expand / migrate / contract 顺序。
4. 做可用且经过抽查的备份，写明恢复目标与允许丢失窗口。
5. 选择有观察与回退人员的窗口，设置停止条件。
6. 由数据负责人确认生产实例、脚本摘要和计划，再执行一次。
7. 验证结构、关键读写、权限、任务和指标；不要只看命令退出码。

添加可空字段、回填、切换读取、收紧约束、删除旧字段通常应拆开。具体数据库的在线 DDL、事务和锁行为不同，执行前查当前官方资料并用真实规模演练。

## 备份与恢复

备份的验收不是“文件存在”，而是能在受控位置恢复并通过校验。

```text
备份 ID / 时间及时区：
来源实例 / 数据库：
包含范围：结构 / 数据 / 角色 / 文件
一致性方式：
加密与访问者：
保存位置 / 保留期：
校验和：
恢复目标：新实例 / 新数据库
恢复耗时：
行数或业务抽查：
未覆盖的外部副作用：
```

恢复生产可能覆盖合法新写入，不能当普通重启。数据库回到过去不会撤销已经发送的邮件、支付、对象存储写入和外部 Webhook，需要单独对账。优先恢复到新目标并验证，再决定流量切换。

## SQLite 与服务型数据库

SQLite 是单文件数据库，适合同主机、写事务短、拓扑简单的应用；它仍需要一致性备份，不能在写入中随便复制文件。多个应用实例共同写入、远程连接、复杂权限或独立扩展时，PostgreSQL 等服务型数据库更合适。

选择不由“用户少”单独决定，还要看并发写入、故障恢复、部署拓扑和团队运维能力。托管数据库减少系统维护，不会替你设计表、索引、权限、迁移和恢复演练。

## 文件存储不是数据库附件

上传文件通常保存在对象存储或受控磁盘，数据库只记录对象键、所有者、状态和元数据。验证以下关系：

- 客户端只能按授权上传和读取，不获得管理员密钥。
- 文件名不直接决定服务器路径；限制大小、类型和实际内容。
- 数据库记录创建失败时，不留下无人管理的对象；对象删除失败时，可重试并审计。
- 备份、保留、地区与删除政策覆盖数据库和文件两侧。
- 日志不记录签名 URL、访问令牌或文件正文。

## BaaS 的边界

Supabase、Firebase 等平台可以提供认证、数据库、文件、函数和实时能力。SDK 方便不等于客户端可以绕过授权。公开配置值与管理秘密要按平台模型区分；行级规则、存储规则和后端函数仍需负面测试。

最低测试包括：未登录读取、读取他人对象、修改他人记录、伪造所有者字段、上传超限文件、过期令牌、删除账号后的残留访问。控制台数据表里“看得到”不能证明用户侧权限正确。
